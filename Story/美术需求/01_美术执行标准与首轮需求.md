本文确定美术制作、接入与验收标准。首轮以同一个可换装角色贯通部件试产、Spine 接入与灯光对照。各项实测结果分别登记，文档定稿表示执行标准已确认。

## 1. 画面与可读性

局外以战国末至秦汉题材的风格化手绘 2D 为方向。村庄使用夯土、木构、布料、瓦面等能辨识的材质。地表强调可行走边缘和跳跃落点，洞穴与遗构收敛背景细节并保留出口层次。边缘空间允许其他文明拥有独立形体与纹样，通过色彩关系、笔触尺度和空间异常的表现保持整体一致。

- 以现有世界地图的墨、朱砂、赭石、石青、石绿、金、纸色作为主色关系，允许材质各自使用衍生色。统一基础光向、边缘软硬和细节密度。角色、道具和环境应在目标镜头下共同评审。
- 受控者、队友、敌人、可交互物分别用剪影、明度、形状或标记辨识。危险提示优先于环境装饰与掉落提示。白天、夜间、地表、洞穴都要看清可站立边缘、攻击前摇和实际落点。
- 地形沿用程序生成计划与碰撞数据。按邻接关系处理顶面、侧边、内外角、平台端头和材料交界。前景与装饰避开战斗提示和可行走面。
- 世界地图与 UI 沿用现有 uGUI、TMP、九宫格和 MVP 展示入口。势力色、选中状态、任务状态分别表达。检查 1366×768 与 1920×1080 下的正文、提示、遮罩及手柄焦点。

## 2. 素材制作与交付

先完成同屏风格样张和标准结构模板，再批量生产。UI、地图符号和重复装饰可用矢量或参数化生成。角色以同一基础姿势、比例、关节、枢轴和部件边界为模板，可用多模态出图或本地生成流程做受控变体和局部重绘。建筑、武器与道具可用正交 3D 底图统一结构，再调整轮廓、材质和细节疏密。

1. 每件资产记录稳定 ID、用途、来源与修改和商用许可、可编辑源、导出文件和导入设置。参考商业游戏时提炼构图、色彩关系和动作节奏，生产输入使用自有或授权适用的素材。
2. 换装部件在统一模板上生成和编辑，补齐被遮挡区域。保留正确的关节重叠、前后片与透明边缘。首件验证后再确定后续导出尺寸、PPU、材质和图集分组。
3. 生成资产记录工作流、输入图、遮罩、提示词、seed、模型和 LoRA 哈希、节点版本、关键运行环境。工具或 MCP 可负责批处理、导入和记录，制作成果以接入后的表现验收。
4. 目标尺寸下分别做实心剪影测试、灰度明度测试、同屏一致性测试。复核造型、边缘、光向、细节分布、材质辨识和透明区域。统一限色、纸纹和描边按资产需求使用。
5. 试产记录候选数、验收通过数、淘汰原因，以及筛选、修复、拆件、绑定和验收耗时。用每件通过验收的总工时估算扩产，工期和通过率以试产记录为依据。

## 3. Spine 角色与换装

首轮采用项目现有 Spine 3.8 兼容的导出与运行时组合。人形角色先共用一个体型和骨架。使用 Skin Placeholder 保持稳定的附件键，装备独立为可组合 Skin。一件装备可控制多个绘制槽，装备槽、绘制槽、遮挡规则分别定义。动画可通过 Placeholder 控制附件可见性、武器收放和前后关系。

- 首轮制作同类武器两把、另一动作族武器一把、两套护甲、两件头部装备。其中至少一件覆盖头发或衣物，能验证卸下后的恢复。武器定义主握点、辅助手目标和局部偏移。双手动作由动画或 IK 对准握点。
- 世界角色和 UI 预览共用按稳定装备 ID 解析的外观结果，包括组合 Skin 与必要覆盖。存档保存装备 ID。图集按实际同屏分组，是否运行时重打包依据材质切换和性能记录。
- 换装在正常动画更新中完成。设置组合 Skin 后恢复槽位初始状态，再应用当前动画的附件关键帧，随后处理有意保留的覆盖并更新骨骼、网格。优先使用组件已有的更新时序。暂停预览也应即时刷新。
- 首轮角色动作覆盖待机、走跑、起跳与落地、攻击、受击、倒地和恢复。武器按动作族组织。攻击表现对齐玩法判定，前摇或命中时刻的变更单独作为战斗需求处理。保留既有碰撞根节点与 Cinemachine 镜头控制。
- 验收覆盖加载、换装、卸装、翻转、移动、攻击中换装、武器动作族切换与暂停 UI 预览。观察附件残留、错误遮挡、握点错位、变形、丢图、透明边缘及战斗判定与画面同步。

## 4. 首轮任务与验收顺序

| 顺序 | 交付 | 验收条件 |
| --- | --- | --- |
| 1. Alpha 对照 | 已知半透明边缘与不透明色块的测试图、当前设置与 Straight Alpha 对照截图、导出和材质记录 | Linear 下在深浅背景核对边缘和实体颜色，分别检查世界角色与 UI。缩放、过滤和 mipmap 单独比较 |
| 2. 风格样张与部件试产 | 村庄、地表或洞穴、角色与 HUD 同屏关键帧。一个标准人形模板、一名可换装门客与第 3 节装备小样 | 在目标尺寸通过剪影、明度、同屏一致性和换装验收，记录每件总工时与返修原因 |
| 3. 目标品质场景切片 | 同一门客、一个敌方表现样例、一段地表至洞穴过渡与一个交互物。完成 Built-in 基线和隔离 URP 2D 对照 | 固定硬件、镜头、种子、分辨率、画质和角色数量。提供同屏截图、CPU/GPU 帧时间、P95/P99、灯光覆盖和阴影投射记录。观察出口、落点和前摇的辨识度 |
| 4. 扩产决策 | 技术选择、材质及导入预设、部件交付清单和已验收样张 | 基于前三项结果确定正式渲染管线、装备适配规则和产量。Windows PC 的 1080p、60fps 为首轮目标，目标硬件和质量档须随测试报告登记 |

当前角色图集原始像素只有全透明与全不透明，现有材质配置只能提示透明工作流需要核查。保留 Linear 时，正式素材优先使用 Straight Alpha 图集，导出启用 Bleed，颜色贴图按 sRGB 导入，世界与 UI 材质分别启用匹配的 Straight Alpha 输入。先用测试图和角色小样验证，再决定旧资源是否重导。 [Spine 导出与导入](https://en.esotericsoftware.com/spine-unity-assets)

主工程以现有 Built-in 为 A/B 基线。URP 试验使用独立项目副本或 worktree 与独立 Library，核对被忽略的 `Packages/manifest.json`、`Packages/packages-lock.json` 和本地依赖。沿用同一份场景与素材。适配范围包括昼夜的两个 Built-in `CameraEvent` 和 `OnPreCull` 参数更新、支持 2D 灯光的地形材质、Spine 世界角色材质、UI 专用材质与最终合成。先测试环境受光，再按画面需要评估角色受光、法线、阴影与后处理。 [Unity 2022.3 管线对照](https://docs.unity3d.com/2022.3/Documentation/Manual/render-pipelines-feature-comparison.html) · [Spine 渲染说明](https://en.esotericsoftware.com/spine-unity-rendering)

## 5. 验收记录

每轮记录素材版本、测试场景、镜头与显示尺寸、硬件与画质、通过项、证据路径、失败项和复验结果。以下决策以首轮记录为依据。

| 待决项 | 决策证据 |
| --- | --- |
| 旧角色是否重导、是否启用 mipmap | 已知 Alpha 测试图及角色在不同缩放下的对照 |
| 是否迁移 URP、世界角色是否受光 | 同场景画面收益、现有昼夜与 UI 兼容性、帧时间、适配工作量 |
| 正式角色与环境量产规格 | 接入后的同屏效果、换装与动作测试、每件通过验收的总工时 |

Spine 槽位刷新和 Skin 组合以本项目 3.8 运行时为准。 [Spine Runtime Skins](https://en.esotericsoftware.com/spine-runtime-skins)
