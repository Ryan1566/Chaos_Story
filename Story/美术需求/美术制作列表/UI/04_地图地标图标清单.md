**口径推导（三条一起看，不要只抄数字）**

1. **主档 = 1080p 逻辑显示尺寸 ×4 = 2K 物理像素的两倍。** 换算示例：普通地标 1080p 逻辑 24 → 2K 下屏幕占 48px → 主档 96；主城 32 → 64 → 128；局内 64 → 128 → 256；配套件按其逻辑显示尺寸的两倍出图（小地图 190 ×2 = 380，外环/遮罩 234×176 ×2 = 468×352）。
2. **为什么是 4 倍而不是 2 倍**：地标是「薄线剪影 + 细边」，合法线宽在 1080p 屏幕上只有 **1–2px**。若主档只取两倍边长（普通地标 48、主城 64、局内 128），2K 下 48px 显示时刚好 1:1，没有余量，细边就停在 1–2px；再缩到 1080p 又要 2:1 下采样，边缘必软、细纹糊成一团。取 4 倍后主档线宽落在 **4–8px**（§1.3），2K 屏 2:1 下采样时线宽仍是 2–4px，肉眼锐利；缩到 1080p 是 4:1，等于自带超采样抗锯齿。
3. **主档不是屏幕 1:1 显示尺寸**：导入 Unity 时按逻辑尺寸缩放显示——`RectTransform` 仍是 24、32、64 三种逻辑尺寸，贴图是 96、128、256 三种主档。**不要**把 RectTransform 改成主档像素，否则地标会大四倍、同屏全部压叠。
4. **缩放叠乘的余量**：悬停 ×1.35、选中 ×1.6（`WorldMapPointIcon.cs:15-16`、`:71-72`）。2K 下普通地标 48px，选中时画到 **76.8px**，主档 96 仍是降采样（1.25:1）；主城 2K 选中 96px，主档 128 也仍有 1.33:1 余量。若主档只有两倍余量，选中态就是向上放大，必糊。地图本体缩放不影响图标尺寸：`WorldLocationsView.cs:370` 用 `point.scale = 1/max(1,zoom)` 反向抵消，图标在 zoom 1~6 全程屏幕尺寸恒定，**不需要为缩放另出图**。

**取整过程（必须照此写进验收单）**

- 22 → 向上取 4 的倍数 = **24**（逻辑）；主档 = 24 ×4 = **96**
- 30 → 向上取 4 的倍数 = **32**（逻辑）；主档 = 32 ×4 = **128**
- 局内 64 → 已是 4 的倍数（逻辑）；主档 = 64 ×4 = **256**
- 配套：小地图 190×190 → 主档 **380×380**；外环 / 遮罩 234×176 → 主档 **468×352**

> 「逻辑显示」是取整到 4 的倍数的设计口径（22→24、30→32），不是把代码里的 22/30 抄成 24/30。实际绘制区由 Unity 按 Rect 拉伸决定，主档按 24/32 出图对 22/30 的绘制区是 4.36:1 / 4:1 降采样，两种口径都覆盖。

**局内 64px 的推导（不是实测，必须标注）**：卡片 234×176、Border 24 → 内容区 186×128；图标取内容区高度的 50% = 64px，剩余 64px 留给 TMP 名称与规则行。该组当前在工程内零引用（§6.3），量不出真实呈现尺寸，接图时必须回测。

### 1.2 画布与构图（紧贴外接框，不留白）

| 项 | 规格 |
|---|---|
| 画布 | **严格正方形**，边长 = 交付主档（96 / 128 / 256），透明背景 |
| 紧贴 | 图稿外接框贴住画布，四周只留 **1px 透明保险边**；禁止画布居中偏移、大块空白、尺寸与图形不符 |
| 主体定位 | 外接框几何中心与画布中心重合，偏差 **≤1px**（主档尺度） |
| 主体占比 | 内容外接框占画布 **≥85%**（目标 96–100%），低于 85% 直接退回重出 |
| 形变 | 禁止为凑方框拉伸；宽扁物件按原始比例，短边方向的空档算在「内容外接框」内，不算留白 |
| 母版（不交付） | 可在两倍边长内部画布作画（192 / 256 / 512），最后一步 Lanczos 缩到主档；**只交主档一张** |
| 九宫格 Border | 图标类一律 **0,0,0,0**（纯图形件，禁止拉伸）；配套外环 / 遮罩 **48,48,48,48**（= 逻辑 24 的两倍）；小地图框 0 |

**统一视觉重量**：画布已按逻辑尺寸分三档（96 / 128 / 256），同组图标都紧贴各自画布，同屏视觉重量由逻辑尺寸决定，**不再用固定的主体占比调平**（旧口径废止）。现有 12 张历史文件的长宽占比只在 §6.1 作为「为什么现在看起来大小不齐」的证据保留，不再是出图目标。

### 1.3 单色、明暗与线宽

| 项 | 规格 |
|---|---|
| 剪影色 | **单色**：一张图只用一种不透明色相，不得自带第二种颜色或底板。具体色值由风格提示词决定 |
| 纹理（淡但有） | 允许**同一色相内** 1–2 级明度起伏（≤8% 明度）：石墙砌缝、木纹明暗、田埂起伏。主档上看得见，缩到逻辑尺寸后不显。**禁止**第二色相、方向性渐变带、噪点、材质贴图——地标是剪影，纹理只做「别太平」的一点点 |
| 局内节点明暗 | 必须用**浅色剪影**：局内卡底实测为深色 `(42,36,29)`，深色剪影对照只有 **1.01:1**，等于看不见；大地图反之用深色剪影压浅色底板 |
| 镂空 | 内部细节用**透明负空间**表达，不画白色/浅色填充 |
| 渐变 / 发光 / 投影 | **禁止**（与上条纹理不冲突：纹理是明度台阶，不是渐变过渡带） |
| 外轮廓描边 | **不使用独立外描边**——形状由实心块面的边界构成 |
| 内部分界描边 | **主档 4px**（= 1080p 逻辑 1px），用于檐口、洞口内沿、田埂等内外分界 |
| 结构主笔画 | **主档 6–8px**，保证 2K 下 2:1 后仍有 3–4px |
| 最小负空间 | **主档 ≥8px**（= 1080p 逻辑 2px）。小于 8px 的镂空在 2K 上会合缝 |
| 抗锯齿 | 边缘 1px 过渡即可（主档 4px 内），禁止羽化到 2px 以上 |
| 换算 | 本文所有 `@主档` 值 = 1080p 逻辑 px ×4；这是唯一换算，不再有第二套档位 |

### 1.5 抠图与裁切（新增）

这一节是「直接切图进 Unity」的硬门槛，出图后逐张过 §1.5.3 的脚本。

**1.5.1 必须**

- 图稿**紧贴图形外接框**：四周不留白，图标类允许 **1px** 透明保险边（主档尺度）。
- 抠图边缘干净：alpha **只有 0 与 255 两档**（允许 1px 抗锯齿带，即 1–32 / 223–255）。
- 剪影内部镂空必须**完全 alpha=0**，不得用近乎透明的浅色块「假装镂空」。
- 画布尺寸 == 主档尺寸，图形外接框占画布 **≥85%**，几何中心与画布中心偏差 ≤1px。

**1.5.2 禁止**

- 半透明灰边 / 白边 / 黑边、外发光、投影、任何底色块或 matte（包括「怕边缘硬而加的柔化层」）。
- 画布居中偏移、大块空白、尺寸与图形不符（例如把小图放进 256 画布再喊紧贴）。
- 图标里画地图底纹、格子、地名、指北针等任何附加元素——**一张图只描述一个地标**。

**1.5.3 出图后自检（照跑，不通过不进 Unity）**

```python
# check_icon.py 用法: python check_icon.py <png> <主档边长:96|128|256>
from PIL import Image
import sys

path, want = sys.argv[1], int(sys.argv[2])
im = Image.open(path).convert("RGBA")
W, H = im.size
assert (W, H) == (want, want), f"画布 {W}x{H} != {want}x{want}"

a = im.getchannel("A")
px = a.load()
for i in range(W):                      # 四边 1px 全透明
    assert px[i, 0] == 0 and px[i, H - 1] == 0, "上/下边 1px 未全透明"
    assert px[0, i] == 0 and px[W - 1, i] == 0, "左/右边 1px 未全透明"

x0, y0, x1, y1 = a.getbbox()            # 内容外接框
bw, bh = x1 - x0, y1 - y0
assert max(bw, bh) >= 0.85 * want, f"内容外接框 {bw}x{bh} 不足 85%"
assert x0 <= 2 and y0 <= 2 and x1 >= W - 2 and y1 >= H - 2, "未紧贴画布（有留白或偏移）"

vals = set(a.getdata()) - {0, 255}      # alpha 只允许 0/255 与 1px 抗锯齿带
bad = sorted(v for v in vals if 32 < v < 223)
assert not bad, f"存在半透明灰边/柔化层: {bad[:8]}"

print("OK", path, W, H, "bbox", (x0, y0, x1, y1))
```

- 只需跑 96 / 128 / 256 三档；配套件 380×380 用 380 跑（脚本的 85% 与四边透明同样适用），468×352 把 `want` 换成长边判定即可。
- 脚本能查「尺寸 / 留白 / 偏移 / 半透明灰边」四类硬错；纹理是否「淡但有」靠人眼在 2K 截图上看，不进脚本。

## 3. 禁止文字与符号（**强制条款，违反即整批退回**）

**3.1 图标内不得出现任何文字形态。**

| 类别 | 禁止内容 |
|---|---|
| 文字 | 汉字、假名、谚文、拉丁字母、西里尔字母、阿拉伯字母，以及任何真实或虚构文字体系（含甲骨、金文、小篆、隶书、楷书字形） |
| 数字 | 0-9、罗马数字（Ⅰ Ⅱ Ⅲ）、算筹、计数刻痕、序号 |
| 标点 | `，。、；：！？（）【】《》""''…—` 与 `. , ; : ! ? ( ) [ ] { } " ' / \` |
| 符号 | `× ✕ ✓ ✔ + − ± ← → ↑ ↓ ↵ ★ ☆ ￥ $ % # @ & * ~ § † ‡ ● ▲ ◆ ○ □` 及任何字符形态 |
| 伪文字 | AI 生图常见的"像字不是字"的乱码、扭曲纹章字母、篆刻伪字、符文、铭文、字母浮雕 |
| 地图专属 | **地标图标不得自带编号**（1~12、Ⅰ~Ⅻ、甲/乙/丙）、不得自带星级表示主城等级、不得自带货币符号表示贸易 |

**3.2 语义只能由「剪影 + 形状 + 配色」三者承担，其余一律不许。**
不许用文字缩写（`铁` `盐` `市`）、不许用字母区分（`F` `M` `T`）、不许用符号提示（`?` 传闻、`!` 任务、`×` 未解锁）。

**3.3 天然靠文字区分的类型，一律改图形隐喻：**

| 概念 | ❌ 禁用 | ✅ 允许 |
|---|---|---|
| 铁匠 | "铁"字 / "F" | 铁砧 + 锤 |
| 酒馆 | "酒" / "T" | 酒壶 + 杯（壶口留负空间） |
| 集市 | "市" | 单坡棚 + 立柱 + 柜台（= `market_town`） |
| 盐场 | "盐" | 田格 + 卤池（= `saltworks`） |
| 传闻 | "?" / "闻" | 竹简双联（= `rumor`） |
| 任务 | "!" / "任" | 挂木牌（= `task`） |
| 未解锁 | "×" / 锁芯上的"锁"字 | 斜纹暗罩（= `G-HUD-11`） |

**3.4 判定方法（验收必做）**
1. 把成品缩到 **24px**（= 1080p 普通地标逻辑显示尺寸）看 3 秒：能读出任何字或符号 = 不合格。
2. 跑一次 OCR（任意引擎）：返回 **0 个字符** = 通过。
3. 缩到 24px 后仍能说出"这是什么地点" = 通过；说不出来 = 剪影不合格（不是加字，是改形）。

**3.5 现有工程的错误示范（不要再犯）**：图标缺失时 `WorldLocationsView.cs:474-503` 会在方块里写汉字（城/市/营/林/矿/石/盐/洞/迹/见/闻/事），`QA/WorldLocations/map-market-1920.png` 就是这个样子。**这是缺图兜底，不是设计**——本轮补齐图标后必须一次都不出现。

| 前景 / 背景 | 对比度 | 结论 |
|---|---|---|
| 深色剪影 / 浅色底板（合成后） | **9.01 : 1** | ✅ |

| 灰化剪影 / 深色底（未解锁） | **4.07 : 1** | ✅ 弱化但仍可辨 |

### 5.3 相邻图标不粘连（配置实测；素材侧只做缓解，根治靠代码）

按 `WorldLocationTable_Location.json` 62 个点位的 X/Y（0~1）换算到 IconLayer 1409.71×1080：

| 间距 | 对数 | 结论 |
|---|---|---|
| < 12px | **8 对** | 必粘连 |
| < 22px | **21 对** | 必粘连（22px = 一个图标绘制区） |
| < 30px | 26 对 | 会贴边 |
| 最近一对 | **1.9px**（1009 与 4006） | 完全重叠 |

→ **新口径下的坦白**：旧稿用「主体内缩 + 四周留白」挤出图标之间的空隙；改为紧贴外接框后，画布内已经没有可让的空白，这层缓解手段**失效**。素材侧能保证的只有「不为凑方框再往外扩」，因此 8 对 <12px 与最近 1.9px 的一对会直接叠死，必须靠运行时避让/聚合（§6.3 第 2 项）解决——程序侧在 InfoBar / IconLayer 上按 **≥12px 逻辑间距**避让（§7 裁决 2），已列为联调 P0。

### 5.4 缩到逻辑尺寸后剪影仍可辨

## 7. 裁决结果（已定）

| # | 事项 | 裁决 | 理由 |
|---|---|---|---|
| 1 | 外环 / 遮罩画布尺寸 | **468×352**（= 局内节点逻辑 234×176 ×2），与 `G-HUD-09/10/11` 的九宫格画布严格一致；不出方形、不加透明带；环形画不圆就按**椭圆**画、随节点框拉伸 | 这三件在 `RunMapView` 里始终与节点同框叠放，多出的透明带只会让 pivot 对齐变复杂 |
| 2 | 紧贴裁切后 8 对 <12px 粘连 | 美术侧**不加留白**，保留紧贴裁切；间距不足由程序侧在 InfoBar / IconLayer 上做 spacing 避让，**≥12px 逻辑**（建议 12–16px，冲突对先 8 方向错位，仍冲突则聚合） | 画布内已无空白可让（§5.3），素材侧加透明边只会连落点一起算错 |
| 3 | 交付计数 | **26 个文件** = 23 主档 + 配套 3；索引与 `02` 均按 26 记；`_src` 改为**可选 2× 母版**（普通地标 48、主城 64、局内 128），不进清单、不进索引、不进批次表 | 交付口径只认运行档；母版是改图工具，不是素材 |
| 4 | 局内节点主档 | **保持 256×256**，不降 192 | 4× 口径统一，256 与其余两档同为「逻辑 ×4」，验收只认一套换算 |

**回测项（不阻塞交付）**：局内节点 256×256 在 1K 实机 64px 显示下若发虚或过锐，再降 192×192 重出 6 类；同时核对 §6.3 第 4 项接线后的真实卡面尺寸。
