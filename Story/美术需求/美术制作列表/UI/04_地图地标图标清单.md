### 1.1 显示尺寸与交付主档

| 小地图框 | 190×190 设计档，待接线 | 254 / — | 380×380 | 02 §5.4 |
| 节点选中框 / 暗罩 | 234×176 设计档，待接线 | 312×235 / 呼吸动画待确认 | 468×352 | 与 02 卡底共用注册框 |

普通地标、主城的 24 / 32 是批次绘制档，**当前 Glyph 实际是 22 / 30**。WorldMapPointIcon 悬停 ×1.35、选中 ×1.6，选中优先。地图常态缩放由 WorldLocationsView 对标记做反向缩放，地图底图的缩放倍数不能直接用作地标出图倍率。按两档截图复核默认、悬停、选中和重叠状态。

96 / 128 / 256 是制作主档，给小图造型和裁切留余量。清晰度靠短线、块面和负空间在目标显示尺寸可读。现有地图配置紧邻的图标用运行时避让方案联调，图标不要放大来掩盖挤压。

### 1.2 裁切、对齐和边缘

- 单个地标一张透明 PNG。按有效轮廓裁掉多余透明区。主档保留约 1–2px 防裁边缓冲，使用方形注册框时允许原造型短轴上的必要透明区。保持比例和视觉中心。禁止为填满方框把宽扁剪影强拉成方形。
- 清除纸底、白晕、黑晕和漫出的灰边。轮廓保留必要的半透明抗锯齿，镂空用真透明。对比暖纸和深墨两种背景。
- 地标与圆形小地图框 Border 0，按比例 Simple。节点选中框可 Sliced，Border 48,48,48,48，中心透明；暗罩为同一注册框的均匀低 Alpha Simple，Border 0。两层与卡底共用轴心及裁切坐标。

### 1.3 单色、明暗与线宽

| 项 | 规格 |
|---|---|
| 剪影色 | **单色**：一张图只用一种不透明色相，不得自带第二种颜色或底板。具体色值按 02 §1.4 的概念风格选定 |
| 纹理（淡但有） | 允许**同一色相内** 1–2 级明度起伏（≤8% 明度）：石墙砌缝、木纹明暗、田埂起伏。主档上看得见，缩到逻辑尺寸后不显。**禁止**第二色相、方向性渐变带、噪点、材质贴图——地标是剪影，纹理只做「别太平」的一点点 |
| 局内节点明暗 | 必须用**浅色剪影**：局内卡底实测为深色 `(42,36,29)`，深色剪影对照只有 **1.01:1**，等于看不见；大地图反之用深色剪影压浅色底板 |
| 镂空 | 内部细节用**透明负空间**表达，不画白色/浅色填充 |
| 渐变 / 发光 / 投影 | **禁止**（与上条纹理不冲突：纹理只用于局部明度层次） |
| 外轮廓描边 | **不使用独立外描边**——形状由实心块面的边界构成 |
| 内部分界描边 | **主档约 4px**，用于檐口、洞口内沿、田埂等内外分界 |
| 结构主笔画 | **主档 6–8px**，缩小后检查剪影主结构是否连续 |
| 最小负空间 | **主档建议 ≥8px**。在 1080p 默认态检查最窄镂空是否仍可辨 |
| 抗锯齿 | 允许窄的 Alpha 抗锯齿过渡，边缘不出现底色污染或柔光 |
| 换算 | 绘制笔画按主档标注；屏幕实际线宽随 Glyph 适配与状态缩放 |

### 1.5 出图后自检

检查成品尺寸、主轮廓外接框、中心、Alpha 与背景。程序可批量查尺寸、边界和透明通道。半透明像素按功能判断：剪影应只在边缘抗锯齿，叠层暗罩允许均匀半透明。检查输出在 Unity 的放大、缩小、浅底、深底与真实叠层中的效果。脚本只处理和检验已经生成的位图。

## 3. 禁止文字与符号（**强制条款，违反即整批退回**）

**3.1 图标内不得出现任何文字形态。**

| 类别 | 禁止内容 |
|---|---|
| 文字 | 汉字、假名、谚文、拉丁字母、西里尔字母、阿拉伯字母，以及任何真实或虚构文字体系（含甲骨、金文、小篆、隶书、楷书字形） |
| 数字 | 0-9、罗马数字（Ⅰ Ⅱ Ⅲ）、算筹、计数刻痕、序号 |
| 标点 | `，。、；：！？（）【】《》""''…—` 与 `. , ; : ! ? ( ) [ ] { } " ' / \` |
| 符号 | `× ✕ ✓ ✔ + − ± ← → ↑ ↓ ↵ ★ ☆ ￥ $ % # @ & * ~ § † ‡ ● ▲ ◆ ○ □` 及任何字符形态 |
| 伪文字 | AI 生图常见的"像字不是字"的乱码、扭曲纹章字母、篆刻伪字、符文、铭文、字母浮雕 |
| 地图专属 | **地标图标不得自带编号**（1~12、Ⅰ~Ⅻ、甲/乙/丙）、不得自带星级表示主城等级、不得自带货币符号表示贸易 |

**3.2 语义只能由「剪影 + 形状 + 配色」三者承担，其余一律不许。**
不许用文字缩写（`铁` `盐` `市`）、不许用字母区分（`F` `M` `T`）、不许用符号提示（`?` 传闻、`!` 任务、`×` 未解锁）。

**3.3 天然靠文字区分的类型，一律改图形隐喻：**

| 概念 | ❌ 禁用 | ✅ 允许 |
|---|---|---|
| 铁匠 | "铁"字 / "F" | 铁砧 + 锤 |
| 酒馆 | "酒" / "T" | 酒壶 + 杯（壶口留负空间） |
| 集市 | "市" | 单坡棚 + 立柱 + 柜台（= `market_town`） |
| 盐场 | "盐" | 田格 + 卤池（= `saltworks`） |
| 传闻 | "?" / "闻" | 竹简双联（= `rumor`） |
| 任务 | "!" / "任" | 挂木牌（= `task`） |
| 未解锁 | "×" / 锁芯上的"锁"字 | 低 Alpha 暗罩（G-HUD-11） |

**3.4 判定方法（验收必做）**
1. 把成品缩到 **24px**（= 1080p 普通地标逻辑显示尺寸）看 3 秒：能读出任何字或符号 = 不合格。
2. 跑一次 OCR（任意引擎）：返回 **0 个字符** = 通过。
3. 缩到 24px 后仍能说出"这是什么地点" = 通过；说不出来 = 剪影不合格（不是加字，是改形）。

**3.5 现有工程的错误示范（不要再犯）**：图标缺失时 `WorldLocationsView.cs:474-503` 会在方块里写汉字（城/市/营/林/矿/石/盐/洞/迹/见/闻/事），`QA/WorldLocations/map-market-1920.png` 就是这个样子。**这是缺图兜底，不是设计**——本轮补齐图标后必须一次都不出现。

### 5.3 相邻图标不粘连（配置实测；素材侧只做缓解，根治靠代码）

按 `WorldLocationTable_Location.json` 62 个点位的 X/Y（0~1）换算到 IconLayer 1409.71×1080：

| 间距 | 对数 | 结论 |
|---|---|---|
| < 12px | **8 对** | 必粘连 |
| < 22px | **21 对** | 必粘连（22px = 一个图标绘制区） |
| < 30px | 26 对 | 会贴边 |
| 最近一对 | **1.9px**（1009 与 4006） | 完全重叠 |

→ **尺寸与重叠**：旧稿用「主体内缩 + 四周留白」挤出图标之间的空隙；改为紧贴外接框后，画布内已经没有可让的空白，这层缓解手段**失效**。素材侧能保证的只有「不为凑方框再往外扩」，因此 8 对 <12px 与最近 1.9px 的一对会直接叠死，必须靠运行时避让/聚合（§6.3 第 2 项）解决——程序侧在 InfoBar / IconLayer 上按 **≥12px 逻辑间距**避让（§7 裁决 2），已列为联调 P0。

### 5.4 缩到逻辑尺寸后剪影仍可辨
