## 0. 三条硬性铁律（不满足直接退回重做）

### 铁律 1 · 结构件留出运行时内容

**生成的任何一张 UI 素材，画面上不得出现任何可读内容。全部留空。**

明令禁止出现在素材里的东西（逐项检查，发现任何一项即判不合格）：

| 类别 | 禁止内容 |
|---|---|
| 文字 | 汉字、假名、谚文、拉丁字母、西里尔字母、阿拉伯字母、任何真实或虚构文字体系 |
| 数字 | 0-9 及任何计数刻痕、罗马数字 |
| 标点 | `，。、；：！？（）【】《》""''…—` 及 `. , ; : ! ? ( ) [ ] { } " ' / \ \|` |
| 符号 | `× ✕ ✓ ✔ + − ± ← → ↑ ↓ ↵ ⎋ ⇧ ⌘ ★ ☆ ￥ $ % # @ & * ~ § † ‡ ● ▲ ◆ ○ □` 及任何字符形态 |
| 伪文字 | AI 生成图里常见的「像文字但不是文字」的乱码、扭曲纹章字母、篆刻伪字、符文、铭文、字母浮雕 |
| 数值/标签 | 血条上的数字、等级数字、货币数量、星级、进度百分比、编号 |
| 商标/水印 | 任何厂商 logo（Xbox / PlayStation / 键盘品牌）、生成器水印、签名 |

**允许独立、无字的结构与纹饰**，如回纹角花、云气卷纹、铜件轮廓、嵌饰小菱形和纯几何指示。字符、数值、键名、货币数量和装饰性伪文字由素材留空，功能图标依专项清单处理。
方向类交互件（下拉、翻页、返回、折叠）只允许用**等粗线段的纯几何三角或折线**表达，不得画成 `←` `↵` `⎋` 这类字符字形。
键盘键帽除轮廓与底色外一律留空，功能靠运行时 TMP 文本 / 独立图标叠层表达（详见 `03_按键图标规范清单.md`）。

> 原因：本工程 UI 的动态文字 由 TextMeshPro 在运行时写入（中文本地化会换语言），素材里烘死任何字，切语言就废；且 AI 生图无法保证字形正确，只会产出伪文字污染画面。

### 铁律 2 · 同类控件必须复用同一张 Sprite

同一复用组共享结构、线宽和纹样。按清单交付必要状态及尺寸变体。普通、悬停、按下、禁用等状态沿用同一张母版的几何、画布、pivot 与 Border，以局部改色、明暗和纹理强度表达状态。选中需要能与悬停区分。不同界面优先复用，新增状态以实际使用为准。

MainMenuPanel、SettingPanel、SLPanel 的根 Image 已经引用旧版 Panel_Main。其他纯色壳或运行时生成的面板使用同组是**接线计划**，由 Unity 接入时替换底图并核对 Image.color 与文字颜色。

### 铁律 3 · 复杂形状只给边框 + 极浅淡纹理

轮盘、圆环、冷却环、沙漏等**形状复杂且可能带动画**的件（见第 5 节专项），**只允许出：干净的边框 + 极浅淡的基础纹理（径向/线性渐变、低对比噪点）。**
不得加：**会穿帮的那类装饰**——方向性纹样、投影、外发光、非对称装饰、任何会在旋转/缩放/拉伸下扭曲的具象图案。装饰的有无与形态由§1.4 概念图规则决定，本文档只禁止"动画一跑就露馅"的项。
原因：这类件会在代码里旋转/缩放/fillAmount 动画，装饰会被拉伸扭曲、旋转穿帮、遮罩边缘露馅，且运行时叠加的图标与文字会被装饰抢注意力。**越素越可靠。**

## 1. WorkBuddy 出图与 Unity 接入

### 1.1 直接位图与分辨率

- 用 **WorkBuddy 生图能力直接绘制光栅图**。交付 **8 bit/channel RGBA PNG（PNG-32）、sRGB、直通 Alpha**。禁止 SVG、矢量转 PNG、脚本画图、HTML/Canvas 渲染或截图作图。允许对原生位图抠图、清理边缘、统一状态、裁切、对高像素原图做一次高质量等比降采样。
- **单张和整批均无文件体积上限**。保留原生高质量母版，运行交付一套 PNG。遇到上传通道的实际限制，用本地文件、分批传输或无损归档交付。原生画布不足且细节过不了验收时标记待补，重新生成或按已定义的独立结构分件。插值放大不能算新细节。
- 以 1080p 下最大实际或设计显示框为起点。**1440p 显示需求 = 逻辑宽高各乘 4⁄3，向上取整**。固定件按裁后有效像素和最大状态核算，结构件按成品主档验收。§3.0.2 结构件多用 2× 密度给边角与抗锯齿留余量，小件、旋转件、横竖拉伸件、地图等单列。未接线的尺寸为设计档，需在 Unity 确认后才批量做。
- 旧 `Panel_Main.png` 的 **748×560** 仅供找图。三个已引用的全屏根 Image 以 **1920×1080** 作构图，1440p 下覆盖 **2560×1440**，推荐直出 **3840×2160** 主档。无需为了新图改全屏锚点。纸面和边角按新尺寸重新绘制。

### 1.2 裁切、对齐与 Alpha

- 单个独立元件一张 PNG。去掉概念板纸底、接触阴影、杂物和大块空白。透明背景图用包含抗锯齿的有效轮廓外接框，常规件四周仅保留约 1–2 个主档像素的透明缓冲，需全屏铺到边的底图可以贴边并实底填满。内部镂空用真实透明。禁止白底或纸底残边、背景污染、黑晕和过度羽化。
- 处理拼版时先核对裁切位置与元件语义，再拆为独立源图。去底和清理边缘完成后才等比定尺寸。宽按钮、长条优先单独出图，或按批准的固定角、边条和中心底材组装。四角应落在实际固定边带里，透明补边不计入有效主体尺寸。
- 轮廓抗锯齿允许连续 Alpha。实底区不透出游戏画面。选中叠层、暗罩、渐隐提示等按功能保留计划内的半透明像素。对浅纸、深墨、彩色游戏画面三种底检查边缘。
- 从通过验收的 Normal 母版派生各态。只编辑所需的颜色、明度或内框高亮。需要精确套准时用同一轮廓蒙版或独立叠层，逐态叠合核对几何。状态套图、旋转件和需套准的叠加件共用注册框、轴线、Border 和 pivot，允许保留对位透明区。
- 先裁切，再对成品像素标记 Border、pivot、纹理安全区。Atlas 打包 padding 单独由 Unity 设置。四角纹样和必要抗锯齿都须落在各自固定角格内。

### 1.3 九宫格安全纹理与填充

| 图层 / 部件 | 画法 | Unity 用法 |
|---|---|---|
| 实底面板、弹窗、列表行、卡片 | 暖纸底有极浅、无方向的细纤维或颗粒，内容区留出稳定明度。外框墨线与暗朱漆内线；四角收住回纹。伸缩区保留纸底 Alpha。若长宽变形后仍看得出颗粒被拉长，减弱底材并拆固定密度纹理。 | 首先交付一张可直接挂的 Sliced 底图。四角固定，横边中段沿 X 拉伸，竖边中段沿 Y 拉伸，中心随双轴变化。 |
| 独立空框、选中框 | 中央真实透明。横竖伸缩边使用稳定的线宽和颜色；角花放固定角格。 | Sliced，核对 Fill Center 和中间 Alpha。相同组件的底图与框共享外框及 pivot。 |
| 复杂纹饰与纸纹加强层 | 云雷角花、织锦、编绳、轴头、中央小铜扣、淡龙凤/山水底纹独立。编绳和回纹可另出无缝重复段。 | 角花、轴头、徽记用固定比例 Simple 层。纸纹需要保持密度时用裁剪区域内的 Tiled 层；可见周期纹样逐屏检查接缝。单图规格是首交，新增叠层须列为接线项。 |
| 动态条、Slider、HUD | 底轨与填充分开。端帽、钱形徽记、刻度、尾端装饰在固定轨道或独立层。填充条沿增长方向保持均匀，只在短轴作极轻的哑光层次。 | 轨道可 Sliced；已有 Filled/Mask/Slider 的填充保留原行为，Border 记 0。0/25/50/100% 检查无端帽跳动、重复纹理或错位。 |
| 圆环、方槽、箭头、图标与扇区 | 纹理随轮廓走，优先让剪影和轮廓在实际尺寸上辨认。 | 按现有 Simple、Filled 或旋转方式接入，避免强行套九宫格。 |

中按钮以 B01 纹理样件为参考。四角固定区可见哑光漆纹和少量做旧，回纹及其外缘须完整落在固定角格。伸缩边保持漆线宽度稳定，纸面保留低对比、无明显方向的细颗粒。按 100×56、200×60、300×54 逻辑尺寸复核回纹保形、纸纹拉丝和切线接缝。

Unity Sprite Border 顺序 **左、下、右、上**，按最终 PNG 像素填写。屏幕缩放前的逻辑边宽约等于 `BorderPx ÷ [(Sprite PPU / Canvas Reference PPU) × Image PPU Multiplier]`。例如主面板主档 Border 80，Canvas Reference PPU 100 时，可用 Sprite PPU 200、Image Multiplier 1，得逻辑边宽 40；保留 Sprite PPU 100 时，Sliced Image Multiplier 可设 2。检查旧有 SetNativeSize、布局驱动和状态共用，Multiplier 不改变 SetNativeSize 的结果。取最小使用尺寸验证每轴均大于两侧逻辑 Border 之和，极细控件另测 Simple 或单轴设计。边框需要在两轴保持厚度时给四边相应 Border，只设左右会让上下框线随高度缩放。

导入起点为 Sprite/Single/Full Rect、Bilinear/Clamp、Alpha Is Transparency 开、sRGB 开、NPOT None，普通屏幕 UI 的 mipmap 先关。按实际文件长边设置 Default 和各目标平台 Max Size。3840×2160 主面板和宽过 2048 的行、对话图可从 4096 档验证，分别查看 Sprite 预览与 Atlas 最终像素。巨型底图可独立导入。压缩以未压缩基准对照，特别看细墨线、Alpha 和纸面色阶。PNG 体积与 GPU 贴图/图集预算分别记录。

- 技术参考 [Unity 9-slice 手册](https://docs.unity3d.com/2022.3/Documentation/Manual/9SliceSprites.html) 和 [UGUI Image 接口](https://docs.unity3d.com/Packages/com.unity.ugui@1.0/api/UnityEngine.UI.Image.html)。

### 3.3 复用逻辑小结（为什么这样归组）

1. **按"控件语义"归组，不按"界面"归组**。同类控件在不同界面必须同图——这是 `G-` 前缀体系的全部意义。
2. **面板底是最大的一块复用**：12 个功能面板根节点实测都是「纯色 Image + 标题」，底板由脚本统一铺 → 天然一张图服务全部界面。
3. **Tab 与按钮必须分开**。二者尺寸接近，但语义不同：Tab 表达"当前在哪个分类"，按钮表达"执行这个动作"。混用会让选中态无处表达（现状正是如此）。
4. **状态靠同组多文件或 tint，不靠换组**。品质五色、条七色、行选中态都属于同一组的变体。
5. **不为小尺寸另出图**：九宫格能解决的一律靠九宫格；只有 `G-SYS-01` 因压缩比过大（554×934 → 150×200）例外。

## 5. 复杂形状与动画件专项（只许边框 + 极浅淡纹理）

> 本节所有件都满足：**形状不规则 / 带曲线 / 会旋转或缩放动画**。
> 对这些件，统一生产要求：**只有干净的边框 + 极浅淡的基础纹理（单向渐变或低对比噪点），不加任何明显装饰**。装饰会被动画拉伸/旋转穿帮，也会和运行时叠加的图标、文字打架。
> 每条给出确切尺寸、形状、半径、角度——照数值画，不要目测。

> **分两类处理**：工程内**已实现**的复杂件 = 快捷选择轮盘（`RadialMenuView` + `DefaultSlices.png`）、扎营时间轮盘（`RadialWedgeGraphic` 程序化 mesh）、条类（Boss 条 / 阶段刻度）；**尚未实现**的 = 技能冷却环、小地图圆框、深度 HUD 环、加载沙漏——`fillAmount` 全工程只用于水平条（`LoadingController.cs:239-242,762`）。
> 对**尚未实现**的件，按「新增设计」处理：先照本节几何参数设计形状，再出图；不要去找旧素材对照，工程里没有。

**必须遵守的形状约束**：
1. 每个 sprite 只画**一片**扇区，其余 1200×1200 区域 alpha 必须为 0（透明），否则旋转后互相遮挡；裁掉透明区会让旋转中心偏移，**禁裁边**。
2. 扇区必须**径向对称**：不能有光从左上来、不能有单向高光、不能有纹理走向。因为整片会被旋转到任意角度。
3. 边框线宽恒定（主档 4px = 逻辑 2px），内外沿圆弧用同一线宽，弧段端点不必封口（相邻片会贴合）。
4. 中心孔（**r < 79**）必须完全透明，那里是图标与文字的落点。
5. 内环展开时缩到 0.58 —— 线宽会视觉变细，所以**内环素材的线宽可比外环粗 1px** 作为补偿（可选，若内外环共用一张则取中间值）。
6. 只出 **1 张主档 = 1200×1200**。Unity 导入 `Max Size` 设 2048、`Compression = None`（核查导入后细线与边缘）。

**生产结论**：表中半径为 600×600 逻辑坐标，落到 1200×1200 主档时半径与线宽乘 2，角度不变。先做内外环各一组，联调通过后补齐各项数。
> 轮盘扇区形状复杂（环形扇区、任意角度旋转、缩放动画），且运行时在其上叠加 30×30 图标与三行文字。
> **因此本组素材只允许：1 条恒定线宽的边框 + 扇区内部极浅淡径向渐变（两色差 ≤ 8% 明度）。不得加花纹、纹理图案、高光、投影、内发光、任何不对称装饰。**

## 附录 B · 术语对照

| 术语 | 含义 |
|---|---|
| 九宫格 / Border | Unity Sprite 的 9-slice 边距，用于控制角格、单轴边段和双轴中心的伸缩 |
| tint | 运行时 `Image.color` 乘色，用来让一张中性灰素材变出多种颜色 |
| 预制体 / prefab | Unity 可复用 UI 模板 |
| 壳预制体 | 文件里只有根节点 + 标题，真正控件由 C# 在运行时 new 出来 |
| 实控件预制体 | 控件在文件里真实存在（SettingPanel、SettingRow_*、MainMenuPanel 等） |
