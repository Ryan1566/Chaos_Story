## 1. 目标与范围

局内通过功能集合查看队伍、局内背包和局内地图。此次实现物理背包格位、分类整理、永久重要道具收藏、扩格入口和单格键鼠绑定。队伍、局内地图及前三类道具的快捷选用保留入口和明确占位文字，尚未实现相应玩法。

局外仓库继续使用原库存规则。局内四类格位单独保存扩格进度，不采用局外仓库的基础 8 格、24 格上限或 `EffectType=2` 格位加成。

本轮没有新增重要道具、工程道具的正式内容，也没有虚构剧情、事件或养成奖励。类型、扩格接口和验证用临时定义，不代表正式内容已经接入。

## 2. 入口与页面

| 入口 | 场景与行为 |
| --- | --- |
| Tab / 功能集合动作 | 局内打开功能集合；已打开该集合时再次触发可关闭。首次进入默认显示局内背包；已有面板可保留选中页签。 |
| M / 地图动作 | 局外村庄打开世界观地图；局内打开集合中的局内地图页签。局内不借用局外世界地图。 |
| 队伍页签 | 显示待接入占位。 |
| 局内背包页签 | 显示四类物理槽、开放状态、物品堆叠和未带入的重要收藏。 |
| 局内地图页签 | 显示待接入占位。 |

功能集合打开期间暂停局内世界、阻止角色玩法输入。继续、关闭或返回游戏时恢复暂停前的时间状态。设置、扎营等覆盖面板的打开和返回，不应提前解除集合持有的暂停。

“撤离”需要再次确认；确认前可取消。普通局内行囊按原撤离规则处理，已登记的重要道具永久所有权保留。切页、关闭面板或渲染刷新应取消尚未完成的拖拽。

## 3. 四类物理槽

| 区域 | 新存档初始开放 | 最大槽数 | 允许放入 | 快捷选用 |
| --- | ---: | ---: | --- | --- |
| 重要道具 | 0 | 5 | `RunCategory=1` | 仅预留 |
| 工程道具 | 1 | 7 | `RunCategory=2` | 仅预留 |
| 疗伤加成 | 2 | 7 | `RunCategory=3` | 仅预留 |
| 杂物 | 5 | 30 | 全部局内类型 | 无 |

杂物按 10 列、3 行布局，共显示 30 个物理槽；未开放格显示“未开放”，不可放入。前三类各为一行。一个槽容纳一个物品类型的整堆，堆叠数量遵守道具的 `StackLimit`；`IsUnique=true` 时数量上限为 1。重要道具无论传入数量多少，每个类型最多拥有和携带 1 个。

当前入包策略为：重要道具先尝试重要行，再尝试杂物；普通道具先尝试杂物，杂物无空格时可尝试相应专用行。已有同类堆叠优先增加原堆。这个策略不改变玩家通过拖拽整理物品的规则。

## 4. 分类与道具标识

| Item 字段 | 约定 |
| --- | --- |
| `Index` | 道具类型的唯一标识；永久收藏也按此 ID 去重。 |
| `RunCategory` | 新增局内分类：0 杂物、1 重要、2 工程、3 疗伤加成。 |
| `IsUnique` | 新增唯一性字段；普通物品为 true 时也只允许数量 1。重要道具直接按其局内分类执行唯一规则。 |
| `Category` | 保留旧用途，不用它判断局内专用行。 |

本轮源表已追加 `RunCategory`、`IsUnique` 两列。现有 ID 1、5、6 归为疗伤加成，其余现有道具归为杂物；未新增正式重要或工程道具。后续正式内容应配置真实 `Index`、名称、分类、启用状态和堆叠上限，再验证获取渠道。

## 5. 重要道具永久收藏

1. 通过 `InventoryService.AddItem` 或 `RunInventory.AddItem` 获得重要道具时，按 `Index` 登记至 `ownedImportantItems`，重复获得不复制。
2. 永久所有权保存成功后才算获得成功。保存失败必须回滚所有权；地面拾取不能因此提前销毁掉落物。
3. 物理背包已满时仍可登记永久收藏；界面应提示已经收藏，并在有可用槽后允许通过“带入”将未携带收藏放入重要行或杂物。
4. 开始新一局时尝试自动带入已有的重要收藏；可用格不足的继续保留在收藏列表。
5. 重要道具不能消耗、丢弃或出售；失败、撤离、普通行囊清空和重新开局均不清除永久所有权。
6. 市场等收费获取渠道必须以永久收藏登记成功作为重要道具的获得判据，并拒绝对已拥有的重要道具再次收费。不能沿用普通仓库数量增长判据。

重要收藏与当前携带是两个状态：永久拥有不代表本局一定占有物理槽。界面“带入”只改变当前携带，不再次收费或重新授予所有权。

## 6. 拖拽与交换

从已开放且有物品的槽以鼠标左键拖拽，松到已开放目标槽时整堆移动。目标已有物品时交换两堆，不合并、不拆分、不复制。

交换前同时检查两边的目的地类型：来源物品必须能进入目标行，目标物品也必须能进入来源行。任意一方不合法，整次操作拒绝，数量和两个槽均不改变。例如，工程物品从杂物拖到工程行，而工程行已有另一件工程物品时可交换；若来源为疗伤行、目标工程物品无法放回疗伤行，则应拒绝。

拖到自身不改变状态；空源、未开放格、越界格和错误类型操作给出原因。拖拽只整理物理位置，不改变永久收藏。

## 7. 扩格来源与幂等

事件、剧情、养成可以调用统一扩格 API，传入区域、正数数量和稳定的 `sourceId`。现阶段只提供调用能力，没有添加具体奖励事件或正式扩格内容。

扩格回执存入 `runSlotGrants`，以“区域 + sourceId”识别同一区域的同一来源；同一回执重复触发不再增加格位。不同区域可以使用同一来源 ID，分别形成回执。数量增加后夹到该区域最大槽数。无效区域、非正数量、空来源拒绝；已满且尚无回执的新授予拒绝。

独立授予应完成自己的保存事务；已处于事件等玩法命令的变更阶段时加入外层事务。保存、提交回调或最终状态通知阶段不能再把新奖励混入已经结束的变更。保存失败必须同时回滚容量和回执。

## 8. 单格键鼠绑定

跳跃默认只绑定空格，取消 K 与隐藏空格备用键并存。每个键鼠动作只有一个可替换绑定格，该格可接收键盘键或鼠标按钮；改为鼠标后原键盘路径不再作为第二触发器。移动按左移、右移各一行呈现，每个方向各有一个绑定格。

功能集合默认 Tab，地图默认 M。手柄保留独立方案和单独的重绑定，键鼠改键不覆盖手柄路径。手柄功能集合动作保留可配置入口，当前没有默认按钮。
