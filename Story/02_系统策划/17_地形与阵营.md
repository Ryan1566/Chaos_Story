# 地形与阵营系统设计方案（W5.2 · M14 边缘空间的地形与各文明队伍）

> 状态：评审中
> Owner：策划
> 最后更新：2026-10-22
> 关联：`Story/01_企划/01_游戏概念案.md`（§6 M14）、`Story/02_系统策划/01_局内地图生成系统.md`（3 类场景 / `MapBiome` 草案）、`Story/02_系统策划/10_局内掉落与带出.md`（`DropGroup`）、`Story/02_系统策划/14_进度界面与时代推进.md`（`Era`）、`Story/02_系统策划/02_局外世界观地图系统.md`（局外势力）

> **本文的两个结论（先看）**
> 1. **地形：不新建表** —— 复用现有 **`MapBiome`（地图主题表，已有 3 行 = 3 类地形）**，只在它上面**加 3 列**（`EnemyHpMul` / `EnemyDmgMul` / `DropGroupBase`）。
> 2. **阵营：不新建表、不加列** —— 原型期用 **(B) 时代映射**（`Era → 阵营` 5 条常量），**不用** (A) 局外地图出发地点势力（理由见 §4）。
> 影响面**只做 3 项**：① 敌人属性倍率 ② 掉落组由地形决定 ③ 进入场景的文字提示。**不做**敌人数量差异（原因是代码常量，改动面超出最小项）。

> **当前实现核对（2026-10-22，源码与导出 Json 静态核查；历史运行证据见 `20_W5阶段验收报告.md`）**
> - `MapBiome_地图主题表.xlsx`：**3 行** —— `1=Underground(地下, layer=1)`、`2=Surface(地表, layer=2)`、`3=Building(地表建筑, layer=3)`；现为 9 列：`Id/themeKey/nameCN/layer/retryMax/enable/EnemyHpMul/EnemyDmgMul/DropGroupBase`，3 项扩列已经导出。
> - `MapPreset`：4 行，`biomeId` 指 `MapBiome.Id`；`RunMapBootstrap.BuildScene` 按 `sceneIndex` 取 `presets[sceneIndex-1]` → **场景 1→预设 11（地表）／2→预设 10（地下）／3→预设 12（地面建筑）**（顺序由 `AllocateRunPresets` 决定：`{Surface, Underground, Building}`，**不按 Id 升序**），即"场景→地形"**已经存在**，无需新映射。
> - `EnemyPlaceholder`：`maxHp = 30`、`contactDamage = 5`、`contactDamageInterval = 0.8f`（均为 `public` 字段，可被倍率覆盖）。
> - `RunEncounter.EnemiesPerRoom = 2`（**代码常量**，不是表）。
> - `DropService`：`RollForEnemy(uint dropGroup, uint runSeed, uint killSeq, ...)`；`GroupNormal = 1`、`GroupElite = 2`；`Drop` 表组 1 有 4 行、组 2 有 2 行。
> - `WorldMapService.TryGetFactionAt(uint stage, Vector2 normalized, out uint factionId, out uint regionId)` **存在**；但 `WorldFaction` 仅 **7 行占位**数据、且**没有"出发地点"概念**。
> - `MetaProgressService.Era`（1~5）、`Depth`、`EraConfigService.GetFinalDifficulty(era, depth)` 已落地。

## 1. 系统概述

| 项目 | 内容 |
| --- | --- |
| 系统名 | 地形与阵营（Terrain & Faction，M14） |
| 所属模块 | 概念案 §6 **M14 边缘空间的地形与各文明队伍** |
| 优先级 | MVP（计划的 W5.2；**只做最小可验证闭环**） |
| 一句话说明 | 局内 3 个场景天然对应 **3 类地形**（地下 / 地表 / 地表建筑）；每类地形给**敌人属性倍率 + 掉落组**；再叠一个**阵营**（原型期由当前时代决定）给**额外属性倍率**；进入场景时用**一行文字**告诉玩家"地形：地表 · 阵营：秦军"（第 1 场景） |
| 上游依赖 | `MapBiome`（地形）、`MapPreset`（场景→地形，已存在）、`Drop`（掉落组）、`Era`（阵营来源） |
| 下游影响 | `EnemyPlaceholder`（HP/伤害倍率）、`DropService`（掉落组）、场景提示 UI |
| 本系统涉及的配置表 | **只读/扩列**：`MapBiome`（+3 列已落地）；**不新增表** |

### 1.1 设计目标

| # | 目标 | 如何验证 |
| --- | --- | --- |
| G1 | **地形差异能被感知** | 同一场景链里，地下/地表/建筑的敌人**血量或掉落**明显不同 |
| G2 | **地形差异是表驱动的** | 改 `MapBiome` 的倍率列 → 重导 → 敌人属性/掉落随之变化，代码 0 改动 |
| G3 | **阵营有个明确来源** | 改 `Era` → 进入场景提示的阵营名与倍率变化 |
| G4 | **不铺开** | 只落地 3 项影响面；不做敌人数差异、不做外观换皮、不做完整文明设定 |
| G5 | **可复现** | GM 能强制指定时代/场景，稳定复现"某地形+某阵营" |

### 1.2 明确不做的（Non-goals）

| # | 不做的事 | 原因 |
| --- | --- | --- |
| N1 | **敌人数量按地形变化** | `RunEncounter.EnemiesPerRoom` 是**代码常量**，改成表驱动要动生成管线 → 超出"最小项"（§13 Q1 登记） |
| N2 | 完整文明设定（各文明队伍的背景、兵种、台词） | 只需"阵营标签 + 倍率"；内容归后续 |
| N3 | 地形专属房间块/瓦片换皮 | `MapChunk` 已按 `biomeId` 分块，**现有能力已够**；不再加 |
| N4 | 阵营影响事件筛选 | 事件只有 3 种触发条件（W5.1 用户裁决），不扩 |
| N5 | 阵营外观色（敌人染色） | 原型期**只做文字提示**；染色留后续 |
| N6 | 阵营随场景切换 | 一局内阵营固定（由出发时的 `Era` 决定） |

| 术语 | 含义 | 备注 |
| --- | --- | --- |

## 3. 规则详述

### 3.1 地形：复用 `MapBiome` + **加 3 列**（**不新建表**）

**为什么不用新表**：`MapBiome` 本来就是"**每类地形一行**"（3 行 = 3 类），还带 `layer`（空间层）与 `nameCN`（中文名，直接用于提示）；新建 `Terrain` 表会变成与 `MapBiome` **1:1 拆表**，纯增加维护成本。

**已落地的 3 列**（契约同步见 `01_局内地图生成系统.md` §8.2）：

| 列（第 3 行中文备注） | 第 4 行属性名 | 第 6 行类型 | 含义 | 默认/示例 |
| --- | --- | --- | --- | --- |
| 敌人生命倍率 | `EnemyHpMul` | `float` | 该地形敌人 HP 的倍率 | `1`；地下可 `1.2`、建筑 `1.5` |
| 敌人伤害倍率 | `EnemyDmgMul` | `float` | 该地形敌人接触伤害的倍率 | `1`；地表可 `1.0`、建筑 `1.2` |
| 掉落组基号 | `DropGroupBase` | `uint` | 该地形默认 `DropGroup`（`1` 普通 / `2` 精英） | `1`；建筑可 `2` |

> ⚠️ **这是"改现有表"而不是"新表"**：加列后需**重新导出**（`EventConfig` 等其它表不受影响）；老存档不涉及（这些是配置，不进存档）。

**地形差异（当前配置值；平衡评审见 `21_W5收尾与数值评审.md`）**

| 地形（`MapBiome.Id`） | 名称 | 敌人 HP 倍率 | 敌人伤害倍率 | 掉落组 | 玩法定位 |
| --- | --- | --- | --- | --- | --- |
| `1` | 地下 | `1.2` | `1.0` | `1`（普通） | 空间窄、消耗战 |
| `2` | 地表 | `1.0` | `1.0` | `1`（普通） | 基准 |
| `3` | 地表建筑 | `1.5` | `1.2` | `2`（精英） | 终局/精英 |

> ⚠️ **场景实际顺序是 `地表 → 地下 → 地表建筑`**（预设 **11 → 10 → 12**，由 `AllocateRunPresets` 的 `{Surface, Underground, Building}` 决定，**不是我最初以为的 10/11/12 顺序**）。
> 仅按当前地形 HP/伤害倍率，敌人强度**逐场景不降低**：第 2 场景（地下，HP×1.2）比第 1 场景（地表，×1.0）更难，第 3 场景（建筑，×1.5/伤害×1.2/精英掉落组）最难。
> **地形倍率仍按 `biome` 生效**：地表 `1.0/1.0/组1`、地下 `1.2/1.0/组1`、地面建筑 `1.5/1.2/组2`。

### 3.2 阵营：**(B) 时代映射**（不新建表、不加列）

**映射表（当前源码 5 个时代；倍率恒 1.00）**

| `Era` | 时代 | 阵营标签 | `FactionMul` | 说明 |
| --- | --- | --- | --- | --- |
| `1` | 战国末期 | **秦军** | `1.00` | 主角所属（概念案：秦国官吏） |
| `2` | 秦朝 | **秦军** | `1.00` | 当前只作阵营标签 |
| `3` | 秦末起义初期 | **楚军** | `1.00` | 当前只作阵营标签 |
| `4` | 楚汉争霸 | **楚军** | `1.00` | 当前只作阵营标签 |
| `5` | 汉刘邦时期 | **汉军** | `1.00` | 当前只作阵营标签 |

> 阵营**只影响**：① 敌人属性倍率（× `FactionMul`）② 进入场景的提示文字。**不影响**掉落与事件。

### 3.3 影响面（**只做 3 项**）

| # | 影响项 | 规则 | 落点（现有代码） |
| --- | --- | --- | --- |
| M1 | **敌人属性倍率** | `maxHp = Round(30 × EnemyHpMul × FactionMul)`；`contactDamage = Round(5 × EnemyDmgMul × FactionMul)`（**至少 1**） | `EnemyPlaceholder.maxHp` / `contactDamage`（public 字段，生成时覆盖） |
| M2 | **掉落组由地形决定** | 敌人死亡掉落用 `DropGroup = 地形.DropGroupBase`（**不再固定 1**） | `DropService.RollForEnemy(group, ...)`（已支持任意组） |
| M3 | **进入场景文字提示** | 进场景时提示一行：「**地形：地下 · 阵营：秦军**」 | 场景加载/`RunEncounter.EnterScene` 后 |

**明确不做**：敌人**数量**差异（N1）、阵营掉落差异、外观染色、事件筛选。

### 3.4 规则优先级

`地形（MapBiome 行）` > `阵营（Era 映射）`（地形决定掉落组与基础倍率；阵营只叠倍率）。

### 3.5 与既有难度的关系（**不要重复加难度**）

| 来源 | 作用 | 是否与本系统叠加 |
| --- | --- | --- |
| `Era.BaseDifficulty` + `Depth.DifficultyDelta`（`GetFinalDifficulty`） | 已提供难度指标与进度展示 | **当前敌人属性公式未接入**。源码 `EnemyPlaceholder.ApplyTerrainScaling` 仍是基值 30/5 × 地形 × 阵营；不得把难度指标误写成实际敌人倍率 |
| 地形 `EnemyHpMul/EnemyDmgMul` | 地形差异 | 是 |
| 阵营 `FactionMul` | 阵营差异 | 是 |

> ⚠️ **重叠风险**：`FactionMul` 与 `BaseDifficulty` 都随 `Era` 上升，将来同时接入会**重复放大**。**策划建议**：`FactionMul` 先全部填 **1.00**（只作"标签"），等数值调完再逐步引入（§13 Q2 待确认）。

## 4. 阵营来源：**为什么选 (B) 时代映射**（二选一的理由）

| 维度 | **(A) 局外地图出发地点势力** | **(B) 当前时代映射（✅ 采用）** |
| --- | --- | --- |
| 数据是否就绪 | `WorldFaction` **只有 7 行占位**（1 个势力 1 块区域），覆盖率极低 | `Era` 已稳定（1~5），GM 可一键改 |
| 需要的新概念 | 需要"**出发地点**"（`WorldMap` 现有点位没有标记哪个是村庄/出发点） | **不需要** |
| 可验证性 | 查询结果取决于归一化坐标是否落在多边形内 → **难稳定复现** | 改 `Era` 立刻变，**可稳定复现** |
| 实现成本 | 需先定出发点 + 补 `WorldFaction` 真实数据 + 处理"点在空白区" | **5 条常量 switch** |
| 语义准确性 | 局外势力（战国七雄）＝ 局内"各文明队伍"？**概念上并不等价**（M14 说的是"文明队伍"） | 同样不等价，但本波把阵营定位为**表现层标签**，不承诺与局外地图一一对应 |
| 升级路径 | — | 将来把映射挪进表（`Era` 加 1 列或新表）即可，**不影响本波接口** |

**结论**：原型期用 **(B)**，把"由局外地图出发地点决定"作为 **W6+ 的升级路径**（并登记 Q3）。

## 5. 状态与流程

### 5.1 一局内的地形/阵营

| 阶段 | 地形 | 阵营 |
| --- | --- | --- |
| 出发（`DispatchService.Depart`） | 未定 | **按 `Era` 定格**（整局不变） |
| 进入第 1 场景 | 预设 **11** → `biomeId=2` → **地表**（HP×1.0 / 伤害×1.0 / 掉落组 1） | 同上 |
| 进入第 2 场景 | 预设 **10** → `biomeId=1` → **地下**（HP×1.2 / 伤害×1.0 / 掉落组 1） | 同上 |
| 进入第 3 场景 | 预设 **12** → `biomeId=3` → **地面建筑**（HP×1.5 / 伤害×1.2 / 掉落组 2） | 同上 |

> **已定项（W5.3 写实）**：① **敌人数量不随地形变**（`RunEncounter.EnemiesPerRoom = 2` 是代码常量，本波不改生成逻辑）；② **`FactionMul` 全为 `1.00`**，阵营目前**只作标签**（名字 + 提示），不再叠难度；③ 影响面**只有 3 项**：敌人属性倍率 / 掉落组由地形决定 / 进场文字提示。
| 撤离/结算 | — | 清空 |

### 5.2 流程

```
出发 → factionId = EraToFaction(Era)（5 条常量）
进入场景 i：
  preset = presets[i-1]（现有逻辑）
  biome   = MapBiome[preset.biomeId]
  敌人生成时：maxHp = Round(30 × biome.EnemyHpMul × faction.Mul)
              contactDamage = max(1, Round(5 × biome.EnemyDmgMul × faction.Mul))
  进入提示：「地形：{biome.nameCN} · 阵营：{faction.Name}」
敌人死亡掉落：DropService.RollForEnemy(biome.DropGroupBase, runSeed, killSeq)
```

### 5.3 时序

| 顺序 | 发起方 | 接收方 | 动作 |
| --- | --- | --- | --- |
| 1 | `RunEncounter.EnterScene` | 地形/阵营服务 | 取 `biome`（按预设）与 `faction`（按 `Era`） |
| 2 | 服务 | `EnemyPlaceholder` 生成处 | 传入 HP/伤害倍率 |
| 3 | 服务 | 场景提示 UI | 显示「地形 · 阵营」 |
| 4 | 敌人死亡 | `DropService` | 用 `biome.DropGroupBase` 抽掉落 |

## 9. 边界与异常

| # | 场景 | 期望行为 |
| --- | --- | --- |
| E1 | 某 `MapBiome` 缺列/值为 0（加列后未填） | `EnemyHpMul/EnemyDmgMul` 视为 **1**、`DropGroupBase` 视为 **1** + Warn（不得变成 0 血/0 伤） |
| E2 | `preset.biomeId` 在 `MapBiome` 里不存在 | 视为 `Surface`（`layer=2`）+ Warn |
| E3 | `Era` 不在 1~5 | 阵营取 `1`（秦军）+ Warn |
| E4 | 倍率算出 0 或负 | HP 至少 **1**、伤害至少 **1**（clamp） |
| E5 | `DropGroupBase` 指向的组在 `Drop` 表为空 | 不掉落 + Warn（沿用 `DropService` 现有行为） |
| E6 | 双预设（`MapPreset` 20 号"双层"） | 以预设的 `biomeId` 为准（当前 =1 地下）；不特殊处理 |
| E7 | 中途改 `Era`（GM） | 本局阵营**不实时变**（出发时锁定）；下次出发生效 |

## 11. GM 演示路径（**实测目录：界面 / 系统 / 局内生成 / 道具 / 原型**）

> **GM 已实现入口**（「局内生成」下）：版块 **「地形与阵营」** → 「打印当前地形/阵营」「强制指定 Era（1~5）」「强制指定场景索引（1~3）」。

| 步骤 | 路径 | 看到什么 |
| --- | --- | --- |
| 1 | GM →「原型」→「进度」→「打印进度状态」 | 记下当前 `era` |
| 2 | GM →「系统」→「派遣」→ 出发 | 进入第 1 场景；提示「**地形：地表 · 阵营：秦军**」 |
| 3 | 观察敌人 | **地表**敌人 HP = `Round(30×1.0×1.0)=30`（`FactionMul=1.00`） |
| 4 | 击杀敌人 | 掉落来自 `DropGroup=1`（普通组） |
| 5 | 清空第 1 场景 → 进第 2 场景 | 提示「**地形：地下 · 阵营：秦军**」；敌人 HP = `Round(30×1.2)=36`；掉落仍用组 1 |
| 6 | 进第 3 场景 | 提示「**地形：地面建筑 · 阵营：秦军**」；敌人 HP `Round(30×1.5)=45`、伤害 `Round(5×1.2)=6`；掉落用 `DropGroup=2`（精英组） |
| 7 | GM →「局内生成」→「地形与阵营」→「强制指定 Era=5」→ 重新出发 | 提示「**地形：地表 · 阵营：汉军**」；倍率随之变化 |
| 8 | 同版块 →「打印当前地形/阵营」 | 日志输出 `biomeId/nameCN/倍率/dropGroup/faction/mul` |

## 12. 验收标准（可测试）

| # | 验收项 | 判定方式 |
| --- | --- | --- |
| A1 | **3 类地形可区分** | 3 个场景依次显示 **地表 / 地下 / 地面建筑**（实际顺序，非 Id 顺序） |
| A2 | **地形倍率生效** | 敌人 HP/伤害 = `Round(基础 × 地形倍率 × 阵营倍率)`，3 个场景数值不同 |
| A3 | **掉落组随地形变** | 第 3 场景（建筑）掉落来自 `DropGroup=2`（可用 GM 打印验证） |
| A4 | **阵营随时代变** | `Era` 1/2→秦军、3/4→楚军、5→汉军；提示与倍率同步 |
| A5 | **表驱动** | 改 `MapBiome` 倍率列 → 重导 → 敌人属性变化，代码 0 改动 |
| A6 | **不重复加难度** | 若 `FactionMul` 全 `1.00`，敌人属性只受地形影响（避免与 `BaseDifficulty` 叠加放大） |
| A7 | 提示文字 | 进入场景有「地形 · 阵营」提示；纯中文、不遮挡 HUD |
| A8 | 异常 | 缺列/悬空 `biomeId`/非法 `Era` 均按 §9 兜底，无崩溃 |
| A9 | 不做项 | 敌人**数量**在 3 个场景中**不变**（验证 N1 未被顺手实现） |
| A10 | 可复现 | 同一 `Era`+同一场景 → 敌人属性/掉落组一致 |
