## 1. 基线与编号

Unity 工程当前的 `bundleVersion` 为 `0.1`，玩家存档 `SavePayload.CurrentVersion` 为 `1`。`0.2.0` 是本次验收通过后拟登记的内部版本基线。首次登记前以实际构建和验收报告确认候选包内容。

| 编号 | 含义 | 更新时机 |
| --- | --- | --- |
| 应用发布版本 | 对应 Unity Player 的应用版本，首个拟登记内部基线为 `0.2.0`。 | 每次登记新发布包时确定。后续建议以补丁位登记修复，以次版本位登记阶段功能交付。 |
| 配置发布版本 | 同一发布包所携带配置的发布号。 | 与应用发布版本逐字同号。`0.2.0` 应用只与登记为 `0.2.0` 的配置一同交付。 |
| 存档结构版本 | 区分槽位存档字段结构和持久化语义，目前为 `v1`。 | 旧读法无法保留原意时独立递增，并先验证对应迁移。能安全补默认值的追加字段先用旧档样例验证。 |
| 局内检查点格式 | `ActiveRunSave.CurrentFormat`，当前为 `1`。 | 局内快照结构发生不兼容变更时独立处理。 |
| 地图生成器版本 | 记录局内布局生成规则，目前为 `v3`。 | 生成规则发生兼容性变化时单独维护。恢复局内还需核对地图配置指纹与布局签名。 |

应用和配置以同号成对发布，发布号用于辨认交付，配置指纹用于核对实际内容。即使配置内容无变化，候选包也要登记该应用发布号对应的配置指纹。登记后的同平台、同构建类型的发布包保持可复现，后续修正用新发布号登记。

## 2. 每个发布包的记录

每次内部或正式发布记录一条可追溯条目。以下是记录模板，首条 `0.2.0` 实值在验收时填入。

| 字段 | 记录内容 |
| --- | --- |
| 发布与构建 | 应用发布版本、同号配置发布版本、平台、内部测试或正式构建、日期、Unity 编辑器版本。 |
| 三仓来源 | `Project_Chaos`、`Chaos_excel`、`Chaos_Story` 各自完整提交号。若候选包含未提交改动，标记为本地候选，固定三仓来源后再登记发布包。 |
| 配置产物 | 保留 `ConfigTableIndex.json`、实际随包运行时配置清单及配置指纹。按文件相对路径排序，对索引及运行时消费的配置 JSON 计算逐文件 SHA-256，再对固定格式清单计算总指纹。生成的 C# 与原表提交对应关系一并核对。 |
| 兼容口径 | 存档结构版本、检查点格式、生成器版本、支持的旧档范围及续跑条件。 |
| 交付与验证 | 构建产物路径、包 SHA-256、功能和兼容验收报告、已知限制、可回退构建与旧档备份位置。 |

发布配置总指纹与局内地图配置指纹分别记录。前者覆盖随包配置，后者随局内检查点用于地图恢复。

## 3. 品牌预留与目录影响

公司名、项目对外显示名、游戏图标、开发组图标及开幕动画均待定。先在发布记录中预留这些条目，待确认资源与命名后安排接入。当前 Unity 使用 `DefaultCompany` 与 `Project_Chaos`，游戏图标与开发组开幕素材待提供。

Windows 当前的 `Application.persistentDataPath` 对应 `%USERPROFILE%\AppData\LocalLow\DefaultCompany\Project_Chaos\`。`Saves\Slot1.json` 至 `Saves\Slot3.json` 与 `Config\settings.json` 都在该目录下。变更 Unity 公司名或产品名时，需用候选 Player 实测新目录和旧目录读取行为。若路径改变，先确认旧目录导入规则、槽位冲突处理及设置迁移范围，再改正式命名。图标和开幕动画按品牌验收单独核对。

## 4. 里程碑

| 阶段 | 完成条件 | 当前状态 |
| --- | --- | --- |
| 现状登记 | 核对应用 `0.1`、存档 `v1`、现有目录和地图版本。 | 已记录源码与工程设置现状。 |
| 内部基线 `0.2.0` | 候选包通过本轮功能验收，应用与配置同号，三仓提交、配置指纹和构建证据齐备。明确当时可读取的档案范围。 | 待验收与登记。 |
| 迁移和发布检查 | 按 37 案建立迁移与发布检查，使用隔离档案取得验收证据。 | 后续实施。 |
| 品牌接入与正式发布 | 确定名称和图标、开幕动画，核对目录兼容。正式构建剔除 GM，取得包内与实机验收证据。 | 品牌和发布安排待定。 |

Unity 菜单「Chaos → 构建」提供「打包开发版」和「打包正式版」。开发版按 `Ctrl+Shift+G` 打开 GM，鼠标也可使用原按钮。正式构建移除随场景打包的 GM 画布和测试入口，并拒绝构建测试场景。后续发布验收见 37 案。
