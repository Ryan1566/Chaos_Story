# 进度界面与时代推进系统设计方案（W4）

> 状态：评审中

> 关联：`Story/01_企划/01_游戏概念案.md`（§5.3 两条正交轴、§6 M13/M13b、§9 两条进度分离展示）、`Story/02_系统策划/12_结算与进度.md`（结算逻辑）、`Story/02_系统策划/13_W3阶段验收报告.md`（W3 收口事实）、`Story/03_配置表设计/07_Era与Depth_字段规格.md`（`Era`/`Depth` 表）

> **本文定位**：W4 的**唯一**策划文档 —— 把"两条进度"从**数据**变成**玩家看得见、点得动**的两块界面，并定义**时代推进的交互**。
> **不改已有结论**：结算逻辑归 `12_结算与进度.md`，本文只写 **UI 字段 / 刷新时机 / 推进交互 / 缺口与建议**。

> **已定口径（不得改）**
> - **门客 = `Retainer`**（参战）；族人 = `Clansman`（不参战，本波不涉及）。
> - **深度上限 = 当前时代序号**（`DepthCap = Era`，运行时截断）；**深度不重置**。
> - **时代推进 = 双门槛、只 +1、不可回退**。
> - **两条进度必须分开显示**（概念案 §9 要求）：**时代（轴一）** 与 **深度（轴二）** 不能合成一个条。
>
> **现有落地（2026-10-18 实测，W3 收口于 `82c4032`，见 `13_W3阶段验收报告.md`）**
> - `MetaProgressService`：`Era` / `Depth` / `DepthCap`（=Era）/ `Clears` / `MaxClearedDepth` / `Runs` / `BossClearedThisRun` / `TryAdvanceDepth()` / `TryAdvanceEra()` / `DeployCap` / `CampRefillUnlocked` / `DumpState()`。
> - `EraConfigService`：`GetNameKey(era)` / `GetBaseDifficulty(era)` / `GetMilestoneType(era)` / `GetMilestoneValue(era)` / `GetFinalDifficulty(era, depth)` / `GetDepthBonus(era, depth)`。
> - `RunEncounter`：`MaxSceneIndex=3` / `CurrentSceneIndex` / `ClearedRooms` / `RunCleared` / **`Defeated` + `TriggerDefeat()`**；`PlayerHealth`：`hp=100`，**归零 → `TriggerDefeat()`**（W3.2d 起不再回出生点重生）。
> - `Era` 表实测：`MilestoneType=1`（累计通关数）；阈值 **era1~5 = 0 / 3 / 6 / 10 / 0**；`BaseDifficulty = 10 / 12 / 14 / 16 / 18`。`Depth` 表 25 行（`DifficultyDelta` 公式实测为 `(era-1) + (depth-1)×2`）。
> - **尚无**"时代进度面板"与"局内深度 HUD"；GM「原型 → 进度」可打印 `DumpState()`。

## 1. 系统概述

| 项目 | 内容 |
| --- | --- |
| 系统名 | 进度界面（Progress UI）与时代推进交互（Era Advance） |
| 所属模块 | 概念案 §6 **M13 时代/难度（轴一）** ＋ **M13b 层数/深度（轴二）** 的**表现层**；§9「两条进度分离展示」 |
| 优先级 | MVP（计划的 W4） |
| 一句话说明 | **局外**一个「时代进度」面板（时代名 / 深度 d/上限 / 累计通关 / 里程碑 progress / 下一时代双门槛 / 推进按钮），**局内**一个「深度进度」HUD（深度 d/上限 / 本局场景 n/3 / 带出上限）；推进时代要**二次确认**，不满足时**逐条说明缺什么** |
| 上游依赖 | `MetaProgressService`（全部数据）、`EraConfigService`（名称/难度/阈值）、`RunEncounter`（局内场景与 boss）、`DeployCap` |

| 本系统涉及的配置表 | **无新表**；只读 `Era`（名称/难度/里程碑）与 `Depth`（难度增量） |

### 1.1 设计目标

| # | 目标 | 如何验证 |
| --- | --- | --- |
| G1 | **两条进度一眼分得开** | 面板上"时代 2/5"与"深度 1/2"是**两块独立信息**，不是一条进度条 |

## 3. 规则详述

### 3.1 局外「时代进度」面板（`EraProgressPanel`）

| # | 字段 | 显示形式 | 数据源 | 备注 |
| --- | --- | --- | --- | --- |
| P1 | **当前时代名** | 「**战国末期**」（+ `时代 1/5`） | `EraConfigService.GetNameKey(era)` → 本地化 | **必须用本地化 key**，不写中文常量 |
| P2 | **当前深度** | 「深度 **1 / 1**」（当前/上限） | `Depth` / `DepthCap` | 到上限时高亮「已满」 |
| P3 | **累计通关** | 「累计通关 **2**」 | `Clears` | — |
| P4 | **里程碑进度** | 「里程碑 **2 / 3**」（当前/阈值） | `Clears` / `GetMilestoneValue(era)` | 阈值 0 时显示「无需里程碑」（见 §6） |
| P5 | **下一时代门槛①** | 「第 3 场景 boss：✔ 已击败 / ✘ 未击败」 | `BossClearedThisRun` | 局外时该值通常为 `false`（`TryAdvanceEra` 已清标记）→ 见 §3.4 |
| P6 | **下一时代门槛②** | 「累计通关 ≥ 3：✔ / ✘（当前 1）」 | `Clears` vs `GetMilestoneValue` | 逐条可读 |
| P7 | **推进按钮** | 「推进时代 → **秦朝**」；不满足时**灰显** + 上方原因 | `TryAdvanceEra` 前置判定 | 已是时代 5 → 「已是最后时代」 |
| P8 | **历史最大深度**（可选） | 「历史最深 **2**」 | `MaxClearedDepth` | 策划建议：加，帮助理解"深层解锁" |
| P9 | **本局次数**（可选/调试） | 「进入局内 **N** 次」 | `Runs` | 默认**不显示**（避免信息过载），GM 面板看 |

### 3.2 局内「深度进度」HUD（`RunDepthHud`）

| # | 字段 | 显示形式 | 数据源 |
| --- | --- | --- | --- |
| H1 | **当前深度** | 「深度 **1 / 2**」 | `Depth` / `DepthCap` |
| H2 | **本局已清场景** | 「场景 **2 / 3**」 | `RunEncounter.CurrentSceneIndex` / `MaxSceneIndex` |
| H3 | **带出上限** | 「可带出 **1 件**」 | `DeployCap` |
| H4 | 最终难度（可选） | 「难度 **10**」 | `EraConfigService.GetFinalDifficulty(era, depth)` | 

> **HUD 只读**：局内**不能**推进时代（必须在局外）。局内 HUD 不出现任何按钮。

### 3.3 刷新时机（**硬要求**）

| # | 时机 | 刷新什么 | 说明 |
| --- | --- | --- | --- |
| T1 | **打开面板时** | 局外面板全字段 | `BasePanel` 显示时拉一次 |
| T2 | **结算完成后** | 局外面板 + 局内 HUD | 一次结算可能同时改 `clears/depth/era/maxClearedDepth` |
| T3 | **时代推进后** | 局外面板（时代名/难度/深度上限/门槛） | 推进后立刻刷 |
| T4 | **深度变化后** | 局内 HUD | 通关 +1 深度时 |
| T5 | **场景切换后** | 局内 HUD 的 `n/3` | 进入下一场景 |
| T6 | **扎营/带出上限变化后**（可选） | 局内 HUD 的 `DeployCap` | 家族树变化时才变，原则上不会局内变 |

> **禁止**用 `Update()` 每帧刷新文本（性能与 GC）；用**事件/状态变更回调**或"面板可见时才在固定间隔刷一次"。

### 3.4 门槛①的特殊说明（**必须写进 UI 文案**）

`TryAdvanceEra()` 的成功条件含 `BossClearedThisRun`，而**推进成功后会把该标记清零**（防止"一次通关连推两个时代"）。
因此**在局外看面板时，门槛①通常显示 ✘** —— 它在"本次通关结算后、推进前"这一小段时间内为 ✔。

| # | 结论 |
| --- | --- |
| B1 | 面板上的门槛①应显示为「**本局已击败第 3 场景 boss**」并**只在结算后到推进前为 ✔** |
| B2 | 为避免玩家困惑，**建议**把门槛①的文案写成「**本次通关已满足**」而不是常驻的"未击败" |
| B3 | 若玩家在结算后离开/重进（`BossClearedThisRun` 不落盘）→ 需**重新通关**才能推进（**待确认** Q3） |

### 3.5 时代推进交互流程（**逐步**）

```
① 局外面板看到「推进时代 → 秦朝」
② 判定（按顺序，第一个不满足的给原因）：
     已是最后时代(era=5) → 「已是最后时代」
     门槛① 未满足        → 「本局需击败第 3 场景 boss」
     门槛② 未满足        → 「需累计通关 N 次（当前 M）」
   任一不满足 → 按钮**灰显** + 逐条原因；点击无效
③ 都满足 → 按钮可点 → 点击
④ **二次确认弹窗**：「推进到『秦朝』？时代**不可回退**，难度将从 10 提升到 12。」
        [取消] / [确认推进]
⑤ 点「确认推进」→ `TryAdvanceEra()`
        ├─ 成功 → era+1；深度按新上限 clamp；**清 boss 标记**
        │         提示「已进入『秦朝』，难度 12；深度上限 2」
        │         刷新面板（时代名/难度/深度上限/门槛全部变）
        └─ 失败（竞态/存档异常）→ 提示失败原因，**不改变**任何数值
⑥ 落盘（存档服务）
```

### 3.6 规则优先级

`已是最后时代` > `门槛①` > `门槛②` > `二次确认` > `执行`。

## 6. **era1 里程碑阈值：建议值 3**（**必须回答的数值问题**）

### 6.1 问题

`Era` 表实测 **era1 阈值 = 0**。`TryAdvanceEra()` 判的是**当前时代行的阈值**：`have(clears) < need(0)` 恒为假 → **只要打过第 3 场景 boss，第一次通关就直接进时代 2**。

### 6.2 后果（为什么必须改）

| # | 后果 |
| --- | --- |
| 1 | **时代 1 形同不存在**：玩家第一局就跳到时代 2，看不到"深度上限=1"的早期约束（M13b 的整条设计在开局就失效） |
| 2 | **深度轴失去"从 1 开始"的体验**：深度刚变 2 就换了基础难度档，玩家分不清"是深度变难还是时代变难" |
| 3 | 与概念案 MVP 口径冲突：MVP **只做第 1 个时代内容**，却一局就离开它 |
| 4 | 家族树/村庄的积累时间被压到 1 局（进化太快，养成立不住） |

### 6.3 建议：**era1 改为 `3`**

| 选项 | 评价 | 理由 |
| --- | --- | --- |
| 0（现状） | ❌ | 一局即进，见 §6.2 |
| 1 | ❌ | 第二局就进，仍太快 |
| **3（建议）** | ✅ | ① 让玩家在时代 1 **至少玩 3 局**（≈2 小时），体验"深度只能到 1"的约束；② 与现有曲线 `3 / 6 / 10` 连成 **3 / 3 / 6 / 10**，单调不减、无跳变；③ 一局 30~40 分钟 → 3 局刚好是"一个晚上"的节奏 |
| 5 | ⚠️ | 更稳，但 MVP 只有时代 1 内容，**5 局 ≈ 3 小时重复**容易让玩家以为"卡住了"；适合正式版内容充足时再考虑 |

> **配套建议（可选，不影响本次）**：若采用 3，era2 的 3 会让"时代 2 也要 3 次"略显平坦，可考虑把曲线调成 **3 / 5 / 8 / 12**；**但本文不改表**，仅登记为待确认（Q1）。

## 7. 复核：失败判定是否应从「受控角色倒下」改为「全队倒下」

### 7.1 现状（实测）

| 事实 | 位置 |
| --- | --- |
| `PlayerHealth` **HP 归零 → `TriggerDefeat()`**（W3.2d 起**不再回出生点重生**） | `PlayerHealth.cs:44` |
| `RunEncounter.Defeated` + `TriggerDefeat()` 存在 | `RunEncounter.cs:203/206` |
| **门客（`AllyController`）没有 HP / 阵亡状态** | `AllyController.cs`（实测无 hp 字段） |
| `MetaProgressService` 的 `TryAdvanceDepth/TryAdvanceEra` 与失败无关（失败不改进度） | `12_结算与进度.md` |

### 7.2 结论

| # | 结论 |
| --- | --- |
| V1 | **按设计应当是「全队倒下」才算失败**（概念案：角色**没有死亡机制**，只有重伤；主角也不是唯一战力） |
