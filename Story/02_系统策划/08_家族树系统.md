> 状态：评审中

> - **U4：5 板块 × 3 节点 = 15 节点**（① 影响力 ② 家族产业 ③ 门客培养 ④ 局外战斗 ⑤ 局内战斗）。

> - **U3**：格位 8 / 叠加 99；格位提升走 `EffectType=2`。
> - **效果模型**：`Effect`（类型码 1~8）+ `FamilyTreeEffect`（`Index`/`NodeId`/`EffectId`/`Weight`/`Enable`）；叠加规则 = **增量相加 / 上限取最高 / 覆盖取最后**，硬范围 clamp（带出上限 **1~10**、格位 **0~24**（以代码常量 `HardMaxSlots` 为准）、建造时长 **≥1s**）。

> **本文按代码的 24 为准**（代码是运行期真相），并建议把 `08_` §5.3 的 255 改为 24（**不是我的写权限内的顺手改**，等 Lead 裁决）。

## 1. 系统概述

| 项目 | 内容 |
| --- | --- |
| 系统名 | 家族树（FamilyTree）—— 局外养成主干 |
| 所属模块 | 概念案 §6 **M3 家族树（5 个板块）**；同时承载 **M10 扎营补充减员的解锁**（概念案原话：初期无法补充，需家族树加点后解锁） |
| 优先级 | MVP（计划的 W1b） |
| 一句话说明 | 5 个板块各 3 个节点；玩家花资源点亮节点，节点通过 `FamilyTreeEffect` 挂 1~N 个 `Effect`；所有已点亮节点的效果**按类型聚合**，供库存（格位）、带出（上限）、门客（属性/信心上限）、扎营（补员开关）等系统读取 |
| 上游依赖 | 资源与库存（点亮消耗资源、格位效果）、`FamilyTree` 表、`FamilyTreeEffect` + `Effect` 表、存档 `SavePayload.familyTreeNodes` |
| 下游影响 | 库存（格位）、带出（W3 上限）、门客（属性/信心上限）、扎营（W3 补员）、村庄（建造/产量） |
| 本系统涉及的配置表 | **`FamilyTree`**（节点）、**`FamilyTreeEffect`**（节点↔效果）、**`Effect`**（效果本体） |

### 1.1 设计目标

| # | 目标 | 如何验证 |
| --- | --- | --- |
| G1 | **15 个节点全部可点亮** | GM 一键点亮全部 → 15 个节点都变「已点亮」，无卡死节点 |
| G2 | **带出上限能成长到 10** | 点亮相关节点后，「带出上限」从 **1** 逐步升到 **10**（受 clamp 1~10） |
| G3 | **格位可提升** | 点亮家族产业/局内战斗相关节点 → 库存 `TotalSlots` 从 **8** 变 **11** |
| G4 | **解锁扎营补员** | 未点亮时扎营「补充减员」不可用；点亮 `303` 后可用（M10） |
| G5 | **效果可追溯** | 每个节点给什么**都能在表里查到**（`FamilyTreeEffect` → `Effect`），代码里没有硬编码加成 |
| G6 | **数据可存读** | 已点亮节点列表落盘；重进后状态与聚合结果一致 |

### 1.2 明确不做的（Non-goals）

| # | 不做的事 | 原因 |
| --- | --- | --- |
| N1 | 节点重置/洗点 | MVP 不做（避免退款套利）；**待确认** Q5 |
| N2 | 节点数量超过 15 | U4 已裁决 5×3；后续扩板块需新增表行 + 新 `Effect` 行 |
| N3 | 节点的"等级"（同一节点多次强化） | MVP 节点只有"未点亮/已点亮"两态（+ 前置锁定） |
| N4 | 局内即时生效的家族树 buff | 家族树效果是**常驻**；局内 buff 归 W3 的局内系统 |
| N5 | 节点美术（插画/连线动画） | 占位美术；连线用简单线条或纯色节点 |

## 2. 术语表

| 术语 | 含义 | 备注 |
| --- | --- | --- |
| 板块 / `Board` | 5 个分类：`1` 影响力 / `2` 家族产业 / `3` 门客培养 / `4` 局外战斗 / `5` 局内战斗 | `FamilyTree.Board` |

| 带出上限 | 反哺可带出的件数，**初始 1、满级 10** | 概念案 M12 |
| 格位 | 库存物品种类上限，**基础 8** | 见 `06_资源与库存.md` |

## 3. 规则详述

### 3.1 点亮条件（必须同时满足）

| # | 条件 | 违反时 |
| --- | --- | --- |
| R1 | **前置已点亮**（`PrereqNodeId = 0` 或该节点已在 `familyTreeNodes` 里） | 按钮显示「需要前置节点」，不可点 |
| R2 | **资源足够**（`CostType` / `CostValue`） | 显示「资源不足」，不可点 |
| R3 | 节点 `Enable = true`（已在表里启用） | 不显示 |
| R4 | 节点**未被点亮过** | 已点亮 → 显示「已点亮」，不可再点 |

### 3.2 点亮结果

| # | 结果 |
| --- | --- |
| R5 | 扣资源（`InventoryService.SpendResource`） |
| R6 | 把 `FamilyTree.Index` 加入 `SavePayload.familyTreeNodes`（`List<uint>`，**已存在**） |
| R7 | **重算聚合效果**（见 §3.3），并立即刷新相关系统（库存格位、带出上限、门客属性、扎营开关） |
| R8 | 写存档 |

### 3.3 效果聚合（**程序按此实现**）

```
已点亮集合 N = SavePayload.familyTreeNodes
效果集合 E = FamilyTreeEffect 中 NodeId ∈ N 且 Enable 的行 → 各自取 Effect[EffectId]（Enable 且存在）
按 EffectType 聚合：
  类型 1/2/3/4/6/7（增量）→ 相加（Σ Value × Weight）
  类型 5（解锁）        → 取最高（0/1，任一为 1 即解锁）
  类型 8（概率）        → 相加后 clamp 0~100
clamp 到硬范围：带出上限 1~10 / 格位 0~24（HardMaxSlots）/ 建造时长 ≥1s / 信心上限 0~100
```

**关键接口**（已落地，实测）：`InventoryService.ApplySlotEffects(List<uint> effectIds)`
→ 家族树点亮后，把**已点亮节点关联的全部 `EffectId`** 传给它，由它重算 `SlotBonus`/`TotalSlots`。

### 3.4 规则优先级

`R3 启用` > `R4 未点亮` > `R1 前置` > `R2 资源`（UI 上依次判断，决定按钮灰态与提示文案）。

### 3.5 效果来源范围

| 类型 | 只来自家族树吗 |
| --- | --- |
| 2 格位 / 3 带出上限 / 4 门客属性 / 5 解锁补员 | 家族树（W1b）+ 将来建筑/道具 |
| 6 建造时长 / 7 收获产量 | 家族树（W1b）+ 将来道具 |
| 1 资源产出 / 8 概率 | **W1b 不使用**（预留） |

> 聚合时**必须把来源合并**（家族树 + 建筑 + 道具 + …），不能各算各的。

## 6. 数据结构

### 6.1 运行时结构

| 字段 | 类型 | 含义 | 落盘 |
| --- | --- | --- | --- |
| `UnlockedNodes` | `List<uint>` | 已点亮节点 ID | **是**（现有 `SavePayload.familyTreeNodes`） |
| `AggregatedEffects` | `Dictionary<uint, float>`（**不落盘**） | 按 `EffectType` 聚合后的结果 | 否（每次由表 + 已点亮集合重算） |
| `LastAggregateVersion` | `int` | 变更计数（用于 UI 刷新） | 否 |

### 6.2 存档映射

| 存档字段 | 现状（实测） | 本系统用法 |
| --- | --- | --- |
| `familyTreeNodes` | ✅ **已存在**：`List<uint>` | **直接复用**：存已点亮节点 ID |
| 聚合后的属性值 | ❌ 不存 | **不落盘**（避免两处真相：改表后存档值会过期） |

> ⚠️ **`JsonUtility` 不支持 `Dictionary`** → 运行时聚合结果放内存字段，**不要**塞进 `SavePayload`。

### 6.3 供其他系统读取

| 数据 | 谁读 | 用途 | 落地方式 |
| --- | --- | --- | --- |
| 格位加成 | `InventoryService` | `TotalSlots` | `ApplySlotEffects(List<uint> effectIds)`（**已存在**） |
| 带出上限 | 带出选择（W3） | 上限 1~10 | 读聚合值（类型 3） |
| 门客属性/信心上限 | `RetainerService` / UI | 展示与判定 | 读聚合值（类型 4） |
| 扎营补员开关 | 扎营（W3） | 是否可补充减员 | 读聚合值（类型 5，0/1） |
| 建造时长/产量 | 村庄（`07_村庄系统.md`） | 建造与收获 | 读聚合值（类型 6/7） |

| --- | --- | --- |
| E1 | `familyTreeNodes` 里有表中不存在的节点 ID | 忽略该 ID（不影响聚合），记 Warn；**不删存档数据** |
| E2 | `FamilyTreeEffect` 指向的 `EffectId` 不存在 | 该关联跳过并 **Warn**（不崩溃）；节点仍可点亮但无效果 |
| E3 | 前置节点被禁用（`Enable=false`） | 该链后续节点**不可点亮**（前置条件永不满足），UI 显示锁定 |
| E4 | 重复点亮同一节点 | 拒绝，不扣资源 |
| E5 | 资源不足 | 拒绝并提示，不扣资源 |
| E6 | 老存档（无 `familyTreeNodes`） | 空列表，正常进入 |
| E7 | 聚合值被 clamp（如带出上限到 10、信心上限到 100） | 记 Warn（便于发现"效果给多了"） |
