# 门客生命与阵亡系统设计方案（W3.3 · 门客 HP / 受伤 / 重伤 / 补员 / 全队倒下）

> 状态：评审中
> Owner：策划
> 最后更新：2026-10-22
> 关联：`Story/01_企划/01_游戏概念案.md`（§6 M11 重伤与出战资格、M8/M10）、`Story/02_系统策划/05_门客系统.md`（局外状态与重伤规则）、`11_扎营与修整.md`（补员动作）、`12_结算与进度.md`（失败结算）、`14_进度界面与时代推进.md`（§7 失败判定复核）、`Story/03_配置表设计/09_Retainer_字段规格.md`

> **本文定位**：W3.3 —— 把「门客受伤 / 重伤 / 阵亡」从**占位**变成**真实规则**，并据此把**失败判定**改成「全队倒下」。
> 这三件事互为前提：① 失败判定要能改成"全队倒下" → 门客必须有 HP；② 扎营"补充减员"要能真复活 → 门客必须有"倒地"状态；③ 门客受伤有意义 → HP 与伤害要进伤害链。

> **已定口径（不得改）**
> - **门客 = `Retainer`**（参战）；**族人 = `Clansman`**（不参战）。
> - **HP 上限直接取 `Retainer` 表已有的 `Hp` 字段**（表结构**不改**）；局内 HP 是**纯运行时值**，**不写存档**，撤离/结算后**回满**。
> - **敌人"谁近打谁"**（不强制优先玩家）。
> - 门客 HP 归零 → **重伤/倒地**（不可操作、不可被攻击、不跟随）；局外落 `wounded = true` + **30 秒**倒计时（现有字段与 `RetainerService.Wound` 规则）。
> - **失败判定 = 受控角色倒下 且 全部门客倒下**；**门客全倒但玩家还活着 → 不失败**。
> - **扎营补员 = 让倒地门客以 50% 上限 HP 复活**并可继续参战（不再是占位日志）。
> - **结算**：通关 → 倒地门客进入"恢复中"（`wounded` + 倒计时）；失败 → **全部门客**重伤。
>
> **当前实现核对（2026-10-22，源码静态核查）**
> - `AllyController` 已有 `Hp/MaxHp/IsDowned`、`TakeDamage` 与 `Revive`；HP来自门客模板与既有效果，不再是无HP占位。
> - `EnemyPlaceholder` 已能向存活门客造成伤害；受控角色倒下而门客仍存活时进入观战，全部倒下才判负。
> - `CampService.TryRefill` 已扣2药并将倒地门客按 `ceil(MaxHp×0.5)` 真实复活；仍需安全房间、未用扎营、家族树303。
> - `RunEncounter` 已有结算伤病与失败判定；`RetainerService.Wound` 仍是30秒运行中倒计时。修甲仍占位，未新增护甲系统。
> - 本段只订正旧实现状态；本轮地形对门客受伤与真实操作验收在 `21_W5收尾与数值评审.md` 补录。

## 1. 系统概述

| 项目 | 内容 |
| --- | --- |
| 系统名 | 门客生命与阵亡（Retainer HP / Downed / Revive） |
| 所属模块 | 概念案 §6 **M11 重伤与出战资格** 的**局内半边** ＋ **M8 局内战斗**的门客承伤 ＋ **M10 扎营**的补员对象 |
| 优先级 | MVP（计划的 W3.3） |
| 一句话说明 | 门客在局内有自己的血（上限取 `Retainer.Hp`）；被敌人打到 0 → **倒地**（不能动、不能被打、不再跟随）；本局结束时倒地者记为**重伤**（30 秒恢复）；扎营可让倒地者**半血复活**；**玩家与全部门客都倒下**才判本局失败 |
| 上游依赖 | `Retainer` 表（`Hp`）、`AllyController`（AI）、`EnemyPlaceholder`（伤害来源）、`CampService`（补员）、`RetainerService`（重伤）、`RunEncounter`（失败判定） |
| 下游影响 | 失败判定口径（`12_结算与进度.md`）、扎营补员（`11_扎营与修整.md`）、派遣（不能派重伤门客）、失败结算文案 |
| 本系统涉及的配置表 | **无新表、无新列**（只用 `Retainer.Hp`） |

### 1.1 设计目标

| # | 目标 | 如何验证 |
| --- | --- | --- |
| G1 | **门客会挨打也会倒** | 敌人接触门客 → 门客 HP 下降；归零 → 变「倒地」 |
| G2 | **倒地不等于死** | 无任何"死亡"状态；倒地者本局结束记为重伤，30 秒后恢复 |
| G3 | **失败判定名副其实** | 玩家倒下但还有门客站着 → **不失败**；两者都倒下 → 失败 |
| G4 | **补员真能救人** | 扎营「补充减员」后倒地门客以 **50% HP** 站起来并继续跟随/攻击 |
| G5 | **表驱动** | 门客血量只由 `Retainer.Hp` 决定；改表 → 重导 → 血量变化，代码 0 改动 |
| G6 | **不污染存档** | 局内 HP **不落盘**；撤离/通关/失败后回满（只落"是否重伤"） |

### 1.2 明确不做的（Non-goals）

| # | 不做的事 | 原因 |
| --- | --- | --- |
| N1 | 死亡/永久损失 | 概念案硬约束：**没有死亡机制，只有重伤** |
| N2 | 门客升级/换装影响 HP | 成长归家族树（`EffectType=4` 属性加成）；本期 HP 上限 = 表中 `Hp` + 属性类效果（若有） |
| N3 | 跨局带伤 | 局内 HP 不落盘，回局外回满（§6.3） |
| N4 | 门客自我治疗/自动回血 | 只有扎营「完全治疗 / 补充减员」 |
| N5 | 敌人 AI 精细化（仇恨、集火） | 只做"谁近打谁" |

## 2. 术语表

| 术语 | 含义 | 备注 |
| --- | --- | --- |
| 门客 HP / `MaxHp` | 生命上限 = `Retainer.Hp`（+ 属性类 `Effect` 加成） | 表驱动 |
| 当前 HP / `Hp` | **局内运行时**血量（`0 ~ MaxHp`） | **不落盘** |
| 受伤 | 被敌人接触伤害扣 HP | 5 点 / 0.8s（现有常量） |
| 倒地 / `Downed` | 局内 HP = 0 的状态：**不可操作、不可被攻击、不跟随** | 不是死亡 |
| 重伤 / `Wounded` | **局外**状态：`wounded=true` + `woundedRemainSeconds`（30s） | `RetainerService.Wound` |
| 恢复中 | 重伤倒计时进行中（局外面板显示"重伤 Ns"） | `RetainerService.Tick` |
| 补员 / Refill | 扎营让倒地门客**半血复活** | 需家族树 `303` |
| 全队倒下 | `受控角色倒下 && 全部门客 Downed` | **失败条件** |
| 队长 / 受控角色 | 玩家直接操作的那一个 | 见 §13 Q1（倒下后控制权是否转移） |

## 3. 规则详述

### 3.1 门客 HP 的来源与生命周期

| # | 规则 |
| --- | --- |
| H1 | `MaxHp = Retainer.Hp + Σ(EffectType=4, Target=1 生命) × 1`（属性类效果，与局外展示同一套聚合） |
| H2 | 出发时：每个门客 `Hp = MaxHp`（满血入场） |
| H3 | 局内 `Hp` 只减不增，除：**扎营完全治疗**（回满）/ **补充减员**（倒地者回到 50%） |
| H4 | **局内 HP 不落盘**；撤离 / 通关 / 失败结算后 → 局外视为**满血** |
| H5 | `RetainerSave.hp`（存档字段）**本波仍不写**（恒等于表值），保留给"将来跨局带伤"（§13 Q2） |

### 3.2 受伤规则（敌人 → 门客）

| # | 规则 |
| --- | --- |
| I1 | 敌人接触伤害 = **5**，间隔 **0.8s**（沿用 `EnemyPlaceholder.contactDamage/contactDamageInterval`，**不改数值**） |
| I2 | **目标选择：谁近打谁** —— 敌人接触命中时，在"受控角色 + 门客"里选**距离最近**者；同距时**受控角色优先**（可预期） |
| I3 | 门客受击后有 **0.5s 无敌帧**（与 `PlayerHealth.invulnSeconds` 同口径），避免同帧多次扣血 |
| I4 | 门客**不互相挡伤害**；不做仇恨系统 |
| I5 | 倒地门客**不再被选中**为目标（I2 的候选集里剔除 `Downed`） |

### 3.3 倒地（局内）

| # | 规则 |
| --- | --- |
| D1 | `Hp ≤ 0` → `Downed = true`，`Hp = 0`；**不播放死亡**，播"倒地"表现（占位：本体半透明 + 头顶「倒地」标签） |
| D2 | 倒地后：**不可操作**（AI 停止）、**不再被攻击**（从敌人目标候选剔除）、**不跟随**（停在原地） |
| D3 | 倒地门客**不占"受控"**、不影响其它门客行动 |
| D4 | 倒地**不立即写存档**（见 D5） |
| D5 | **回到局外时统一结算**：对每个 `Downed` 门客调用 `RetainerService.Wound(id, 30)` → `wounded=true`、`woundedRemainSeconds=30`；未倒地者不改 |
| D6 | 倒地者在本局**不能自己爬起来**；只有扎营补员（§3.5）能让其恢复 |

### 3.4 失败判定（**核心变更**）

| # | 规则 |
| --- | --- |
| F1 | **失败 = 受控角色倒下 且 全部门客 `Downed`**（两个条件同时满足） |
| F2 | **门客全倒但受控角色还活着 → 不失败**（玩家还能打；这是"以少打多"的高光时刻） |
| F3 | **受控角色倒下但还有门客站着 → 不失败**（见 §13 Q1：控制权应转移到还活着的门客） |
| F4 | 失败时调 `RunEncounter.TriggerDefeat()`（现有入口）→ 进入**失败结算**（`12_结算与进度.md`） |
| F5 | 失败判定**只在状态变化时检查一次**（有人倒下 / 有人复活），不每帧轮询 |
| F6 | **补员后要重算**：若原本已满足失败条件但玩家用扎营补员救了人 → 仍按"已失败"处理（一旦 `TriggerDefeat` 触发不可回滚） |

> ⚠️ **F3 是本次必须先定的一条**：W3 只有 **1 个受控角色**，若"受控倒下"就不再判失败，玩家会**无法操作**（僵局）。本文建议 **控制权转移**（§13 Q1 方案 B），并以"无门客可接 → 立即失败"兜底。

### 3.5 扎营「补充减员」（真实生效）

| # | 规则 |
| --- | --- |
| R1 | 前置：`CampService.IsInSafeRoom` 且本局未扎营 且 **`CampRefillUnlocked`（家族树 303）** |
| R2 | 效果：**所有 `Downed` 门客**以 `Hp = ceil(MaxHp × 50%)` **复活**；`Downed=false`；恢复跟随/可被攻击 |
| R3 | 消耗：**药品 ×2**（沿用现有常量） |
| R4 | 若**无人倒地** → `CanRefill = false`，原因「无需补充」 |
| R5 | 未解锁 303 → 按钮灰 + 「需点亮家族树·门客培养·Ⅲ（解锁补充减员）」 |
| R6 | 复活后**不再触发**"全队倒下"判定（因为已有人站起）；已 `TriggerDefeat` 的局不因补员而取消失败 |
| R7 | 「完全治疗」= 让**还活着的**门客/受控角色 `Hp` 回满（不含倒地者 —— 倒地者只能用补员） |

### 3.6 结算时的伤病

| # | 场景 | 处理 |
| --- | --- | --- |
| S1 | **通关** | 每个 `Downed` 门客 → `Wound(30)`（局外显示"重伤 30s"，按现有 `Tick` 恢复）；活着的不变 |
| S2 | **失败** | **全部门客** → `Wound(30)`（含未倒地者，体现"全军覆没"）；受控角色本身不落盘（玩家不是 `Retainer`） |
| S3 | **主动撤离** | 与 S1 同：倒地者 → `Wound(30)`；活着的不变 |
| S4 | 任何结算后 | 局内 HP 丢弃（下次入场满血） |

> S2 的"全部门客重伤"是为了让失败有**可感知代价**（否则失败只损失掉落）；同时不会让玩家"永久损失"（30 秒后恢复）。

### 3.7 规则优先级

`D1 倒地判定` > `F1 失败判定` > `S1~S3 结算写重伤` > `R2 补员复活`（补员只在本局内、结算前有效）。

## 4. 数值与公式

| # | 数值 / 公式 | 值 | 来源 |
| --- | --- | --- | --- |
| F1 | `MaxHp` | `Retainer.Hp` + 属性效果 | `Retainer` 表（示例 100~200） |
| F2 | 敌人接触伤害 | **5** / 0.8s | `EnemyPlaceholder`（现有，不改） |
| F3 | 门客无敌帧 | **0.5s** | 与 `PlayerHealth` 同口径 |
| F4 | 重伤时长 | **30s** | `RetainerService.DefaultWoundSeconds` |
| F5 | 补员复活血量 | `ceil(MaxHp × 50%)` | 本文（§13 Q3 待确认比例） |
| F6 | 补员消耗 | **药品 ×2** | `CampService`（现有） |
| F7 | 完全治疗消耗 | **药品 ×1** | `CampService`（现有） |

### 4.1 取整与边界

| 项目 | 规定 |
| --- | --- |
| `Hp` | 整数；`0 ~ MaxHp`；扣到 ≤0 归 0 |
| 复活血量 | **向上取整**（`ceil(MaxHp × 0.5)`），避免 1 血复活 |
| `MaxHp` | 若表值 ≤0（配置错误）→ 视为 1 并 **Error 日志** |
| 重伤秒 | 整数；显示向下取整 |

## 5. 状态与流程

### 5.1 门客局内状态机

| 状态 | 进入条件 | 可做 | 退出 |
| --- | --- | --- | --- |
| **正常** | `Hp > 0` | 跟随 / 攻击 / 挨打 | `Hp ≤ 0` → 倒地 |
| **倒地** | `Hp = 0` | 无（不可操作/不可被打/不跟随） | 扎营补员 → 正常（50% HP） |
| （回局外）**重伤** | 结算时有倒地记录 | 不可出战 | `woundedRemainSeconds` 归 0 → 可用 |

### 5.2 流程

```
敌人接触 ──> 选最近目标（玩家或门客）
   ├─ 命中玩家 → PlayerHealth.ApplyContactDamage(5)
   └─ 命中门客 → 扣 5（0.5s 无敌）→ Hp<=0 ? 倒地 : 继续
倒地后：检查失败判定
   若 受控倒下 && 全部门客 Downed → RunEncounter.TriggerDefeat() → 失败结算
扎营补员：Downed 全部复活到 50% HP
结算：Downed 者 → RetainerService.Wound(30)；失败时全部门客 Wound(30)
```

### 5.3 时序

| 顺序 | 发起方 | 接收方 | 动作 |
| --- | --- | --- | --- |
| 1 | `EnemyPlaceholder`（接触） | 最近目标 | 5 点接触伤害（0.8s 间隔） |
| 2 | 门客受击 | `AllyController`/新 `AllyHealth` | 扣血 + 无敌帧 |
| 3 | 门客 HP=0 | 生命服务 | 置 `Downed`；从敌人目标集剔除 |
| 4 | 生命服务 | `RunEncounter` | 检查 F1 → 可能 `TriggerDefeat()` |
| 5 | `CampService.TryRefill` | 生命服务 | 倒地者 50% HP 复活 |
| 6 | 结算 | `RetainerService` | `Wound(30)` |

## 6. 数据结构

| 数据 | 位置 | 类型 | 落盘 |
| --- | --- | --- | --- |
| 门客血量上限 | `Retainer.Hp` + 属性效果 | `uint` → `int` | 表（配置） |
| 门客当前 HP | 运行时（`AllyController` 或独立 `AllyHealth`） | `int` | **否** |
| 是否倒地 | 运行时 | `bool` | **否** |
| 是否重伤 | `RetainerSave.wounded` | `bool` | ✅ |
| 重伤剩余秒 | `RetainerSave.woundedRemainSeconds` | `uint` | ✅ |
| 受控角色 HP | `PlayerHealth.Hp` | `int` | 否 |

### 6.3 为什么 `RetainerSave.hp` 仍然不用

| # | 理由 |
| --- | --- |
| 1 | 局内 HP **不落盘**（撤离即回满）→ 落盘字段没有"当前值"的来源 |
| 2 | 若写入，会出现"中途退出再进，血仍是半血"的**跨局带伤**需求，而 MVP 明确不做（N3） |
| 3 | 保留字段，将来做"跨局伤势/医疗"时再启用（**加字段 = 零迁移**，改语义需评估） |

## 9. 边界与异常

| # | 场景 | 期望行为 |
| --- | --- | --- |
| E1 | `Retainer.Hp = 0`（配置错误） | 视为 1 + Error 日志；不出现"入场即倒地" |
| E2 | 门客在出生点外/掉出地图 | 沿用现有 `AllyController` 的传送逻辑；**不因掉落判倒地** |
| E3 | 门客与玩家同时被同一敌人接触 | 按"最近者"取一个（I2），不同时扣两人 |
