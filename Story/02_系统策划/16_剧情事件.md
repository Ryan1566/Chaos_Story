# 剧情事件系统设计方案（W5.1 · M4 剧情事件）

> 状态：评审中
> Owner：策划
> 最后更新：2026-10-21
> 关联：`Story/01_企划/01_游戏概念案.md`（§6 M4 剧情事件）、`Story/02_系统策划/04_功能开发计划与优先级.md`（W5）、`Story/02_系统策划/05_门客系统.md`（信心/招募）、`Story/02_系统策划/06_资源与库存.md`（资源/物品）、`Story/02_系统策划/08_家族树系统.md`（技能点）、`Story/02_系统策划/12_结算与进度.md`（回局外时机）、`Story/03_配置表设计/15_Event_字段规格.md`、`Story/03_配置表设计/16_EventOption_字段规格.md`

> **用户已裁决（原型期只做这 3 种触发条件，**不得扩展**）**
> | 编号 | 条件 | 字段 | 判定 |
> | --- | --- | --- | --- |
> | ① | **进入局内次数** | `SavePayload.runs` | `runs >= TriggerValue` |
> | ② | **通关过的最高深度** | `SavePayload.maxClearedDepth` | `maxClearedDepth >= TriggerValue` |
> | ③ | **已点亮局外技能点** | `SavePayload.familyTreeNodes` | `familyTreeNodes.Contains(TriggerValue)` |
>
> 其他条件（时代、资源、心情、随机…）**后续再扩，本轮不做**。

> **实现现状（2026-10-21 实测）**
> - `SavePayload` 已有 `runs` / `clears` / `maxClearedDepth` / `familyTreeNodes`（4 条件中的 3 个已就绪）；**没有 `firedEvents`**（本波新增，零迁移）。
> - `MetaProgressService`（进度与 `DumpState`）、`InventoryService`（`AddItem` / `AddResource`）、`RetainerService`（`RecruitRandom` / `ChangeConfidence`）、`FamilyTreeService`（`IsUnlocked`）**均已落地** —— 事件奖励只调用它们，不另造一套。
> - `PanelType` 现有 22 项（含门客/库存/村庄/家族树/派遣/结算/扎营/时代进度），**没有事件面板**。
> - GM 分类实测：`界面 / 系统（语言切换·日志与性能·门客·村庄·家族树·派遣）/ 局内生成（生成地图·扎营）/ 道具（发放道具·背包仓库）/ 原型（进度·存档·地图）`。
> - ⚠️ **面板文案现状**：现有面板是**纯中文、不挂 `LocalizedText`**（挂 key 而表里没有会**回填成 key 本身**）→ 影响 §7 的列命名决策。

## 1. 系统概述

| 项目 | 内容 |
| --- | --- |
| 系统名 | 剧情事件（Story Event / M4） |
| 所属模块 | 概念案 §6 **M4 剧情事件（局外）** |
| 优先级 | MVP（计划的 W5.1） |
| 一句话说明 | 局外按"3 个进度条件"检查剧情事件；满足就弹一个**居中事件窗**（标题 + 正文 + 1~3 个选项）；玩家选一个 → 结算奖励（资源/物品/门客/信心）→ 事件结束（一次性事件**只触发一次**） |
| 上游依赖 | `SavePayload`（`runs`/`maxClearedDepth`/`familyTreeNodes` + 新增 `firedEvents`）、`InventoryService`、`RetainerService`、`FamilyTreeService` |
| 下游影响 | 局外资源/库存/门客信心与招募、时代推进所需的"局外里程碑"体验、后续剧情内容量 |
| 本系统涉及的配置表 | **`Event`（事件表）**、**`EventOption`（选项表）** |

### 1.1 设计目标

| # | 目标 | 如何验证 |
| --- | --- | --- |
| G1 | **3 种触发条件可判** | 造 `runs=3` / `maxClearedDepth=2` / 点亮某节点 → 对应事件弹出；条件不满足不弹 |
| G2 | **一次性事件只弹一次** | 处置后写 `firedEvents`；重进/再回局外**不再弹** |
| G3 | **一次只弹一个** | 同时满足 5 个事件 → 按 `Priority` 排，逐个弹；关掉一个才弹下一个 |
| G4 | **选项真的给东西** | 选「获得物资 ×50」→ 资源栏当场 +50；选「招募门客」→ 门客列表 +1 |
| G5 | **表驱动** | 改 `Event`/`EventOption` → 重跑导出 → 事件内容与奖励随之变化，代码 0 改动 |
| G6 | **不卡流程** | 事件弹窗**不阻塞**局外面板操作（可关闭、可稍后再弹） |

### 1.2 明确不做的（Non-goals）

| # | 不做的事 | 原因 |
| --- | --- | --- |
| N1 | 其他触发条件（时代/资源/随机/时间） | **用户裁决：原型期只做 3 种** |
| N2 | 事件分支树/多级连续对话 | MVP 只有"一个事件 + 1~3 选项"，不做对话图 |
| N3 | **局内**剧情事件 | 概念案 M4 是局外事件；局内事件归 M9 场景事件（后续） |
| N4 | 事件日志/历史回看 | MVP 不做（只有 `firedEvents` 记录已触发 ID） |
| N5 | 选项的**永久 Effect 授予** | `Effect` 是**常驻聚合**（家族树/道具），选项是**瞬发**；本期不混用（§13 Q2） |
| N6 | 语音/立绘/演出 | 占位：纯文本 |

## 2. 术语表

| 术语 | 含义 | 备注 |
| --- | --- | --- |
| 事件 / `Event` | 一次剧情弹窗：标题 + 正文 + 1~3 选项 | `Event.Index` |
| 选项 / `EventOption` | 事件里的一个按钮，带一组奖励 | `EventOption.Index` |
| 触发条件 / `TriggerType` | `1`=runs、`2`=depth、`3`=node | **只用这 3 个** |
| 触发值 / `TriggerValue` | 条件的阈值或节点 ID | 语义随 `TriggerType` |
| 一次性 / `Repeatable=false` | 触发处置后写入 `firedEvents`，**永不再弹** | 默认 |
| 可重复 / `Repeatable=true` | 可再次触发（**每次回局外最多一次**） | 不写 `firedEvents` |
| `firedEvents` | 已处置的一次性事件 ID 列表 | **新增存档字段** |
| 优先级 / `Priority` | 同时满足多个时的弹出顺序 | 值大先弹；同值按 `Index` 升序 |
| 排队 / Queue | 待弹事件的有序列表 | 一次只弹一个 |

## 3. 规则详述

### 3.1 事件结构

| 组成 | 来源 | 说明 |
| --- | --- | --- |
| **标题** | `Event.TitleText` | 一句话（中文**原文**，见 §7 命名说明） |
| **正文** | `Event.BodyText` | 一段文本；**禁止英文逗号 / 英文双引号 / 换行**（会破坏整表 Json） |
| **选项** | `EventOption`（`EventId = Event.Index`，`OptionIndex` 1~3） | 1~3 个；**至少 1 个** |
| 选项奖励 | `EventOption` 的奖励列 | 资源 / 物品 / 门客 / 信心（§3.4） |

### 3.2 触发条件判定（**逐字口径**）

```
条件满足(Event e):
  switch (e.TriggerType)
    case 1: return SavePayload.runs            >= e.TriggerValue
    case 2: return SavePayload.maxClearedDepth >= e.TriggerValue
    case 3: return SavePayload.familyTreeNodes.Contains(e.TriggerValue)
    default: Warn + 视为不满足         // TriggerType 不在 1~3 → 跳过
```

| # | 备注 |
| --- | --- |
| T1 | `TriggerValue` 对 `type=1/2` 是**阈值**（含等于）；对 `type=3` 是**家族树节点 ID**（必须已点亮） |
| T2 | `type=3` 的 `TriggerValue` 建议用真实节点 ID（`101~503`，见 `11_FamilyTree_字段规格.md`）；填 `0` 视为配置错误 → Warn + 不满足 |
| T3 | 条件**只判"是否达到"**，不判"是否刚达到"（不需要"跨越事件"） |

### 3.3 触发检查时机（**关键**）

| # | 时机 | 是否检查 | 说明 |
| --- | --- | --- | --- |
| C1 | **每次回到局外**（撤离 / 通关结算后 / 失败结算后） | ✅ **唯一正式时机** | 由结算流程末尾调用一次 |
| C2 | 打开局外主界面 / 事件面板时 | ✅（兜底） | 若 C1 已弹过则不会重复 |
| C3 | 局内 | ❌ | 局内不弹事件 |
| C4 | 每帧 / 定时轮询 | ❌ | 禁止（性能与误触） |

> **一次回局外只检查一次**，避免"同一条件反复弹同一个可重复事件"。

### 3.4 选项奖励（4 类 + 1 预留）

| # | 奖励类型 | 列 | 调用（已落地服务） | 本期 |
| --- | --- | --- | --- | --- |
| A1 | **给资源** | `GiveResourceType`（`0`=无 / `1`物资 / `2`材料 / `3`钱财 / `4`图纸）+ `GiveResourceAmount` | `InventoryService.AddResource(kind, amount)` | ✅ |
| A2 | **给物品** | `GiveItemId`（`0`=无，否则 `Item.Index`）+ `GiveItemCount` | `InventoryService.AddItem(itemId, count, out reason)` | ✅ |
| A3 | **给门客** | `GiveRetainerId`（`0`=无，否则 `Retainer.Index` = `protoId`） | 按模板实例化一个门客（等价 `RetainerService` 的招募路径） | ✅ |
| A4 | **加信心** | `ConfidenceDelta`（`int`，可负） | 对**全部门客** `ChangeConfidence(id, delta)`（clamp 0~100） | ✅ |
| A5 | **调 Effect / 解锁开关** | `EffectId`（`0`=无） | **本期不实现**（预留列）：`Effect` 是常驻聚合，选项是瞬发，需要新的"已授予效果"存储（§13 Q2） | ⛔ 预留 |

> **奖励叠加**：一个选项**可以同时**给资源 + 物品 + 门客 + 信心（各列非 0 即生效）；执行顺序按 A1→A2→A3→A4。
> **失败不回滚**：若 `AddItem` 因格位满失败 → 提示"物品未能放入（格位已满）"，**其它奖励照给**，不整体回滚（避免"选了却什么都没拿到"的困惑）。

### 3.5 一次性 vs 可重复

| # | 规则 |
| --- | --- |
| R1 | `Repeatable = false`（**默认**）：弹出并**完成处置**（选了选项或点关闭）后 → 把 `Event.Index` 写入 `SavePayload.firedEvents` |
| R2 | 写入时机 = **处置完成之后**（不是弹出瞬间）；中途强退 → 下次还会弹（可接受，避免"弹了没看就永久消失"） |
| R3 | `Repeatable = true`：**不写** `firedEvents`；但**每次回局外会话最多弹 1 次**（用不落盘的会话集合去重） |
| R4 | 已在 `firedEvents` 里的 ID → **永不参与排队**（哪怕条件再次满足） |

### 3.6 排队与弹出顺序

| # | 规则 |
| --- | --- |
| Q1 | 每次检查收集**所有**满足条件且未被过滤的事件 → 组成队列 |
| Q2 | 排序：**`Priority` 降序**；`Priority` 相同 → **`Index` 升序** |
| Q3 | **一次只弹一个**；关掉/选完后弹下一个（同一检查批次内连续弹） |
| Q4 | 弹窗期间**不阻塞**其它面板（可关闭；关闭也视为"已处置"，写 `firedEvents`） |
| Q5 | 队列上限（**策划建议**）：单次最多弹 **5** 个，其余留到下次检查（避免回局外被 20 个事件淹没） |

### 3.7 规则优先级

`R4 已触发过滤` > `Q2 排序` > `Q3 逐个弹` > `R1 写 firedEvents`。

## 5. 状态与流程

### 5.1 事件生命周期

| 状态 | 进入 | 可做 | 退出 |
| --- | --- | --- | --- |
| **未触发** | 条件不满足 / 已在 `firedEvents` | — | 条件满足 → 入队 |
| **排队中** | 条件满足且在队列 | 等待前一个关闭 | 轮到 → 弹出 |
| **弹出中** | 轮到并显示 | 点选项 / 关闭 | 选完 → 结算奖励 → 结束；关闭 → 直接结束 |
| **已完成（一次性）** | 处置完成 | — | 写入 `firedEvents`，永不再弹 |
| **可再次触发（Repeatable）** | 处置完成 | — | 下次回局外再检查 |

### 5.2 流程图

```
回到局外（撤离/结算后） ──> 检查一次
   ├─ 遍历 Event（Enable=true）
   ├─ 过滤：条件满足 && !firedEvents.Contains(Index) && (Repeatable ? 本会话未弹过 : true)
   ├─ 排序（Priority desc, Index asc）→ 队列（最多 5）
   └─ 逐个弹：StoryEventPanel 显示
         ├─ 玩家点选项 k → 执行奖励 A1→A4 → 提示结果 → 关闭
         └─ 玩家点关闭 → 无奖励 → 关闭
      关闭后：若一次性 → firedEvents.Add(Index)；存档
```

### 5.3 时序

| 顺序 | 发起方 | 接收方 | 动作 |
| --- | --- | --- | --- |
| 1 | 结算/撤离流程 | 事件服务 | `CheckAndQueue()` |
| 2 | 事件服务 | `SavePayload` | 读 `runs`/`maxClearedDepth`/`familyTreeNodes`/`firedEvents` |
| 3 | 事件服务 | Event/EventOption 表 | 取候选与选项 |
| 4 | 事件面板 | 玩家 | 显示标题/正文/选项 |
| 5 | 玩家 | 事件面板 | 选择选项 / 关闭 |
| 6 | 事件面板 | `InventoryService`/`RetainerService` | 发放奖励 |
| 7 | 事件面板 | 事件服务 + 存档 | 写 `firedEvents`、保存 |

## 6. 数据结构

| 数据 | 位置 | 类型 | 落盘 |
| --- | --- | --- | --- |
| 已处置的一次性事件 ID | **`SavePayload.firedEvents`（新增）** | `List<uint>` | ✅ |
| 本次回局外已弹过的可重复事件 | 运行时集合 | `HashSet<uint>` | ❌ |
| 待弹队列 | 运行时 | `List<EventConfig>` | ❌ |
| 触发数据源 | `SavePayload.runs` / `maxClearedDepth` / `familyTreeNodes` | `uint` / `List<uint>` | ✅（均已存在） |

> **零迁移**：`firedEvents` 是**新增 public 字段**（`List<uint>`，初始化 `new List<uint>()`）；老存档读进来是空列表 → 视为"还没触发过任何事件"，**不报错**（`SaveSlotData.cs` 顶部"追加字段=零迁移"机制）。
> ⚠️ `JsonUtility` 不支持 `Dictionary`/`HashSet` → **只落 `List<uint>`**，运行时去重用 `HashSet`（不落盘）。

## 9. 边界与异常

| # | 场景 | 期望行为 |
| --- | --- | --- |
| E1 | 条件满足但无任何选项行 | 事件仍弹出，只有一个「关闭」按钮（记 Warn：选项配置缺失） |
| E2 | `EventOption` 的 `EventId` 指向不存在的事件 | 忽略该选项行 + Warn |
| E3 | `GiveItemId` 指向不存在的物品 | 跳过物品奖励 + Warn；其它奖励照给 |
| E4 | `GiveRetainerId` 指向不存在的模板 | 跳过门客奖励 + Warn |
| E5 | `GiveResourceType` 不在 `1~4` | 跳过资源奖励 + Warn |
| E6 | `TriggerType` 不在 `1~3` | 视为不满足 + Warn |
| E7 | `firedEvents` 里有表中已删除的事件 ID | 忽略（不影响其它事件） |
| E8 | 存档失败（写 `firedEvents` 失败） | 提示保存失败；该事件保持"未处置"（下次还会弹） |
| E9 | 同一帧多次检查 | 幂等：队列已存在时不重复入队 |
| E10 | 选项奖励同时触发格位满 | 该奖励失败提示，不整体回滚（§3.4） |
| E11 | 老存档（无 `firedEvents`） | 空列表；**所有一次性事件会重新弹一次**（可接受，原型期） |

## 12. 验收标准（可测试）

| # | 验收项 | 判定方式 |
| --- | --- | --- |
| A1 | **3 种触发都能判** | `runs` / `maxClearedDepth` / `familyTreeNodes` 三种条件各自能触发对应事件 |
| A2 | 不满足不弹 | 阈值未达时不弹 |
| A3 | **一次性** | 处置后再检查不弹；`firedEvents` 含该 ID |
| A4 | **可重复** | `Repeatable=true` 事件每次回局外最多弹一次 |
| A5 | **排队** | 多事件同满足 → 按 `Priority` 降序、`Index` 升序；一次只弹一个 |
| A6 | 队列上限 | 单次最多 5 个（超出留到下次） |
| A7 | **奖励生效** | 资源/物品/门客/信心各自可验；多项叠加生效 |
| A8 | 奖励失败隔离 | 物品格位满 → 提示该项失败，其它奖励照给 |
| A9 | 存档 | `firedEvents` 落盘；重进后一次性事件不再弹 |
| A10 | 老存档 | 无 `firedEvents` 的存档可正常进入（视空列表） |
| A11 | 表驱动 | 改表 → 重导 → 事件内容/条件/奖励变化，代码 0 改动 |
| A12 | 文案 | 纯中文；**无英文逗号/引号/换行**（导出失败即验证） |
