# 扎营与修整系统设计方案（W3.2 · M10）

> 状态：评审中
> Owner：策划
> 最后更新：2026-10-22
> 关联：`Story/01_企划/01_游戏概念案.md`（§6 M10 扎营）、`Story/02_系统策划/05_门客系统.md`、`08_家族树系统.md`（节点 303 解锁补员）、`10_局内掉落与带出.md`（消耗局内道具）、`12_结算与进度.md`、`Story/03_配置表设计/10_Item_字段规格.md`

> **已定口径（不得改）**
> - **门客 = `Retainer`**（参战）；族人 = `Clansman`（不参战，本波不涉及）。
> - **扎营「补充减员」必须家族树节点 `303` 已点亮**（概念案 M10：**初期无法补充减员，需家族树加点解锁**）；未点亮时按钮**灰显 + 说明**。
> - **U2 仅运行中计时**（离线不走表）。
> - 受控角色用 `PlayerHealth`；门客 `AllyController` 已有Hp/MaxHp/IsDowned，W3.3后补员是真实复活，详见 `Story/02_系统策划/15_门客生命与阵亡.md`。
>
> **实现现状（2026-10-18 实测）**：`MetaProgressService.CampRefillUnlocked`（**已存在**，即"节点 303 是否点亮"的现成入口）、`FamilyTreeService.IsUnlocked(303)`、`PlayerHealth`（`Hp`/`maxHp`/`ApplyContactDamage`，**无治疗接口**）、`RunEncounter`（3 场景链）。**局内目前没有扎营**。

## 1. 系统概述

| 项目 | 内容 |
| --- | --- |
| 系统名 | 扎营与修整（Camp / Rest） |
| 所属模块 | 概念案 §6 **M10 扎营** |
| 优先级 | MVP（计划的 W3.2） |
| 一句话说明 | 局内在安全处扎营，花少量代价做三件事：**修甲**（保命）、**完全治疗**（回满 hp）、**补充减员**（复活阵亡门客，**需家族树 303**）；**每局限 1 次** |
| 上游依赖 | 家族树（节点 303）、局内掉落（消耗道具）、`PlayerHealth`、`RunEncounter`（是否安全房间） |
| 下游影响 | 结算（扎营不影响通关判定）、带出（消耗掉的道具不能带出） |
| 本系统涉及的配置表 | **不需要新表**（次数/耗时/消耗为常量；治疗量来自 `PlayerHealth`） |

### 1.1 设计目标

| # | 目标 | 如何验证 |
| --- | --- | --- |
| G1 | **扎营是"有限资源"** | 每局只能用 1 次；用掉后按钮变灰「本局已扎营」 |
| G2 | **补充减员受家族树闸门** | 未点亮 `303` → 按钮灰 + 说明「需点亮家族树·门客培养·Ⅲ」；点亮后可用 |
| G3 | **扎营有代价** | 消耗局内道具（药品/材料）；不够则不可用 |
| G4 | **不能在战斗中滥用** | 只有**安全房间**（当前房间无敌）才可扎营 |
| G5 | **数据可解释** | 扎营后 `hp`、门客状态、消耗、剩余次数都能在 GM 面板打印出来 |

### 1.2 明确不做的（Non-goals）

| # | 不做的事 | 原因 |
| --- | --- | --- |
| N1 | 扎营场景/帐篷美术 | 占位：原地弹面板 + 短暂黑屏/提示 |
| N2 | 扎营期间敌人刷新/夜袭 | MVP 不做；扎营**不刷怪**（§3.5） |
| N3 | 护甲系统（修甲的真实数值） | 当前**没有护甲系统** → 修甲**先占位**（§13 Q2） |
| N4 | 门客属性/技能成长 | 归家族树与后续系统 |
| N5 | 离线恢复 | U2：只算运行中 |

## 2. 术语表

| 术语 | 含义 | 备注 |
| --- | --- | --- |
| 扎营 / Camp | 在安全房间进行一次修整 | 每局 1 次（建议） |
| 安全房间 | 当前房间内**没有活着的敌人** | 判定见 §3.2 |
| 修甲 | 恢复护甲/装备耐久 | **占位**（无护甲系统） |
| 完全治疗 | 门客（含受控角色）hp 回满 | `PlayerHealth.maxHp` |
| 补充减员 | 让阵亡门客重新可出战 | **需 `303`**（`CampRefillUnlocked`） |
| 减员 / Downed | 门客离场/倒下（不可行动） | 当前已有HP/倒地；补员恢复50%上限HP |

## 3. 规则详述

### 3.1 三个动作

| # | 动作 | 效果 | 消耗（**建议占位值**） | 前置 |
| --- | --- | --- | --- | --- |
| C1 | **修甲** | 护甲/耐久恢复（**占位**：本期只做提示"护甲已修复"，无实际数值） | 药品 ×1 | — |
| C2 | **完全治疗** | 受控角色 hp 回满；门客 hp 回满（若 W3.2 给门客加 HP） | 药品 ×1 | — |
| C3 | **补充减员** | 阵亡/离场门客恢复可行动 | 药品 ×2 | **家族树 `303` 已点亮**（`CampRefillUnlocked`） |

> 三个动作可**分别选择**（一次扎营可做其中 1~3 个，按各自消耗扣）；扎营**次数**按"本次扎营"计 1 次，不按动作计。

### 3.2 可用条件（必须同时满足）

| # | 条件 | 不满足时 |
| --- | --- | --- |
| R1 | 在**安全房间**（当前房间无活敌） | 提示「战斗中无法扎营」；按钮灰 |
| R2 | **本局尚未扎营**（`campUsed = false`） | 提示「本局已扎营」；按钮灰 |
| R3 | 动作对应的**消耗道具足够** | 该动作按钮灰 + 提示「药品不足」 |
| R4（仅 C3） | **`CampRefillUnlocked == true`** | 按钮灰 + 说明「需点亮家族树·门客培养·Ⅲ（解锁补充减员）」 |

### 3.3 扎营无减员/无伤时的行为

| # | 场景 | 行为 |
| --- | --- | --- |
| P1 | hp 已满 | 「完全治疗」按钮灰 + 提示「无需治疗」 |
| P2 | 无阵亡门客 | 「补充减员」按钮灰 + 提示「无需补充」 |
| P3 | 三个动作都不可用 | 可"扎营"但无收益（**策划建议**：直接禁止并提示「当前无需扎营」，不消耗次数） |

### 3.4 次数与触发

| # | 规则 |
| --- | --- |
| T1 | **每局 1 次**（`campUsed`，落点：局内状态，不落盘） |
| T2 | 触发方式：**快捷键（建议 `C`）+ 任意安全房间原地触发**；原型期同时提供 **GM 触发** |
| T3 | 扎营**不算一次场景**、**不影响通关进度** |
| T4 | 扎营结束后等待 **2 秒**（占位，**仅运行中计时**）再恢复操作，给"已经扎营"的仪式感 |

### 3.5 扎营与敌人/计时

| # | 规则 |
| --- | --- |
| U1 | 扎营**不刷怪**（不模拟夜袭）；已有敌人必须已清空（R1） |
| U2 | 扎营**计时仅运行中**（U2）；离线不推进（本系统无跨局计时） |
| U3 | 扎营**不重置**已清房间（`RunEncounter` 状态不变） |

### 3.6 规则优先级

`R1 安全房间` > `R2 次数` > `R4 家族树闸门` > `R3 消耗` > `P1~P3 无收益提示`。

## 5. 状态与流程

### 5.1 扎营状态机

| 状态 | 条件 | 可做 | 退出 |
| --- | --- | --- | --- |
| **不可扎营** | 战斗中 / 已用次数 / 无收益 | 无 | 条件满足 → 可扎营 |
| **可扎营** | R1+R2 满足且至少一个动作可用 | 选择动作 → 确认 | 确认后 → 已扎营 |
| **已扎营** | 本局已用 | 无（按钮灰） | 局结束重置 |

### 5.2 流程

```
按 C（或 GM）→ 判定 R1/R2（失败则提示并结束）
  → 弹扎营面板：三个动作（可用/灰 + 原因）
  → 玩家选择 1~3 个动作 → 确认
      逐动作：判 R4/R3（不满足则该动作失败并提示，不影响其它动作）
              扣道具 → 生效
  → campUsed = true；2 秒后收起面板
```

### 5.3 时序

| 顺序 | 发起方 | 接收方 | 动作 |
| --- | --- | --- | --- |
| 1 | 输入/GM | 扎营服务 | `TryCamp(out reason)` |
| 2 | 扎营服务 | `RunEncounter` | 查询当前房间是否安全 |
| 3 | 扎营服务 | `MetaProgressService` | 读 `CampRefillUnlocked` |
| 4 | 扎营服务 | 局内库存 | 扣药品 |
| 5 | 扎营服务 | `PlayerHealth` / 门客 | 回满 hp / 补员 |
| 6 | 扎营面板 | — | 刷新状态 |

## 6. 数据结构

| 数据 | 位置 | 类型 | 落盘 |
| --- | --- | --- | --- |
| 本局是否已扎营 | 局内状态（`RunCamp`） | `bool` | **否**（局结束即失效） |
| 扎营消耗 | 局内库存扣减 | — | 否（局内库存本身不落盘） |
| 补员闸门 | `MetaProgressService.CampRefillUnlocked` | `bool` | 由家族树派生 |

> **为什么不落盘**：扎营是**局内一次性的状态**；重进游戏局内状态不存在（与 `09_派遣` E3 一致）。

## 7. 配置表关联

| 表 | 用途 |
| --- | --- |
| `Item` | 消耗的道具（药品，`Category=1`；`IsCampItem=true` 表示"扎营类"） |
| （无新表） | 次数/消耗/延迟先用常量 |

> ⚠️ `Item.IsCampItem` 的语义：现有字段定义为"**只能在扎营时使用**"。本系统的消耗用的是**普通药品**（也允许 camp item）。若将来要"扎营专属道具"，用 `IsCampItem=true` 的物品并在此处指定。

## 11. GM 演示路径（**实测目录：界面 / 系统 / 局内生成 / 道具 / 原型**）

> **GM 需新增**：分类「局内生成」下加版块 **「扎营」**（或并入「掉落与带出」版块）。

| 步骤 | 路径 | 看到什么 |

| 8 | 确认扎营 → 再按 C / 再打开面板 | 提示「本局已扎营」 |
| 9 | GM →「局内生成」→「扎营」→「打印扎营状态」 | 显示 `campUsed=true`、`CampRefillUnlocked=?`、剩余药品 |
