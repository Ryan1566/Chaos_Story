# 市场系统设计方案（W5.3 · M5 市场与运送护送 · **只做兑换最小版**）

> 状态：评审中
> Owner：策划
> 最后更新：2026-10-22
> 关联：`Story/01_企划/01_游戏概念案.md`（§6 M5、§5.3 时代轴）、`Story/02_系统策划/06_资源与库存.md`（4 资源 / 格位 / 叠加）、`Story/02_系统策划/04_功能开发计划与优先级.md`（W5）、`Story/03_配置表设计/10_Item_字段规格.md`

> **结论先行（价格放哪）**：**不新建 `Market` 表**，在现有 **`Item` 表加 2 列**（`BuyPrice` / `SellPrice`，均为 `uint`）—— 理由见 §4。
> **本轮范围**：只有"**资源 ↔ 物品**兑换（买 / 卖）"：一个面板 + 一份价格（就是 `Item` 的两个新列）。**不做**商店限购/刷新/时代调价/运送护送（§1.2）。

> **当前实现核对（2026-10-22，源码与导出 Json 静态核查）**
> - `Item` 已有 **9 行、10 列**（原8列＋`BuyPrice/SellPrice`）；价格均已导出，完整快照见21报告§5。
> - `InventoryService`：`AddItem(itemId,count,out reason)` / `RemoveItem(...)` / `GetResource(ResourceKind)` / `AddResource(kind,amount)` / `SpendResource(kind,amount,out reason)` / `UsedSlots` / `TotalSlots` —— **买卖所需的原子操作全部已存在**。
> - `ResourceKind`：`Money = 3`（对应存档 `resMoney`）；钱财是**资源数字**，不占格位。
> - `PanelType.MarketPanel`、`MarketPanel.cs`、同名prefab与GM入口均存在。历史运行证据见20报告；本轮验收另录21报告。

## 1. 系统概述

| 项目 | 内容 |
| --- | --- |
| 系统名 | 市场（Market）—— **资源 ↔ 物品兑换最小版** |
| 所属模块 | 概念案 §6 **M5 市场与运送护送**（**只取"市场"里的兑换部分**） |
| 优先级 | 后置（计划的 W5.3；概念案把 M5 列为第二阶段，`2/2`） |
| 一句话说明 | 局外一个市场面板：花**钱财**买物品、卖物品换**钱财**；价格写在 `Item` 表里（`BuyPrice`/`SellPrice`） |
| 上游依赖 | `Item` 表（+2 列）、`InventoryService`（资源与库存） |
| 下游影响 | 资源去处（钱财有用途了）、村庄/建造的材料来源之一、后续"运送护送"的前置 |
| 本系统涉及的配置表 | **只改 `Item`（+2 列）**；**不新增表** |

### 1.1 设计目标

| # | 目标 | 如何验证 |
| --- | --- | --- |
| G1 | **买得进** | 有钱 → 买 1 个 → 钱财减 `BuyPrice`、库存该物品 +1 |
| G2 | **卖得出** | 有物品 → 卖 1 个 → 物品 -1、钱财 + `SellPrice` |
| G3 | **价格表驱动** | 改 `Item.BuyPrice/SellPrice` → 重导 → 价格变化，代码 0 改动 |
| G4 | **失败有原因** | 钱财不足 / 格位满 / 叠加满 / 无货可卖 → 明确提示，不扣不错 |
| G5 | **不扩张** | 没有限购、没有时代调价、没有运送护送、不新增表 |

### 1.2 明确不做的（Non-goals）

| # | 不做的事 | 原因 |
| --- | --- | --- |
| N1 | **库存 / 每日限购 / 刷新** | 概念案有"随倒计时刷新"，但原型期只做兑换（§13 Q2） |
| N2 | **价格受时代事件波动** | 需要"时代事件"系统（W5.4+），本波不做（Q3） |
| N3 | **运送与护送**（购买后按卖方位置有运送时长、途中可能失败） | 需要计时器 + 路线 + 失败率 + 护送战斗，属**大件**；M6 已判推迟（见 `19_局外战斗.md`） |
| N4 | 多资源定价（材料/图纸当货币） | 只认**钱财**一种货币（Q4） |
| N5 | 批量买卖（买 10 / 卖全部） | 最小版每次 **1 个**；批量待确认（Q5） |
| N6 | 商人立绘/对话框/讨价还价 | 纯列表 UI |

## 2. 术语表

| 术语 | 含义 | 备注 |
| --- | --- | --- |
| 买价 / `BuyPrice` | 买 1 个要花的**钱财** | `Item` 新列；`0` = 该物品**不可买** |
| 卖价 / `SellPrice` | 卖 1 个得到的**钱财** | `Item` 新列；`0` = **不可卖** |
| 钱财 / `resMoney` | 唯一货币 | `ResourceKind.Money = 3` |
| 差价 | `SellPrice < BuyPrice` | 建议 `SellPrice = floor(BuyPrice × 50%)` |
| 可交易 | `BuyPrice > 0` 或 `SellPrice > 0` | 两者都为 0 = 不进市场列表 |

## 3. 规则详述

### 3.1 买入

| # | 规则 |
| --- | --- |
| B1 | 显示条件：`BuyPrice > 0` 且 `Item.Enable = true` |
| B2 | 点「买」→ 校验：`钱财 ≥ BuyPrice`（否则「钱财不足」）→ `SpendResource(Money, BuyPrice)` → `AddItem(itemId, 1)` |
| B3 | `AddItem` 失败（**格位满** / **已到叠加上限**）→ **把已扣的钱财退回**（`AddResource(Money, BuyPrice)`）+ 提示失败原因（**关键：不能出现"扣钱没拿到"**） |
| B4 | 每次买 **1 个**（批量 N6 不做）；连点即连买 |
| B5 | 无库存概念：市场价格固定，想买多少买多少（受格位/叠加限制） |

### 3.2 卖出

| # | 规则 |
| --- | --- |
| S1 | 显示条件：`SellPrice > 0` 且玩家**持有该物品**（`库存数量 > 0`） |
| S2 | 点「卖」→ 校验持有 ≥1 → `RemoveItem(itemId, 1)` → `AddResource(Money, SellPrice)` |
| S3 | 卖出不消耗格位以外的任何东西；卖光后该物品从列表移除（或显示「持有 0」置灰） |
| S4 | 每次卖 **1 个** |

### 3.3 价格口径（表里填，不在代码算）

| # | 规则 |
| --- | --- |
| P1 | **`SellPrice` 由策划直接填**，默认按 `floor(BuyPrice × 0.5)`（向下取整） |
| P2 | 允许例外：某些物品卖价高于/低于半价（如稀有图纸卖价可高） —— **不写死在代码** |
| P3 | `BuyPrice = 0` 且 `SellPrice = 0` → 该物品**不在市场出售**（但可卖？不：两者都 0 = 完全不参与，列表不显示） |
| P4 | `SellPrice = 0` 但 `BuyPrice > 0` → 只买不卖（如"任务物品"） |
| P5 | `BuyPrice = 0` 但 `SellPrice > 0` → 只卖不买（如"局内掉落"卖给商人） |

### 3.4 规则优先级

`B2 钱财校验` > `B3 入库校验（失败回滚）`；`S2 持有校验` > 出售。

## 4. **价格放哪：`Item` 加 2 列 vs 新建 `Market` 表**（结论：加列）

| 维度 | **`Item` 加 2 列（✅ 采用）** | 新建 `Market` 表 |
| --- | --- | --- |
| 语义 | 价格是**物品的属性**（每种物品一个价）→ 1:1 放在物品行最自然 | 价格是独立实体，需要 `ItemId` 外键 + 多一次查表/join |
| 表数量 | **14 → 14（不变）** | 14 → 15，导出链路再扩一张 |
| 导出/建表成本 | 只改 1 张表 + 重导 | 新建 xlsx（7 行表头）+ 导出 + 两套产物 |
| 12 类型限制 | `uint` 足够（价格） | 同样够，但没换来收益 |
| 加列风险 | 加列**零迁移**（配置不进存档；老存档不受影响） | 新表要维护外键一致性（导出器**不校验外键**） |
| 将来扩展 | 需要"按时代调价 / 限购"时，再抽 `Market` 表（`ItemId + Era`）即可 | 一开始就锁死一张表，改动反而更重 |

**结论**：**`Item` 加 2 列 `BuyPrice` / `SellPrice`（`uint`），不新建表。**
> 若将来要做"按时代价格表 / 限购 / 多商人"，再新增 `Market`（`ItemId+Era` 或 `MerchantId+ItemId` 主键），届时 `Item` 的两列可保留为"基准价"。

### 4.1 `Item` 已落地价格列（正式规格见 `10_Item_字段规格.md`）

| 第 3 行中文备注 | 第 4 行属性名 | 第 6 行类型 | 含义 | 示例 |
| --- | --- | --- | --- | --- |
| 买价 | `BuyPrice` | `uint` | 买 1 个花费的钱财；`0` = 不可买 | `20` |
| 卖价 | `SellPrice` | `uint` | 卖 1 个得到的钱财；`0` = 不可卖 | `10` |

> 两列已导出到 `ItemConfig` / `ItemConfig.json`，9 行价格见 `10_Item_字段规格.md`；历史运行验收见 `20_W5阶段验收报告.md`，本轮收尾证据与评审见 `21_W5收尾与数值评审.md`。

## 5. 状态与流程

### 5.1 市场面板状态

| 状态 | 条件 | 表现 |
| --- | --- | --- |
| 正常 | 有可交易物品 | 列表 + 买/卖按钮 |
| 钱不足 | `钱财 < BuyPrice` | 「买」置灰 + 提示「钱财不足」 |
| 格位满 | `UsedSlots >= TotalSlots` 且该物品**新种类** | 「买」置灰 + 提示「格位已满」 |
| 叠加满 | 该物品 `count >= StackLimit` | 「买」置灰 + 提示「已达叠加上限」 |
| 无货 | 该物品 `count = 0` | 「卖」置灰 |
| 不可交易 | `BuyPrice=0 && SellPrice=0` | 不显示该行 |

### 5.2 流程（买）

```
点「买」
 ├─ 钱够？ ── 否 → 提示「钱财不足」，结束
 ├─ SpendResource(Money, BuyPrice) ── 失败 → 提示，结束
 ├─ AddItem(itemId, 1, out reason)
 │    ├─ 成功 → 刷新（钱 -N，库存 +1）
 │    └─ 失败 → AddResource(Money, BuyPrice) 退回 + 提示原因   ← 关键
```

### 5.3 流程（卖）

```
点「卖」
 ├─ 持有 ≥1？ ── 否 → 置灰/提示，结束
 ├─ RemoveItem(itemId, 1, out reason) ── 失败 → 提示，结束
 └─ AddResource(Money, SellPrice) → 刷新
```

### 5.4 时序

| 顺序 | 发起方 | 接收方 | 动作 |
| --- | --- | --- | --- |
| 1 | 市场面板 | `InventoryService` | `GetResource(Money)` / `GetStacks()`（刷新显示） |
| 2 | 玩家 | 市场面板 | 点买 / 卖 |
| 3 | 市场面板 | `InventoryService` | `SpendResource` + `AddItem`（或 `RemoveItem` + `AddResource`） |
| 4 | 市场面板 | — | 刷新列表 + 提示结果 |
