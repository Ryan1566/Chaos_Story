## 3. 开局阶段流程（主菜单 → 存档面板 → 局外）

### 3.1 目标流程

```
进入游戏（EnterScene）
   │
   ├─ 主菜单面板
   │     └─「开始游戏」
   │           └─ 存档面板（选档：新建档 / 读取已有档）
   │                 │
   │                 ├─ 新建档 ──┐
   │                 └─ 读取档 ──┤   ★ 两条路走同一条后续流程
   │                             ▼
   │                    读档 / 建档完成
   │                             ▼
   │                    **[局外系统] 建立并显示**（默认面板 = 世界观地图）
   │                             ├─ 固定地点 / 兴趣点（按 WorldMap 表）
   │                             ├─ 势力范围（按存档当前 Stage 取 WorldFaction）
   │                             └─ 局外经营入口（村庄 / 家族树 / 市场…）
   │
   └─（局外）返回主菜单 → 回到主菜单面板（数据按存档规则保存，见 §3.3）
```

### 3.2 新档与读档**同一条路**（硬规则）

| # | 规则 | 说明 |
| --- | --- | --- |
| R1 | **新建档与读取档在完成之后走完全相同的后续流程** | 不允许"新档走一条、读档走另一条"；差异只体现为**存档数据初值不同** |
| R2 | 完成建档 / 读档后，**必须先建立并显示「局外系统」** | 局外的默认面板是**世界观地图**（§1 的一句话说明） |
| R3 | **不得在此时生成局内地图** | 局内地图属于 M8/M14，由派遣进入；见 R4 |
| R4 | **不切场景**：全程在 `EnterScene` 内**切面板** | 局内地图运行在 `WorldScene`（`01_局内地图生成系统.md` §16.13 ⑦：该场景已挂 `RunMapBootstrap`）——**从局外进入局内是另一条流程（M7 派遣）**，不属于本文 |
| R5 | 返回主菜单 = 回到**主菜单面板** | 仍是 `EnterScene` 内的面板切换；是否需要卸载局外面板/释放地图资源由程序定（§15 Q7） |

> ⚠️ **用户已明确指出当前实现的错误**：现在**读档后直接跑生成局内场景的逻辑**。本文正式定为：**读档 → 局外（世界观地图）**；局内只由派遣触发。

## 4. 世界观地图（UI 小地图）与局内随机地图的区别

> 一句话：**局外那张"天下的图"是给人看的 UI**；**局内那张图是给人跑的关卡**。两者共享"地图"这个词，但没有任何共用数据。

| 维度 | **局外世界观地图（本文）** | **局内随机地图（`01_局内地图生成系统.md`）** |
| --- | --- | --- |
| 目的 | 表现世界格局：地点在哪、势力占哪 | 提供可跑跳的战斗关卡 |
| 生成方式 | **工具手绘 → 配表**（固定到坐标，**不随机**） | 程序化生成（手作房间块 + 原型图混合；**每局不同**） |
| 坐标口径 | **归一化 0~1**（与底图分辨率解耦） | 格子 / 世界单位（瓦片、房间、格行） |
| 数据来源 | `WorldMap` / `WorldFaction` 两张表 | `MapBiome` / `MapPreset` / `PresetLayer` / `MapChunk` / `ChunkSocket` / `ChunkSlot` 等表 |
| 生命周期 | 局外常驻（读档 → 离开局外） | **每局 / 每场景**重建（有 `runSeed`、`sceneIndex`） |
| 所在场景 | `EnterScene`（**不切场景**） | `WorldScene`（`RunMapBootstrap`） |
| 玩家操作 | 看、点（**不做**跑跳） | 操作 1 名角色 + 3 名 AI 跑跳战斗 |
| 随机性 | **无随机**（同表同图） | 有随机（种子决定） |

## 5. 三项功能的规则

### 5.1 固定地点放置（`Kind = 1`）

| # | 规则 |
| --- | --- |
| P1 | 每个固定地点 = `WorldMap` 表里的**一行**：`Kind = 1`、`Type` = **地点表**的分类值、`RefId` = **地点表**主键（`03_地点表与兴趣点表_接口约定.md`） |
| P2 | 位置由 `X` / `Y` 归一化坐标决定（§8.3）；**不随底图分辨率变化** |
| P3 | `Scale`（默认 1）控制该点图标的缩放；`Layer`（默认 0）控制显示层级，**数值大的画在上面** |
| P4 | 同一 `(Kind, Type, RefId)` **不建议出现多行**（同一个地点摆两次会造成重复图标）——**工具应校验**（§14 A5） |
| P5 | 固定地点的**名称、图标、是否可进入**等由地点表决定，**不在本表** |

### 5.2 兴趣点放置（`Kind = 2`）

| # | 规则 |
| --- | --- |
| P6 | 与固定地点同构：`Kind = 2`、`Type` = **兴趣点表**分类值、`RefId` = **兴趣点表**主键 |
| P7 | 兴趣点与固定地点**可重叠占位**（例如村庄旁的一个山洞）；重叠时按 `Layer` 决定谁在上层（§5.4） |
| P8 | 兴趣点的"是否已探索 / 是否可见"属于**存档状态**，不写进本表（本表只有 `Enable` 这一列是**配置级开关**，用于整体下线某个点） |

### 5.3 势力范围绘制

| # | 规则 |
| --- | --- |
| P9 | 一个势力的**一块区域** = 表里一条 `(Stage, FactionId, RegionId)` 的顶点序列：按 `PointOrder` **升序**把 `X` / `Y` 依次连成**闭合多边形** |
| P10 | 同一区域**顶点数 ≥ 3**；`PointOrder` 从 1 起**连续**（1,2,3… 不跳号） |
| P11 | **飞地（同一势力的多块不相连领地）**：同一 `(Stage, FactionId)` 下 **`RegionId` 不同 = 同一势力的多块不相连领地**（本土 + 飞地，或多块飞地）；每块**各自独立成多边形**、顶点数**各自 ≥ 3**；`RegionId` 不同**不改变归属判定**（见 P18） |
| P12 | 填充色由 `Color`（`#RRGGBB`）决定，**逐行携带**（同一区域每行写同一个颜色）；⚠️ **同一 `(Stage, FactionId)` 的所有区域（含飞地）必须同色**（工具自动继承、不一致判 Error 阻止导出，见 `06_WorldFaction_字段规格.md` §6 C10）；**势力正式配色表落地后以其为准** |
| P13 | 按 `Stage` 分别绘制：**一次只显示当前时期**的多边形集合（§6.2） |
| P14 | 多边形**不要求重复首点**（工具按 `PointOrder` 顺序连完自动闭合）——⚠️ 与工具的产出约定必须一致，见 §15 Q2 |
| P18 | **按势力聚合**：运行时以 `(Stage, FactionId)` 为归属单位 —— **点落在该势力任一区域内即属于该势力**（`RegionId` 只用于分块绘制，不参与归属判定）；**两片之间的空隙不属于任何势力**（不按包围盒 / 就近判定） |

**飞地怎么画（工具操作流程）**

```
① 设定 FactionId + Stage（例如 时期 1 / 势力 1 秦）
② 点「新建区域（同势力）」
     → RegionId 自动取「该 (Stage, FactionId) 下一个可用号」
       （本土 = 1；已有 1 → 取 2；再新建 → 取 3 ……）
     → Color 自动继承该势力已有颜色（不让重复选色，见 06 字段规格 §6 C10）
③ 依次点顶点 → 形成一片**与已有领地不相连**的新区域
④ 重复 ②③，可为同一势力画出任意多块不相连领地（本土 + 飞地）
⑤ 导出：该势力在表中表现为**多组**行（RegionId = 1, 2, …），**同一 FactionId、同一 Color**
```

**运行时表现**

| # | 表现 |
| --- | --- |
| B1 | 同一势力的**多块区域同色**，视觉上属于**同一个势力**（不会因为分成两块就换个颜色） |
| B2 | 点落在**任意一块**内 → 都判定为**该势力**（`RegionId` 只用于分块绘制，不参与归属） |
| B3 | **两块之间的空隙不属于任何势力** —— 空隙处的点查询返回「无势力」 |
| B4 | 归属口径的权威定义在 `Story/03_配置表设计/06_WorldFaction_字段规格.md` §5（**M8** + 口径 **R1~R4**），自检条目 **F1~F3** |

### 5.4 显示顺序与冲突

| # | 规则 |
| --- | --- |
| P15 | 绘制层次（从下到上）：**底图 → 势力多边形 → 固定地点 → 兴趣点**（同 `Layer` 时按此优先级；**策划建议**） |
| P16 | `WorldMap.Layer` 数值越大越靠上，可用于让某个点压住另一个点；`WorldFaction` **没有** Layer 列（多边形统一在点位之下） |
| P17 | `Enable = false` 的行**不显示**，但保留在表里（用于临时下线而不删行） |

## 6. 5 时期口径与当前时期

### 6.1 时期对照表（与概念案 §5.3 轴一一致）

| `Stage` | 时期 | 对应概念案 |
| --- | --- | --- |
| 1 | **战国末期** | 时代 1（MVP 唯一产出数据的时期） |
| 2 | 秦朝 | 时代 2 |
| 3 | 秦末起义初期 | 时代 3 |
| 4 | 楚汉争霸 | 时代 4 |
| 5 | 汉刘邦时期 | 时代 5 |

> ⚠️ 本文的 `Stage` **就是**概念案里的"时代"序号，**不要**与 **M13b 深度**（每通关 +1、上限 = 当前时代序号）混淆：**深度是局内难度的叠加轴，不是地图时期**。

### 6.2 当前时期取存档进度

| # | 规则 |
| --- | --- |
| S1 | 显示哪一套势力范围 = **存档里的当前时期**（概念案 §5.3 轴一：5 时代单向推进、不可回退） |
| S2 | 时期推进后**立即**用新时期的 `WorldFaction` 数据重绘；旧时期数据不再显示（**不回退**） |
| S3 | 地图**底图与固定地点**不随时期变化（`MapId` 相同即同一张图）；**变化的是势力范围**（以及后续可能的地点归属表现） |
| S4 | `WorldMap` 表**没有** Stage 列 → 点位是**跨时期共用**的；若将来需要"某时期才出现的点"，需**新增列或拆表**（**不能用 enum**，见 §15 Q4） |

### 6.3 MVP 只做时期 1 数据

- 本次**只产出 `Stage = 1`（战国末期）**的势力范围数据（§9 给清单与配色）。
- 时期 2~5 的**分表可以先建结构、留空**（但**顶层合并表必须 ≥1 行数据**，见 §7.4 H1）；也可以暂不产出。
- MVP 验收只看 `Stage = 1` 的地图是否正确（§14）。

## 7. 数据流（工具 → xlsx → Json → 运行时）

### 7.1 完整链路

```

  ① 选源图（可自定义）         Assets/Art/PNG/GameWorld_Map/Map_tianxia_zhongyuan.png（4096×3138）
  ② 在图上摆固定地点 / 兴趣点    → 带 (Kind, Type, RefId) + 归一化 X/Y
  ③ 按 5 个时期分别画势力范围    → 每个 (Stage,FactionId,RegionId) 一条多边形
  ④ 工具导出 xlsx（7 行表头格式）
        ├─ 时期分表 ×5 → Assets/Excel/Chaos_excel/_worldmap_tool/   ← 子目录，不参与导出
        └─ 顶层合并表 ×2 → Assets/Excel/Chaos_excel/WorldMap_世界观地图表.xlsx
                                                     WorldFaction_势力范围配置表.xlsx
  ⑤ 人工把 5 张时期分表合并进顶层的 WorldFaction（用户已确认手工合并）
  ⑥ 程序执行菜单 ExcelTool/ExportExcelConfigs
        → Resources/Data/Json/Runtime/WorldMapConfig.json   + Scripts/Runtime/MVP/Model/ConfigData/WorldMapConfig.cs
        → Resources/Data/Json/Runtime/WorldFactionConfig.json + …/WorldFactionConfig.cs
  ⑦ 运行时读 Json → 世界观地图渲染（点位 + 当前时期势力多边形）
```

### 7.2 工具的职责

| # | 职责 | 备注 |
| --- | --- | --- |
| T1 | 读**可自定义**的源图（不写死路径） | 换图 = 换底图；归一化坐标保证不破图 |
| T2 | 在图上摆放固定地点 / 兴趣点（带 `Kind` / `Type` / `RefId`） | `RefId` 由使用者填/选，工具**不**校验外键（导出器也不校验，见 §12） |
| T3 | 按 5 个时期**分别**绘制势力范围 | 每时期独立保存 |
| T4 | 导出成**表头格式与现有配置表一致**的 `.xlsx`（7 行表头） | 见 `05_`/`06_` 的字段规格 |
| T5 | 时期分表写**子目录**，顶层只留**一张**合并表 | §7.3 |
| T6 | **自检**：表尾无空行、无空列、第 4 行无空属性名、坐标在 `0~1`、顶点数 ≥3、`Color` 合法 | 这些校验能挡住导出/运行期的静默错误（§14 A5） |

### 7.3 子目录与合并

```
Assets/Excel/Chaos_excel/
├── WorldMap_世界观地图表.xlsx          ← 顶层：参与导出（类 WorldMapConfig）
├── WorldFaction_势力范围配置表.xlsx     ← 顶层：参与导出（类 WorldFactionConfig）
└── _worldmap_tool/                      ← 子目录：不参与导出（导出器不递归扫描）
    ├── WorldFaction_Stage1.xlsx         ← 或工具自己的命名，只要不落在顶层
    ├── WorldFaction_Stage2.xlsx
    ├── WorldFaction_Stage3.xlsx
    ├── WorldFaction_Stage4.xlsx
    └── WorldFaction_Stage5.xlsx
```

> **为什么必须这样**：① 顶层同英文前缀只能一张表（H2）；② 子目录**不参与导出**（导出器只扫顶层，实测行为见 `01_配置表填写规范.md` §1 / L13），所以分表可以用同名前缀而互不覆盖。

### 7.4 两条硬约束（**踩过的坑，必须遵守**）

| # | 硬约束 | 违反后果 |
| --- | --- | --- |
| **H1** | **顶层目录里任何一张表都必须 ≥ 1 行数据**（只有表头 = 空表） | **只有表头无数据** → 该表无任何导出项（只跳过本表）；**页签完全空白** → 抛 `NullReferenceException` 并被 catch，**中断整批导出**，其后所有表都不导出（`01_配置表填写规范.md` §7.1） |
| **H2** | **顶层同英文前缀只能有一张表** | `A_B.xlsx` 与 `A_C.xlsx` 会导出**同一个** `AConfig`，**静默互相覆盖**（不报错、后导出者赢）；因此 5 张时期分表**必须**放子目录 |

> 补充：源表目录里**不要放完全空白或只有表头的表**；未完成的表先移出目录（同上 §7.1 硬规则）。本次两张表若尚未产出，请**不要把空文件放进顶层**。

## 8. 配置表关联

### 8.1 本系统读取的表

| 表 | 用途 | 字段规格 |
| --- | --- | --- |
| `WorldMap` | 固定地点 / 兴趣点的**放置与显示**（`Kind`/`Type`/`RefId`/`X`/`Y`/`Scale`/`Layer`/`Enable`） | `Story/03_配置表设计/05_WorldMap_字段规格.md` |
| `WorldFaction` | 各**时期**势力范围多边形（`Stage`/`FactionId`/`RegionId`/`PointOrder`/`X`/`Y`/`Color`/`Enable`） | `Story/03_配置表设计/06_WorldFaction_字段规格.md` |
| 地点表 / 兴趣点表 | **将来**：`(Kind, Type, RefId)` 指向的内容 | 本次**不建表**，约定见 `03_地点表与兴趣点表_接口约定.md` |

### 8.2 字段口径摘要（权威在各自字段规格文档）

- **10 列** `WorldMap`：`Index`(uint) / `MapId`(uint) / `Kind`(uint) / `Type`(uint) / `RefId`(uint) / `X`(float) / `Y`(float) / `Scale`(float) / `Layer`(uint) / `Enable`(bool)
- **9 列** `WorldFaction`：`Index`(uint) / `Stage`(uint) / `FactionId`(uint) / `RegionId`(uint) / `PointOrder`(uint) / `X`(float) / `Y`(float) / `Color`(string) / `Enable`(bool)
- 两张表第 5 行端标记**全部 `client`**；类型全部取自 12 类型白名单（**无 `enum`**，一律 `uint` + 对照表）。

### 8.3 归一化坐标口径（**必须与工具一致**）

| 项 | 口径 |
| --- | --- |
| `X` | `0 ~ 1`，**自底图左边界向右**递增 |
| `Y` | `0 ~ 1`，**自底图下边界向上**递增（**Y 向上**） |
| 像素 → 归一化 | `X = px / 图宽`；`Y = 1 - py / 图高`（`px`/`py` 为**以图片左上角为原点**的像素坐标） |
| 当前底图 | 宽 4096、高 3138（§文首实测） |

> ⚠️ **最容易出错的一处就是 Y 轴翻转**：图片像素原点在**左上**，而本表 `Y` 向上。工具若直接用 `py / 图高` 会出现**上下镜像**。**此换算公式必须与工具实现互相对齐**（§15 Q1）。

## 12. 边界与异常

| # | 场景 | 期望行为 |
| --- | --- | --- |
| E1 | `WorldMap` 表 0 行 / 全部 `Enable = false` | 地图只显示**底图**，无点位；**不报错** |
| E2 | `WorldFaction` 里当前 `Stage` **没有任何数据** | 地图**不画势力范围**（只有底图 + 点位）；**不报错、不空白**（这是 MVP 时期 2~5 的常态） |
| E3 | `X` / `Y` 越界（<0 或 >1） | 该点位/顶点**画出边界外**或被裁掉；工具**应在导出前拦截**（§7.2 T6）。运行时不校验（导出器也不校验） |
| E4 | 某 `(Stage,FactionId,RegionId)` 顶点数 < 3 | **不构成多边形** → 跳过该区域并记 warning；**不崩溃** |
| E5 | `PointOrder` 不连续 / 有重复 | 连接顺序不确定 → 多边形自交/变形；**工具校验**；运行时按数值升序尽力绘制 |
| E6 | `Color` 不是合法 `#RRGGBB` | 该区域用**默认色**并记 warning（不要让整张地图消失） |
| E7 | `RefId` 指向的条目**在地点表/兴趣点表里不存在** | **导出器不校验外键、运行时不报错** → 点位或详情缺失。**由工具/策划人工把关**（§15 Q5） |
| E8 | `WorldMap` / `WorldFaction` 的 Json 文件缺失 | 地图降级为"只有底图"；**不得阻塞进入局外**（对齐 `01_局内地图生成系统.md` §10 的兜底思路） |
| E9 | 底图资源缺失 | 显示纯色底 + warning；**不阻塞**局外其它面板 |
| E10 | 同一 `(Kind,Type,RefId)` 在 `WorldMap` 里出现多行 | 会画出重复图标；**工具校验**（§14 A5） |
