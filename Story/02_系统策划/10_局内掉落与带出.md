# 局内掉落与带出系统设计方案（W3.2）

> 状态：评审中
> Owner：策划
> 最后更新：2026-10-18
> 关联：`Story/01_企划/01_游戏概念案.md`（§6 M9 局内养成 / M12 反哺与选择性带出）、`Story/02_系统策划/05_门客系统.md`、`06_资源与库存.md`、`09_派遣与编队.md`、`12_结算与进度.md`、`Story/03_配置表设计/10_Item_字段规格.md`、`Story/03_配置表设计/14_Drop_字段规格.md`

> **已定口径（不得改）**
> - **门客 = `Retainer`**（参战）；**族人 = `Clansman`**（不参战，本波不涉及）。
> - **格位 8 起步**（`EffectType=2` 可提升，**硬上限 24**）；**同名叠加 99**。
> - **带出上限 = `DeployCap`**（基准 1 + 家族树 `EffectType=3` 加成，**硬上限 10**；代码 `MetaProgressService.DeployCap`）。
> - **U2 仅运行中计时**（离线不走表）。
> - **格位满/叠加满 → 掉落物留在原地不消失，可回头捡**（用户裁决）。
>
> **实现现状（2026-10-18 实测）**：`RunEncounter`（3 场景链、`RunCleared`、`NotifyEnemyKilled`）、`PlayerHealth`（hp 100）、`AllyController`（门客 AI）、`InventoryService`（`AddItem` 返回失败原因 / `TotalSlots` / `UsedSlots` / `HardMaxSlots=24`）、`MetaProgressService`（`DeployCap`）均已存在；**局内目前没有掉落、没有局内库存、没有带出界面**。

## 1. 系统概述

| 项目 | 内容 |
| --- | --- |
| 系统名 | 局内掉落（Run Drop）与带出（Extraction） |
| 所属模块 | 概念案 §6 **M9 局内养成**（掉落侧）＋ **M12 反哺与选择性带出** |
| 优先级 | MVP（计划的 W3.2） |
| 一句话说明 | 局内敌人按 `Drop` 表掉落物品进入**局内库存**（8 格 / 同名 99）；**通关第 3 场景**后可**勾选最多 `DeployCap` 件**带回局外，其余丢失 |
| 上游依赖 | `Drop` 表（本波新建）、`Item` 表（已出规格）、局内战斗（W3.1 已跑通）、`MetaProgressService.DeployCap` |
| 下游影响 | 局外库存/资源（带出后写入）、结算与进度（`12_结算与进度.md`）、扎营（`11_扎营与修整.md` 消耗局内道具） |
| 本系统涉及的配置表 | **`Drop`（掉落表，新建）**；只读 `Item`（叠加上限/类别） |

### 1.1 设计目标

| # | 目标 | 如何验证 |
| --- | --- | --- |
| G1 | **掉落表驱动** | 改 `Drop` 表的 `ItemId/Weight` → 重导 → 掉落物随之变化，代码 0 改动 |
| G2 | **格位规则一致** | 局内库存同样 **8 格位（可被家族树提升）/ 同名 99**；满了不能捡 |
| G3 | **捡不起也不消失** | 格位满时掉落物**留在原地**（不销毁），腾出格位后**可回头捡** |
| G4 | **带出有上限且可勾选** | 结算面板只允许勾选 ≤ `DeployCap` 件；超出时禁止勾选并提示 |
| G5 | **未带出的真的没了** | 确认后未勾选物品**从局内库存消失**，局外**没有**新增 |
| G6 | **失败不带出** | 全队倒下 → **不进入带出流程**，掉落全部丢失（建议口径，§13 Q3） |

### 1.2 明确不做的（Non-goals）

| # | 不做的事 | 原因 |
| --- | --- | --- |
| N1 | 场景内宝箱/容器交互 | 原型**先只做敌人死亡掉落**；宝箱留 W5 内容期 |
| N2 | 拾取动画/物理踢出 | 占位：直接弹提示 + 入局内库存 |
| N3 | 装备穿戴/升级 | W3.2 只做"拿到/带出"；穿戴归后续 |
| N4 | 掉落保底/伪随机补偿 | MVP 不做（`Drop` 表权重即全部概率） |
| N5 | 局内掉落写档 | 局内库存**不落盘**（失败/撤离即丢，见 §6） |

## 2. 术语表

| 术语 | 含义 | 备注 |
| --- | --- | --- |
| 掉落组 / `DropGroup` | 一次掉落判定所用的一组候选条目 | 同组按权重**抽 1 个**（见 `14_Drop_字段规格.md`） |
| 局内库存 / `RunInventory` | 本次局内携带的背包（**内存、不落盘**） | 8 格位 / 同名 99，与局外库存**独立** |
| 局外库存 / `InventoryService` | 局外常驻库存（落盘） | 带出成功后才写入 |
| 带出 / Extraction | 通关后把局内库存中选中的物品带回局外 | 上限 `DeployCap` |
| `DeployCap` | 本次可带出的**件数**上限 | 基准 1 + `EffectType=3` 加成，**硬上限 10** |
| 件 | 带出计数单位 = **1 个物品**（不管叠加多少） | 见 §3.4「件怎么数」 |
| 原地保留 | 捡不起的掉落物留在场景里不销毁 | 用户裁决 |

## 3. 规则详述

### 3.1 掉落来源（MVP 只做 ①）

| # | 来源 | MVP | 说明 |
| --- | --- | --- | --- |
| ① | **敌人死亡** | ✅ | 由 `RunEncounter.NotifyEnemyKilled` 钩子触发（已存在） |
| ② | 场景可交互箱/容器 | ❌（W5） | 需要交互体与预制体 |
| ③ | 场景/剧情事件奖励 | ❌ | 归 M4 事件 |

### 3.2 掉落判定（**一组按权重抽 1 个**）

```
敌人死亡 → 取该敌人的 DropGroup（本期用常量：普通怪=1，精英/boss=2）
  → 在 Drop 表里取 DropGroup 匹配、Enable=true 的行
  → 若该组为空 → 不掉（记 Warn）
  → 按 Weight 加权随机**抽 1 行**
  → 数量 = Random.Range(MinCount, MaxCount+1)
  → 尝试放入局内库存（§3.3）
  → 放不下 → 掉落物**留在原地**（生成可拾取物/标记），提示"背包已满"
```

> **为什么是"抽 1 个"而不是"逐条独立判定"**：见 `14_Drop_字段规格.md` §5（权重即概率、一次死亡只出一件、无需额外 `Rolls` 列、数值好调）。

### 3.3 入库规则（与局外库存同一套口径）

| # | 场景 | 行为 |
| --- | --- | --- |
| D1 | 新种类 + 有空格位 | 入局内库存，占 1 格 |
| D2 | 已有种类 + 未达叠加上限 | 累加（≤ `Item.StackLimit`，默认 99） |
| D3 | 已达叠加上限 | **超出部分不消失**：留在原地；提示「已达叠加上限（99）」 |
| D4 | **无空格位**（新种类） | 不消失：**留在原地**；提示「格位已满（8/8）」 |
| D5 | 部分可入（如可加 3 但掉了 5 个） | **能入多少入多少**，剩余留在原地 | 
| D6 | 原地物品 | 玩家可**稍后**（腾出格位后）回来捡；场景切换/撤离时**未捡的丢失**（§9 E3） |

### 3.4 带出规则

| # | 规则 |
| --- | --- |
| E1 | 只允许在**通关（第 3 场景清空）后**进入带出流程；失败**不进入**（§3.5） |
| E2 | 结算面板列出**局内库存全部条目**，每条可勾选；**勾选总数 ≤ `DeployCap`** |
| E3 | **「件」= 1 个物品条目（堆叠条目）**：勾选"药品 ×12"算 **1 件**（玩家看到的是"一项"）。**策划建议**按条目计件（否则 99 个物资就能占满 10 件上限，体验极差）→ §13 Q2 |
| E4 | 确认带出 → 勾选条目按数量写入局外 `InventoryService.AddItem`；**失败原因（格位满）要提示**，未写入的**视为放弃** |
| E5 | 未勾选条目 → **随局内库存销毁**（丢失） |
| E6 | 带出**不改**门客/资源；只搬运物品 |

### 3.5 失败处理（原型建议）

| # | 建议 |
| --- | --- |
| F1 | 全队倒下 → 直接走**失败结算**（`12_结算与进度.md`），**不进入带出面板** |
| F2 | **原型期：局内库存全部丢失**（简单、可解释） |
| F3 | 备选（**待确认** Q3）：保留 50%（按数量向下取整），给"失败也能带回一点"的宽慰 |

> 概念案用户原话「失败也能带回部分收获」→ 因此 **F2 与用户原意有偏差**，标注为**待用户拍板**。

## 4. 数值与公式

| # | 数值 | 值 / 公式 | 来源 |
| --- | --- | --- | --- |
| F1 | 单次掉落数量 | `Random.Range(MinCount, MaxCount+1)` | `Drop` 表 |
| F2 | 掉落概率 | 组内 `Weight / ΣWeight` | `Drop` 表 |
| F3 | 局内格位 | `Clamp(BaseSlots 8 + ΣEffectType=2, 0, 24)` | 同 `InventoryService` 口径 |
| F4 | 同名叠加上限 | `Item.StackLimit`（默认 **99**） | `Item` 表 |
| F5 | 带出上限 | `DeployCap = Clamp(1 + ΣEffectType=3, 1, 10)` | `MetaProgressService.DeployCap` |
| F6 | 件数 | 勾选的**条目数**（每项 1 件） | §3.4 E3 |

### 4.1 取整与边界

| 项目 | 规定 |
| --- | --- |
| 数量 | 整数（`uint`）；`MinCount ≤ MaxCount`，否则工具/程序报错 |
| 权重 | 整数 ≥1；整组权重为 0 视为非法（跳过并 Warn） |
| 件数上限 | 整数 1~10 |
| 随机 | 用局内 runSeed 派生（便于复现调试；**待确认** Q6） |

## 5. 状态与流程

### 5.1 局内库存生命周期

| 状态 | 何时 | 数据 |
| --- | --- | --- |
| 创建 | 出发成功（`DispatchService.Depart`） | 空 `RunInventory`（内存） |
| 累积 | 战斗掉落 | 内存条目 |
| 结算（通关） | 第 3 场景清空 | 进入带出勾选 |
| 结算（失败） | 全队倒下 | 按 §3.5 丢弃 |
| 销毁 | 撤离/重进/失败结算完成 | 清空内存，**不写档** |

### 5.2 流程图

```
敌人死亡 ──> 抽 1 条 Drop ──> 入局内库存？
                                 ├─ 能入 → 入（提示 +N）
                                 └─ 不能 → 留在原地（提示"背包已满/已达上限"）
第 3 场景清空 ──> 通关结算 ──> 带出面板（勾选 ≤ DeployCap）
                                 ├─ 确认 → 勾选项写入局外库存；未勾选丢弃
                                 └─ 关闭/放弃 → 全部丢弃
全队倒下 ──> 失败结算（不进带出）
```

### 5.3 时序

| 顺序 | 发起方 | 接收方 | 动作 |
| --- | --- | --- | --- |
| 1 | `RunEncounter` | 掉落服务 | `OnEnemyKilled(enemy)` |
| 2 | 掉落服务 | `Drop` 表 + `Item` 表 | 抽组、取定义 |
| 3 | 掉落服务 | `RunInventory` | `TryAdd(itemId, count, out reason)` |
| 4 | 掉落服务 | 场景 | 放不下 → 原地生成可拾取物 |
| 5 | 结算面板 | 掉落服务 / `InventoryService` | 带出确认 → `AddItem` |

## 6. 数据结构

| 数据 | 位置 | 类型 | 落盘 |
| --- | --- | --- | --- |
| 局内库存 | `RunInventory`（运行时单例/静态） | `List<{uint itemId; uint count;}>` | **否** |
| 原地掉落物 | 场景物体（含 `itemId`/`count` 的拾取物） | GameObject + 组件 | **否**（切场景即丢） |
| 带出结果 | `SavePayload.items` | `List<ItemStackSave>` | ✅ 经 `InventoryService` |
| 带出上限 | `MetaProgressService.DeployCap` | `int`（派生） | 否（由家族树算出） |

> ⚠️ **局内库存与局外库存是两份独立数据**：局内库存**只在内存**，避免"掉落即落盘、失败还得回滚"的复杂回滚逻辑。
> 如果程序选择**直接复用 `InventoryService`**（即掉落直接进存档库存），则**必须**实现"未带出物品的回滚/删除"，否则失败也白拿 —— **不推荐**（§13 Q1）。

## 9. 边界与异常

| # | 场景 | 期望行为 |
| --- | --- | --- |
| E1 | `Drop` 表某组为空 | 不掉落 + Warn；不崩溃 |
| E2 | `ItemId` 在 `Item` 表不存在 | 跳过该条 + Warn（不生成幽灵物品） |
| E3 | 切场景时地上还有未捡的掉落物 | **消失**（不跨场景保留）；已入局内库存的保留 |
| E4 | 局内库存满了但通关 | 带出面板只列已有条目；地上未捡的**不算** |
| E5 | 带出时局外格位已满 | `AddItem` 返回失败原因 → 提示；该条**视为放弃** |
| E6 | `DeployCap = 0`（理论上不会，下限 1） | 视为 1 并 Warn |
| E7 | 勾选后关闭面板 | 视为放弃（不自动带出） |
| E8 | 重进游戏（局内库存不落盘） | 局内状态不存在 → 回局外（与 `09_派遣` E3 一致） |

## 12. 验收标准（可测试）

| # | 验收项 | 判定方式 |
| --- | --- | --- |
| A1 | 表驱动掉落 | 改 `Drop` 权重/物品 → 重导 → 掉落变化，代码 0 改动 |
| A2 | 一组抽 1 个 | 单次敌人死亡**最多**入包 1 条（组内多行不会同时掉） |
| A3 | 数量区间 | `MinCount~MaxCount` 内随机，越界不出现 |
| A4 | 叠加 | 同种物品累加到 ≤99；第 100 个不消失 |
| A5 | **格位满** | 新种类入包失败并提示；**地上掉落物不消失** |
| A6 | **回头捡** | 腾出格位后能捡起地上物品 |
| A7 | 切场景丢失 | 切场景后地上未捡的消失 |
| A8 | 带出上限 | 勾选数 > `DeployCap` 被拒 |
| A9 | 带出成功 | 勾选物进局外库存；未勾选的不进 |
| A10 | 带出失败 | 局外格位满 → 提示且不写入 |
| A11 | 失败不带出 | 全队倒下 → 不进带出面板 |
| A12 | 不落盘 | 局内库存退出重进后不存在（与 `09_派遣` E3 一致） |
