# 派遣与编队系统设计方案（W2 · 门客选出征）

> 状态：评审中
> Owner：策划
> 最后更新：2026-10-18
> 关联：`Story/01_企划/01_游戏概念案.md`（§6 M7 传送阵与派遣编队、§5.3 时代轴）、`Story/02_系统策划/04_功能开发计划与优先级.md`（W2）、`Story/02_系统策划/05_门客系统.md`（可出战判定）、`Story/02_系统策划/06_资源与库存.md`、`Story/03_配置表设计/09_Retainer_字段规格.md`

> **已裁决口径（不得改）**
> - **门客 = `Retainer`**（可被选中派遣进入局内战斗的角色）；**族人 = `Clansman`**（不参战 NPC）—— 本系统的对象**只有门客**。
> - **U6：单人派遣的收益/风险差不在派遣界面显示**（可单人出发，但界面**不提示**"人少更危险/收益更高"之类）。
> - **U2：原型期「仅运行中计时」**（离线不走表）—— 本系统不涉及计时器，但撤离/重进不受离线影响。
> - **U5-①**：`runs`（进入局内次数）是剧情事件的触发条件之一 → **每次成功出发必须 `runs += 1`**。
>
> **实现现状（2026-10-18 实测，程序已落地）**：`DispatchService`（`MaxTeamSize=4`/`MinTeamSize=1`/`StartSceneIndex=1`/`IsInRun`/`SelectedIds`/`GetCandidates`/`GetUnavailableReason`/`Toggle`/`ResetSelection`/`Depart`/`ReturnToMeta`）、`PrototypeMapSpawner`（`ContainerName="PrototypeRunMap"`/`Spawn(sceneIndex, seed)`/`Clear()`/`IsSpawned`）、`SavePayload.runTeam`、GM「系统」→「派遣」版块、`PanelType.DispatchPanel`。**本文是这些实现的策划口径与验收依据。**

## 1. 系统概述

| 项目 | 内容 |
| --- | --- |
| 系统名 | 派遣与编队（Dispatch / Team） |
| 所属模块 | 概念案 §6 **M7 传送阵与派遣编队** |
| 优先级 | MVP（计划的 W2） |
| 一句话说明 | 玩家从**门客**里挑 **1~4 人**组成队伍，从传送阵出发进局；原型期**在当前场景就地生成**第 1 个局内场景（不切场景），可随时撤离回局外 |
| 上游依赖 | 门客系统（可出战判定）、存档（`runTeam`/`runs`）、`PrototypeMapSpawner` |
| 下游影响 | **W3 局内战斗**（消费队伍名单生成角色）、剧情事件（`runs`） |
| 本系统涉及的配置表 | **无新表**（门客数据来自 `Retainer` 表；队伍是存档状态，不是配置） |

### 1.1 设计目标

| # | 目标 | 如何验证 |
| --- | --- | --- |
| G1 | **只能派"能打的人"** | 重伤/信心不足的门客**不可被选中**，且显示具体原因（剩余秒数 / 信心不足） |
| G2 | **1~4 人，1 人也能走** | 选 1 人可出发；选 0 人时出发按钮禁用 |
| G3 | **出发即进局（原型期不切场景）** | 点「出发」→ 当前场景就地出现 RunMap 地图；`SceneManager` 当前场景**不变** |
| G4 | **数据可存读** | 队伍名单（`runTeam`）与 `runs` 落盘；重进后状态一致 |
| G5 | **可撤离** | 「撤离/返回局外」清掉局内场景并回到可再派遣状态 |
| G6 | **不误导玩家** | 单人出发时**不显示**任何收益/风险差异提示（U6） |

### 1.2 明确不做的（Non-goals）

| # | 不做的事 | 原因 |
| --- | --- | --- |
| N1 | 正式读条/切场景流程 | 原型期就地生成；正式流程归加载系统（`04_架构/06_加载读条界面落地…`）与 W3 之后 |
| N2 | 局内战斗角色生成 | **W3** 做；本波只到"进入状态 + 队伍记录" |
| N3 | 出战资格的其他门槛（等级/装备/时代） | MVP 只有"重伤 + 信心"两条（`05_门客系统.md` §3.2） |
| N4 | 单人/多人收益与风险差异提示 | **U6 拦截**：不在 UI 显示 |
| N5 | 编队阵型/站位 | W3 战斗层才有意义 |

## 2. 术语表

| 术语 | 含义 | 备注 |
| --- | --- | --- |
| 门客 / `Retainer` | 可被派遣进入局内战斗的角色 | **只有门客能被选中**；族人（`Clansman`）不参战 |
| 候选 / Candidate | 当前可被选中的门客集合 | `DispatchService.GetCandidates()` |
| 队伍 / Team | 本次出发选中的门客 id 列表 | `SavePayload.runTeam` |
| 已选 / Selected | 界面上处于选中态的门客 | `SelectedIds` / `SelectedCount` |
| 出发 / Depart | 确认进局 | `DispatchService.Depart()` |
| 局内 / Run | 一次进入边缘空间的探险 | `IsInRun` 为真期间 |
| 就地生成 | 在当前场景里直接生成地图容器，不切场景 | `PrototypeMapSpawner.Spawn()`，容器名 `PrototypeRunMap` |
| 撤离 / ReturnToMeta | 结束本次局内、回局外 | `DispatchService.ReturnToMeta()` |

## 3. 规则详述

| # | 规则 | 触发 | 结果 | 例外 |
| --- | --- | --- | --- | --- |
| R1 | **候选集** = 全部门客（不含已被选中的？**不排除**，已选中以选中态显示） | 打开派遣面板 | 列出所有门客；不可出战者置灰 | 无 |
| R2 | **不可选原因**：`wounded` → 「重伤 剩余 Ns」；`confidence < 30` → 「信心不足」 | 渲染列表 / 点击时 | 按钮禁用 + 显示原因（`GetUnavailableReason`） | 无 |
| R3 | **选择/取消**：点击可出战门客 → 选中；再点一次 → 取消 | 点击 | `Toggle(id)`；选中态刷新；`已选 N/4` 更新 | 已满 4 人时再选 → 提示"最多 4 人" |
| R4 | **出发条件**：`1 ≤ 已选 ≤ 4` **且** 未在局内 | 点「出发」 | `CanDepart = true` 时才可点 | 已选 0 → 按钮禁用 |
| R5 | **出发效果**（原子操作，失败要回滚） | `Depart()` 成功 | ① `SavePayload.runTeam = 已选 id 列表`；② **`runs += 1`**（U5-①）；③ `IsInRun = true`；④ **就地生成**第 1 场景（`PrototypeMapSpawner.Spawn(StartSceneIndex)`，容器 `PrototypeRunMap`）；⑤ 清空选中 | 生成失败 → `IsInRun` 与 `runs` **必须回滚**（见 §9 E4） |
| R6 | **撤离**：清局内场景 + 清队伍 + 回局外 | 点「撤离/返回局外」 | `PrototypeMapSpawner.Clear()`；`runTeam` 清空；`IsInRun = false`；**`runs` 不减少** | 未在局内时点撤离 → 提示「当前不在局内」 |
| R7 | **单人派遣** | 已选 = 1 | **允许出发**；**不显示任何收益/风险差异提示**（U6） | 无 |
| R8 | **重复出发拦截** | `IsInRun = true` 时再点出发 | 拒绝并提示「已在局内」 | 无 |
| R9 | **撤离后可再次出发** | `IsInRun = false` | 选择状态清空，可重新选人 | 无 |

### 3.1 规则优先级

`R8 已在局内` > `R4 队伍人数` > `R2 门客可出战` > `R3 选择`。

### 3.2 与门客系统的边界

| 判定 | 归属 |
| --- | --- |
| 「可出战 = 未重伤 且 信心 ≥ 30」 | **门客系统**（`05_门客系统.md` §3.2 / `RetainerService.IsDeployable`） |
| 选中/取消/出发/撤离 | **本系统**（`DispatchService`） |
| 门客属性/信心/重伤倒计时的变化 | **门客系统**（本系统只读，不改） |

> **本系统不修改门客数据**：出发不扣血、不降信心（那些是 W3 战斗/事件的结果）。

## 5. 状态与流程

### 5.1 派遣状态机（`IsInRun`）

| 状态 | 进入条件 | 允许操作 | 退出 |
| --- | --- | --- | --- |
| **待派遣**（`IsInRun = false`） | 局外 | 选人 / 取消 / 出发 | 出发成功 → 局内 |
| **局内**（`IsInRun = true`） | 出发成功 | 撤离 | 撤离成功 → 待派遣 |
| （中间态）出发中 | 点出发 | 无（防连点） | 成功 → 局内；失败 → 回滚到待派遣 |

### 5.2 流程图

```
待派遣 ──[选 1~4 名可出战门客]──> 已选 N
   │                                    │
   │                            [点「出发」]
   │                                    ▼
   │                      ① runTeam = 已选 id
   │                      ② runs += 1
   │                      ③ IsInRun = true
   │                      ④ PrototypeMapSpawner.Spawn(1)   ← 就地生成，不切场景
   │                                    ▼
   └────────[点「撤离/返回局外」]──── 局内（IsInRun = true）
                        ① Clear() 清容器
                        ② runTeam 清空
                        ③ IsInRun = false
```

### 5.3 时序

| 顺序 | 发起方 | 接收方 | 动作 |
| --- | --- | --- | --- |
| 1 | DispatchPanel | `DispatchService` | `Toggle(id)` / `ResetSelection()` |
| 2 | DispatchPanel | `DispatchService` | `Depart(out reason)` |
| 3 | `DispatchService` | `SavePayload` | 写 `runTeam`；`runs += 1` |
| 4 | `DispatchService` | `PrototypeMapSpawner` | `Spawn(1, seed)` |
| 5 | DispatchPanel / GM | — | 显示 `IsInRun` 状态与队伍人数 |
| 6 | `DispatchService` | `PrototypeMapSpawner` | `Clear()`（撤离） |

## 6. 数据结构

| 数据 | 位置 | 类型 | 说明 |
| --- | --- | --- | --- |
| 队伍名单 | `SavePayload.runTeam` | `List<uint>` | **已存在**（实测）；存本次出发的门客 id |
| 进入局内次数 | `SavePayload.runs` | `uint` | **已存在**；每次成功出发 +1 |
| 是否在局内 | `DispatchService.IsInRun` | `bool` | **不落盘**（重进视为不在局内，见 §9 E3） |
| 已选集合 | `DispatchService.SelectedIds` | `List<uint>` | 不落盘（选中态是 UI 状态） |
| 地图容器 | 场景内物体 `PrototypeRunMap` | `GameObject` | 由 `PrototypeMapSpawner` 创建/清除 |

> **为什么 `IsInRun` 不落盘**：原型期"局内"只是一张就地生成的地图 + 内存状态，**没有可恢复的中间进度**；重进直接回局外最安全（W3 才会有真正的局内存档）。

## 9. 边界与异常

| # | 场景 | 期望行为 |
| --- | --- | --- |
| E1 | 没有任何门客 | 列表空态 + 「无可派遣门客」；出发禁用 |
| E2 | 全员重伤/信心不足 | 列表全灰；出发禁用；原因逐行显示 |
| E3 | **局内时退出 Play 再进** | 视为**已撤离**（`IsInRun=false`、`runTeam` 清空），场景里**不残留**地图容器 |
| E4 | 出发时地图生成失败 | **回滚**：`runs` 不 +1、`runTeam` 还原、`IsInRun=false`，提示"进入失败"；不得留下半成品容器 |
| E5 | 连点「出发」 | 第二次被拒（已在局内） |
| E6 | 出发后门客被 GM 打伤 | 不影响本次队伍（已出发）；下次选择时受影响 |
| E7 | 撤离时容器不存在 | 静默成功（幂等），只清状态 |
| E8 | 选中门客在出发前被删除（GM 删档/改表） | 出发前校验 id 仍存在 → 否则提示"门客不存在"并刷新列表 |

## 12. 验收标准（可测试）

| # | 验收项 | 判定方式 |
| --- | --- | --- |
| A1 | **只能选可出战门客** | 重伤/信心不足者点击无效，显示原因与剩余秒数 |
| A2 | **上限 4** | 选到 4 人后再点第 5 人 → 提示"最多 4 人"，不入选 |
| A3 | **下限 1** | 选 0 人时出发禁用 |
| A4 | **单人可出发** | 选 1 人 → 出发成功；**界面无任何收益/风险差异提示**（U6） |
| A5 | **就地生成** | 出发后场景中出现 `PrototypeRunMap` 容器；`SceneManager.GetActiveScene()` 名称不变 |
| A6 | **`runs` +1** | 每次成功出发 `runs` 恰好 +1（撤离不减） |
| A7 | **队伍落盘** | 出发后 `runTeam` = 选中 id 列表；读档后一致 |
| A8 | **重复出发拦截** | 局内再点出发 → 被拒并提示「已在局内」 |
| A9 | **撤离** | 撤离后容器清空、`runTeam` 空、`IsInRun=false`，可再次选人出发 |
| A10 | **无残留** | 撤离/退出重进后场景里没有 `PrototypeRunMap` 残留 |
| A11 | **失败回滚** | 模拟生成失败（如容器被占）→ `runs`/`runTeam`/`IsInRun` 均回滚 |
| A12 | **文案** | 全部来自 `LocalizedText`，代码无中文硬编码 |
