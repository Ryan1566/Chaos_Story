---

## 1. 约定一句话

> 世界观地图上的**每一个点位**，都由 **`(Kind, Type, RefId)` 三元组**定位到一个"内容条目"：
> **`Kind` 决定查哪张表**（1 → 地点表；2 → 兴趣点表），**`Type` 是那张表里的分类**，**`RefId` 是那张表的主键**。

---

## 2. 三元组定义

| 元素 | 来源 | 含义 | 取值 |
| --- | --- | --- | --- |
| `Kind` | `WorldMap` 表第 C 列 | **条目类别**：决定去**哪张表**找内容 | `1` = 固定地点 → **地点表**<br>`2` = 兴趣点 → **兴趣点表**<br>`3+` **预留**（见 §5） |
| `Type` | `WorldMap` 表第 D 列 | **分类**：该表内部的分类值（如"城池 / 村庄 / 关隘"或"山洞 / 遗迹 / 事件点"） | 由**地点表 / 兴趣点表**各自定义；本约定**不定值域**，避免两处定义漂移 |
| `RefId` | `WorldMap` 表第 E 列 | **主键**：该表里那条内容的唯一 ID | 由对应表定义（建议用 `uint`，`1001` 起分段） |

**唯一性**：`(Kind, Type, RefId)` 组合唯一定位一个条目。
⚠️ 严格说 `RefId` 在各自表内已唯一，`Type` 在定位时是**冗余但有用**的过滤维度（工具按分类筛选、运行时按分类批量处理）——**约定上仍要求三者一起使用**，不要只靠 `RefId`（见 §6 Q2）。

---

## 3. 解析规则（运行时）

```
输入 (Kind, Type, RefId)
  ├─ Kind = 1 → 查 地点表：  按 RefId 取条目（并用 Type 校验分类一致）
  ├─ Kind = 2 → 查 兴趣点表：按 RefId 取条目（并用 Type 校验分类一致）
  └─ Kind = 3+（预留）→ 未知类别：跳过该点位并记 warning（不得崩溃）
```

| # | 规则 |
| --- | --- |
| R1 | `Kind` 只认 `1` / `2`；`3+` 视为**未知类别**，跳过并记 warning |
| R2 | 目标表**这次不存在**：MVP 阶段 `Kind=2` 允许"只画占位图标、点击只报出三元组"（`02_局外世界观地图系统.md` §11） |
| R3 | `RefId` 查不到：**不报错**，按"内容缺失"降级（占位图标 / 无详情），并记 warning |
| R4 | `Type` 与目标表里该条目的分类**不一致**：记 warning，**以 `RefId` 查到的条目为准**（`Type` 不参与定位，只做校验）——⚠️ 见 §6 Q2 |
| R5 | **不要求** `WorldMap` 里的 `Type`/`RefId` 连续或成段；由工具按需取值 |

**接口形态建议（`策划建议`，给程序参考）**：

```
bool TryGetEntry(uint kind, uint type, uint refId, out Entry entry)
// kind ∈ {1,2}；返回 false 表示"未知 kind / RefId 不存在"，调用方走占位与 warning
```

## 4. 两张表将来必须补齐的信息（**待办清单**）

> 本节是**需求清单**，不是字段规格；正式字段规格后续单独出文档时按此对齐（可增删，但需同步本文件）。

### 4.1 地点表（`Kind = 1`，固定地点）

| # | 至少要有 | 为什么需要 |
| --- | --- | --- |
| 1 | **主键 ID**（对应 `RefId`） | 三元组定位 |
| 2 | **分类**（对应 `Type`） | 工具按分类筛选；图标/行为按分类分派 |
| 3 | **名称**（建议走本地化 key，而非直接写中文） | 地图提示与详情面板显示 |
| 4 | **图标资源**（建议 `Resources` 相对路径 `string`——⚠️ 导出器**没有 Sprite 类型**，只能存路径，参照 `04_LoadingTable_字段规格.md` 的 `srcImg` 先例） | 地图上点位图标 |
| 5 | **描述 / 简介** | 详情面板 |
| 6 | **是否可进入 / 进入目标**（面板名、场景名或功能 ID） | 点击点位后的跳转 |
| 7 | **解锁条件**（时期 `Stage`、局外里程碑、道具…） | 未解锁地点是否显示/置灰 |
| 8 | **是否在地图上显示**（与 `WorldMap.Enable` 的区别：一个是内容级、一个是摆放级） | 避免两处开关语义打架（见 §6 Q3） |

### 4.2 兴趣点表（`Kind = 2`）

| # | 至少要有 | 为什么需要 |
| --- | --- | --- |
| 1 | **主键 ID**（对应 `RefId`） | 三元组定位 |
| 2 | **分类**（对应 `Type`） | 同上 |
| 3 | **名称**（本地化 key） | 显示 |
| 4 | **图标资源**（`Resources` 相对路径 `string`） | 显示 |
| 5 | **描述 / 事件文本** | 详情 / 事件 |
| 6 | **触发内容**（事件 ID / 奖励 ID / 玩法入口） | 交互后做什么 |
| 7 | **出现时期 `Stage` 与出现条件** | 兴趣点常有时代性（对应 §6 Q1） |
| 8 | **是否一次性**（探索后是否消失 → 属于存档状态） | 影响存档字段 |

> ⚠️ 两张表的**命名与英文前缀**尚未定稿（§6 Q4）：候选 `WorldLocation` / `WorldInterest`（与 `WorldMap`/`WorldFaction` 同族）或 `MapLocation` / `MapInterest`。
> 无论选哪个，都必须满足**顶层同英文前缀唯一**（`01_配置表填写规范.md` §1 H2）。

---

## 5. `Kind` 的预留值（`3+`）

- 现有约定：`1` = 固定地点、`2` = 兴趣点，**`3+` 预留**。
- **将来若新增类别**（如"势力中心""行军路线节点""资源点"），必须**同时**改三处，否则会出现"表里有、代码不认"：
  1. `WorldMap` 字段规格 §4.2 的 `Kind` 对照表；
  2. **本文档** §2 与 §3 的解析规则；
  3. 运行时映射（程序）。
- **新增类别属于接口变更**，需走评审（不要在表里先填 `3` 试）。
