## 1. 系统概述

| 项目 | 内容 |
| --- | --- |

## 2. 术语表

| 术语 | 含义 | 备注 |
| --- | --- | --- |
| 资源 / Resource | 4 个**全局数字**：物资/材料/图纸/钱财 | 不占格位（不是物品） |
| 物资 / `resGoods` | 基础消耗资源（建造/日常） | 存档字段已有 |
| 材料 / `resMaterial` | 建造与制造的原料 | 存档字段已有 |
| 图纸 / `resBlueprint` | 解锁建造/产业的稀有条目 | 存档字段已有（概念案：反哺可带出） |
| 钱财 / `resMoney` | 通用货币（市场/招募） | 存档字段已有 |

| **叠加上限 / `StackLimit`** | **同一种**物品的数量上限 | **默认 99**；来自 `Item` 表 |

| 库存 / Inventory | 一组"物品 → 数量"的堆叠列表 | 占格位的数量 = **不同 `itemId` 的个数** |

## 3. 规则详述

### 3.1 4 类资源

| 资源 | 存档字段 | 类型 | 来源（计划） | 用途（计划） | 原型期（W1a） |
| --- | --- | --- | --- | --- | --- |
| **物资** | `resGoods` | `uint` | 村庄产业收获（W1b）、局内掉落 | 建造/日常消耗 | **只显示 + GM 加减** |
| **材料** | `resMaterial` | `uint` | 局内掉落、反哺带出 | 建造/制造 | 只显示 + GM 加减 |
| **图纸** | `resBlueprint` | `uint` | 局内稀有掉落、反哺 | 解锁高级建筑/产业 | 只显示 + GM 加减 |
| **钱财** | `resMoney` | `uint` | 市场卖出、事件 | 市场买入、招募 | 只显示 + GM 加减 |

> 资源是**单一数字**（不是物品），**不占格位**、不参与叠加规则。

### 3.2 物品与库存

| # | 规则 | 说明 |
| --- | --- | --- |
| R1 | 库存 = `itemId → count` 的堆叠列表 | 一种物品**只占一个格位**，数量累积 |
| R2 | 入库时若 `count + add > StackLimit` | **超出部分拒绝**（不溢出、不丢弃）；提示"已达叠加上限" |
| R3 | 入库时若该 `itemId` **不在库存里** | 需要**新占一个格位**；若无空位 → **拒绝入库**，提示"格位已满" |
| R4 | 出库（消耗/丢弃）到 `count = 0` | 该格位**释放**（种类减少 1） |
| R5 | 格位总数 = **基础 8 + Σ(`EffectType=2` 的格位效果)** | 例：家族树给 +2 → 总格位 10 |
| R6 | 总格位有**硬上限** | `Effect` 聚合后 clamp 到 **0~255**（`byte` 表达范围，见 `08_Effect_` §5.3） |
| R7 | 资源与库存**互不影响** | 资源数字不需要格位 |

### 3.3 **格位 vs 叠加上限（必须分清）**

| 概念 | 管什么 | 本作取值 | 满了会怎样 | 谁能改 |
| --- | --- | --- | --- | --- |
| **格位（Slot）** | **能放多少「种」物品** | **8**（基础） | 第 9 **种**物品**不能入库**（提示"格位已满"）；已有种类仍可继续叠 | 家族树（`EffectType=2`） |
| **叠加上限（StackLimit）** | **同一种能堆多少「个」** | **99**（默认，来自 `Item` 表） | 第 100 **个**同名物品不能入库（提示"已达叠加上限"） | 表（`Item.StackLimit`），个别道具可不同 |

**举例（务必按这个理解）**：

- 8 格、每格 99 → 最多 **8 种 × 99 个 = 792 个**物品。
- 只有 **1 种**物品但数量 500 → 最多存 **99 个**，其余拒绝（受**叠加上限**限制，与格位无关）。
- 有 **9 种**物品但每种只有 1 个 → 第 9 种放不进（受**格位**限制，与数量无关）。

> ❌ **常见误解**：「格位 8 就是最多 8 个物品」→ **错**。格位限制的是**种类数**，不是**个数**。

### 3.4 超出格位 / 叠加的行为（UI 与逻辑）

| 场景 | 行为 |
| --- | --- |
| 新种类 + 无空格位 | **拒绝入库**；提示"格位已满（8/8）"；**不自动丢弃已有物品** |
| 已有种类 + 数量超 `StackLimit` | 只加到 `StackLimit` 为止；超出部分**拒绝**；提示"已达叠加上限（99）" |
| 局内拾取（W3）时格位满 | 该掉落**无法拾取**（提示"格位已满"）；**不删除**地面掉落（可放弃） |
| 同时违反两条 | 先判格位（能否放下一种新物品），再判叠加 |

### 3.5 规则优先级

`格位判定（R3）` > `叠加判定（R2）` > `展示刷新`。即：新种类先要有格位，才谈叠加。

## 4. 数值与公式

| # | 数值 / 公式 | 含义 | 来源 | 取值范围 |
| --- | --- | --- | --- | --- |
| F1 | `BaseSlots = 8` | 库存基础格位 | **U3 裁决**（常量） | 固定 8 |
| F2 | `SlotBonus = Σ(EffectType=2 的 Value)` | 家族树给的格位加成 | `Effect` 聚合 | ≥0 |
| F3 | `TotalSlots = clamp(BaseSlots + SlotBonus, 0, 255)` | 总格位 | 计算 | `8~255` |
| F4 | `StackLimit` | 同名叠加上限 | **`Item.StackLimit`**（默认 99） | `1~999` |
| F5 | `已用格位 UsedSlots = 库存里不同 itemId 的个数` | 展示 `UsedSlots/TotalSlots` | 计算 | `0~TotalSlots` |
| F6 | 资源加减 | `res* = clamp(res* ± delta, 0, uint.MaxValue)` | GM/产出/消耗 | `0~4294967295` |

### 4.1 取整与边界

| 项目 | 规定 |
| --- | --- |
| 资源类型 | `uint`（**不减到负**；不足时拒绝消耗并提示） |
| 道具数量 | `int`（运行时）／落盘 `uint` 或 `int`（见字段规格；**不允许负数**） |
| 格位 | 整数 |
| 叠加上限 | 整数（表里 `uint`） |

### 4.2 调优入口

| 想调什么 | 改哪里 | 需重新导出 |
| --- | --- | --- |
| 基础格位 8 | **常量**（`BaseSlots`） | 否 |
| 单种道具叠加上限 | `Item` 表 `StackLimit` | **是** |
| 格位提升幅度 | `Effect` 表（`EffectType=2` 行的 `Value`） | **是** |
| 开局初始资源 | 存档初始化 / GM | 否 |

## 5. 状态与流程

### 5.1 入库流程

```
AddItem(itemId, count)
  ├─ 查 Item 表（不存在 → 报错返回失败）
  ├─ 若库存已有该 itemId：
  │    能加 = min(count, StackLimit - 已有数量)
  │    count -= 能加；已有数量 += 能加
  │    若 count > 0 → 提示"已达叠加上限"，返回失败部分
  └─ 若库存没有该 itemId：
       若 UsedSlots >= TotalSlots → 提示"格位已满（8/8）"，整体拒绝
       否则新占一格，能加 = min(count, StackLimit)，剩余同上提示
```

### 5.2 出库流程

```
RemoveItem(itemId, count)
  ├─ 库存无此物品 → 失败
  ├─ 数量不足 → 失败（不做部分扣除，是否允许部分由调用方决定）
  └─ 扣减后 count == 0 → 释放该格位
```

### 5.3 时序

| 顺序 | 发起方 | 接收方 | 动作 | 备注 |
| --- | --- | --- | --- | --- |
| 1 | GM / 掉落 / 商店 | 库存服务 | `AddItem` / `AddResource` | 统一入口 |
| 2 | 库存服务 | `SavePayload`（`res*` + **新增 `items` 列表**） | 写入 | 零迁移（只加字段/元素） |
| 3 | 库存服务 | 库存面板 / 资源栏 | 刷新显示 | 事件或轮询由程序定 |

## 6. 数据结构

### 6.1 运行时结构（不落盘）

| 结构 | 字段 | 类型 | 含义 |
| --- | --- | --- | --- |
| `ItemStack` | `ItemId` | `uint` | `Item.Index` |
| | `Count` | `int` | 数量（≤ `StackLimit`） |

### 6.2 存档映射（**与现有 `SavePayload` 对齐**）

| 存档字段 | 现状（实测） | 本系统怎么用 |
| --- | --- | --- |
| `resGoods` / `resMaterial` / `resBlueprint` / `resMoney` | **已存在**：`uint`（注释：货物/材料/图纸/钱币） | **直接复用**，语义 = 物资/材料/图纸/钱财 |
| **`items`** | ❌ **不存在** | **需新增**：`public List<ItemStackSave> items`，元素 `{ uint itemId; uint count; }` |
| 格位总数 | 不落盘（派生） | 由 `BaseSlots` + `Effect` 聚合算出；**不存**，避免两处真相 |

> **零迁移**：`items` 是**新增 public 字段**；老存档读进来是空列表（`new List<...>()` 初始化值），不报错。
> ⚠️ `JsonUtility` 硬约束：**必须 `[Serializable]` + public 字段**（属性会被静默丢弃）；**不要 `Dictionary`**（JsonUtility 不支持）→ 所以库存用 `List` 而不是 `Dictionary`。

## 9. 边界与异常

| # | 场景 | 期望行为 |
| --- | --- | --- |
| E1 | 库存为空 | 面板显示 8 个空格 + `0/8`；不报错 |
| E2 | `Item` 表为空 | 所有入库失败并记 warning；不崩溃 |
| E3 | 入库 `itemId` 不在表中 | 失败 + error 日志（配置错误，不静默） |
| E4 | 格位满 | 拒绝新种类；提示；已有种类可继续叠 |
| E5 | 达到叠加上限 | 拒绝超出部分；提示 |
| E6 | 资源被扣到负数 | 拒绝操作（不做负数） |
| E7 | 老存档无 `items` 字段 | 视为空库存，正常进入（零迁移） |
| E8 | `TotalSlots` 小于已用格位（例如家族树回退/效果移除） | **不删物品**；已用格位显示 `9/8` 并标红，新增被拒（§12 Q5 待确认处理策略） |
| E9 | `StackLimit` 被改小到低于现有数量 | **不截断**已存数量；只阻止新增，显示 `120/99` 标红 |

## 11. 验收标准（可测试）

| # | 验收项 | 判定方式 |
| --- | --- | --- |
| A1 | 4 资源显示 | 资源栏显示 4 个数字；GM "+10 物资" → 物资 +10 |
| A2 | 资源 clamp | 钱财为 0 时扣 100 → 操作被拒，仍为 0 |
| A3 | 入库/叠加 | 加 10 个药品 → 库存 1 格 `10/99`；再加 100 → 变 `99/99` 并提示上限 |
| A4 | **格位=种类数** | 连加 8 种不同物品 → `8/8`；加第 9 种 → **被拒**并提示"格位已满" |
| A5 | **已有种类不受格位影响** | 满格后继续加**已有**种类 → **成功**（叠到 99） |
| A6 | 格位释放 | 把某物品消耗到 0 → 该格腾空，`已用` 减 1，可再放新种类 |
| A7 | 扎营标记 | `IsCampItem=true` 的道具在格子上有角标；详情显示"扎营时可用" |
| A8 | 格位提升（预留） | 手动给一个 `EffectType=2` 的效果（`Index 1`，+2）→ 总格位显示 `10` |
