## 1. 本轮目标与替代范围

本轮将局内环境改为**有限连续地形＋手工结构**：统一网格内生成地表起伏、地下通道/洞室、建筑结构及可达路线，再填充战斗与内容锚点。三场景继续以地表、地下、建筑为主主题，使用既有MapPreset/MapBiome映射；默认地图均320×144，不引入新的时代/地形战斗倍率。

本文取代旧01文档中与“40×24整块房间占满地图、门洞拼接决定全部形状”冲突的本轮生成规则；旧方案与验收数字保留为历史。旧MapChunk等表不删除，手工结构仍可复用其资源定义；不能把旧拼接图的图连通报告当成新地图的角色可达验收。

| 参数行 | 既有预设 | 主题来源 | 手工建筑目标 |
| --- | --- | --- | --- |
| Id1 | 11 | MapBiome2／Surface | 1～2 |
| Id2 | 10 | MapBiome1／Underground | 0～1 |
| Id3 | 12 | MapBiome3／Building | 2～3，建筑偏重 |

其余参数三行相同。50列统一参数全部来自MapGeneration，不在另一个表/Inspector复制同一份权威值；字段与默认值完整列表见17字段规格。本轮不新增未消费字段。

## 2. 空间与可通行规则

| 规则 | 要求 |
| --- | --- |
| 单一空间 | 自然地形、结构、主路、碰撞与内容锚点使用同一张有界网格；1格按当前项目瓦片世界单位映射 |
| 边界与天空 | 地图宽320/高144；边距8；地表基准Y80，起伏幅度8，天空净空32；地下最低Y8。地形或内容不得越界 |
| 主路保护 | 入口至出口/通关目标及必要交互必须有角色可通过路线；洞穴平滑、结构覆盖与杂物放置不能破坏保护区 |
| 运动限制 | maxStepHeight=1、routeHeadroom=4、platformMinWidth=6、maxDropHeight=3。台阶上限不得高于当前玩家可跳高度；真实碰撞体/跳跃速度与落脚宽度均要纳入验证 |
| 缺口限制 | maxGapWidth=2只允许非必经野外段挖缺口；不能据此在受保护主路随机断地板 |
| 主路实际长度 | mainRouteMinLength=200、mainRouteMaxLength=600（float，世界单位）；在角色通行图上累计实际入口至出口主路的通行边长度。不是房间数、单纯地图宽度或全部支路长度，必须报告实际L及上下限验证 |
| 入口方向权重 | startOnRightChance=50（int，0～100）；0固定入口在左、100固定在右；其他值按独立layout/direction种子支线决策。右侧入口时镜像整图布局、结构、锚点及朝向，不只交换起点标签 |
| 支路与回环 | 支路数量1～3、目标长度20～60；loopChance=60仅对合法候选回连判断。能接上区域图不等于角色能跳过该连接 |
| 洞穴 | 目标深度24、通道8×8、洞室半径8、洞口2～3、平滑1次；不得挖穿地下下界、封死出口或侵蚀主路落脚面 |
| 结构 | Building池，最小间距16。结构地基、入口与自然地形须衔接；不能悬空、门前实体封堵或把必经路线盖住 |
| 区域兼容 | 用宽40～64的区域承接战斗/清房数据，区域不再等同40×24实体房块；旧消费者不得继续只用CellX×40/CellY×24推断真实区域/锚点边界 |

默认宽高总格数46080，小于maxTileCells=262144。此比较是静态配置核查，不是性能验收。

## 3. 生成顺序与责任边界

各阶段输出显式数据，再由装配阶段创建Unity对象。以下保留逻辑顺序与验收责任；当前已实现的类与内容扩展接口见§4.1，实际证据与最终收口见§8。

| 阶段 | 输出与约束 |
| --- | --- |
| 1 配置检查与请求 | 按当前预设取MapGeneration与主主题；校验尺寸/范围/预算，继承RunSeed/SceneSeed、场景序号、运行请求身份 |
| 2 自然地形 | 生成地表、地下实体/空气与洞室候选；不创建逐格GameObject；数据始终在有效边界内 |
| 3 路线与区域 | 规划入口/出口、必经走廊、战斗区域、安全区、支路/回环；标记受保护落脚面与净空 |
| 4 手工结构 | 从Building池选择结构，依地基与接口尝试放置；冲突时拒绝候选或有界重试，不强行覆盖保护区 |
| 5 统一可达验证/修复 | 在最终自然地形＋结构上检查角色站立/通行；最多repairMax次修复，仍失败则有界重试或明确降级 |
| 6 锚点预留 | 必要交互/出口优先保留；再分配NPC、敌人、杂物与装饰候选。统一检查站立面、实体占用、净空、安全区、间距及可达性 |
| 7 地图装配 | 以批量Tilemap/少量结构根装配地图，构建碰撞/边界；确保最终碰撞与数据一致后才能生成可活动角色 |
| 8 内容接口装配 | 先必要交互，再NPC与战斗角色，再杂物/装饰；使用已审核锚点，不各系统再次随机找任意地板。缺资源/跳过应返回原因，不影响后续合法点 |
| 9 发布与激活 | 当前布局/入口/区域/内容结果发布一次；读条完成后激活正式WorldScene；重复生成请求不能多出玩家、敌人或地图根 |

自然形状、结构、路线和内容使用由同一场景种子稳定派生的独立随机流。增加装饰数量不能改变主路、结构选择或敌人锚点；不使用Unity全局Random作为跨系统共享随机状态。排序与签名包含几何、结构和锚点，而不是只对旧Nodes/Edges做签名。

### 3.1 新管线读条阶段（MapLoading 9～21）

`MapLoading_地图生成读条表.xlsx`保留原Id/stage/sort=1～8及其五语言内容不变，新增9～21共13行。字段结构仍是8列：Id/stage/sort为uint，descCN/descTW/descEN/descJP/descKR为string；新行Id、stage、sort均等于下表阶段码。源表现A1:H27，共21条数据；本轮已由原Exporter统一导出为21行，不手改MapLoadingConfig生成类或Json。

| stage／Id／sort | descCN | 管线含义 |
| --- | --- | --- |
| 9 | 规划区域与边界 | 参数与有限区域规划 |
| 10 | 生成连续地表 | 自然地表计划 |
| 11 | 雕刻地下与连接通路 | 地下洞穴与通路计划 |
| 12 | 嵌入手工结构 | 结构候选嵌入计划 |
| 13 | 校验角色通行与生成锚点 | 真实角色通行规则与候选锚点检查 |
| 14 | 规划NPC、交互物与杂物 | 内容候选与占用规划 |
| 15 | 地图计划校验完成 | 数据级计划校验完成 |
| 16 | 创建地形瓦片 | Unity瓦片装配 |
| 17 | 落地手工结构 | 手工结构实例装配 |
| 18 | 建立地形碰撞 | 地形碰撞构建 |
| 19 | 创建内容占位物 | 内容锚点/占位实例装配，不等于完整NPC玩法已实现 |
| 20 | 场景地图校验完成 | 场景装配结果校验完成 |
| 21 | 局内地图就绪 | 当前场景地图具备激活条件 |

新13行的简中、繁中、英语、日语、韩语均已填写，无英文逗号/英文双引号/换行；源表保留旧表头、旧1～8行、列宽与旧数据格式，仅新增行适配翻译显示。已完成保存后重导入值/旧格式核查与五语言渲染检查；最终只读对照全部21行×8字段=168项零差异，其中新增13阶段×5语言=65条翻译完整且与Json一致；原表头与1～8数据仍保持。正式生成已走这些阶段，所有语言在LoadingScene逐阶段的显示仍需按程序报告区分，不把翻译齐全扩大成所有语言UI均验。


入口方向使用场景种子派生的独立`layout/direction`支线；其抽样不消费自然形状/结构/内容随机流。右侧入口以同一镜像轴变换地图实体/空气、受保护路线、结构坐标与朝向、区域边界、入口出口、内容锚点及角色初始朝向。镜像前后路线实际世界长度应一致，不能因入口左右改变难度倍率。50为抽样权重，不要求每批恰好一半种子入口在右。
## 4. NPC／杂物／交互生成接口

这些字段先规定**可供后续业务消费的锚点与占用契约**。npcCount=1、propCount=3、interactiveCount=1、decorationCount=24是目标点数，不代表本轮已经实现完整NPC对话、杂物掉落或可交互玩法。

| 内容 | 生成阶段与数据 | 消费要求 |
| --- | --- | --- |
| 必要流程交互 | 锚点预留最先保证入口/出口/目标所需站立面与接近区 | 不计入“随机点缺失可跳过”的低优先级内容；缺失导致图不可通关时必须失败/修复 |
| 交互候选 | interactiveCount目标1，保留可接近面、触发区域与后续对象占用范围 | 交互提供方接收候选，返回成功/资源缺失/冲突等结果；不能在入口前摆不可穿实体 |
| NPC候选 | npcCount目标1，使用可站立/可接近的安全点，角色活动范围与战斗区域分开标识 | 后续NPC系统只消费生成数据；没有NPC prefab时可保留锚点并记录未装配，不能记作NPC玩法通过 |
| 杂物候选 | propCount目标3，净空与碰撞范围不得侵入主路保护区/洞口/结构接口 | 杂物提供方必须报告实际占用与碰撞属性；若会阻挡，必须再次验证通过条件 |
| 敌人候选 | enemiesPerRegion目标2，按有效战斗区域分配；entrySafetyRadius=8内不刷敌人 | 战斗只消费该名单并登记实际成功数；不能仍按旧固定房间坐标再生成一套 |
| 装饰候选 | decorationCount目标24，最后分配，占用优先级最低 | 不阻挡路线；缺预算先减少低优先级装饰，不能挤掉必要流程点 |

统一候选至少能追溯：稳定ID、场景/请求身份、所属区域、类别、网格/世界坐标、占用范围、是否阻塞、优先级及被拒原因。这里是语义契约，不要求Excel新增嵌套字段，也不强制改变旧SlotType数字；新增NPC/杂物/交互类型时程序需提供显式映射，不能默默复用敌人或入口的类型值。

内容点先经全图占用表预留，再按确定顺序装配；必要点高于NPC/战斗与杂物，装饰最低。每次装配都可根据接口返回结果记录“目标数／候选数／成功数／跳过原因”，防止把预留点数量当成实际实例数。

### 4.1 当前已实现的数据与内容接口

| 实现 | 责任与现状 |
| --- | --- |
| NaturalMapParameters | 原MapGenerationConfig读入的同名参数快照，复制后生成；不反写源表 |
| NaturalMapPlan v2 | 有界Solid/Protected/Reachable、区域Regions/Connections、手工Structures、内容Placements、TagsAt查询、RouteParents与RouteTo可查询角色路线 |
| NaturalMapBuild | 独立随机流规划、有限尝试/修复、结构嵌入、内容占用与镜像；实际路线长从通行路径逐边累计 |
| NaturalMapAssembler | Tilemap连续野外/洞穴、手工Building实例、碰撞和内容占位物装配 |
| NaturalMapRuntime | 运行参数/真实角色能力读取、当前计划发布/Ready、预览/正式请求衔接；非法请求不得发布Ready |
| IMapPopulationPass | `StreamKey`、`Priority`、`BuildPlan(MapPlacementContext context, RunMapRng random)`；扩展消费独立population随机支线 |
| MapPlacementContext | Candidates按区域/Tags查站立候选，TryReserve统一校验稳定ID、范围、支撑、可达、保护区、占用、安全半径与间距；区域ID无效不能默默退为全图 |

当前预留顺序为玩家/AI/出口必要点→必需战斗区域敌人→内容Pass；内置Pass按Priority为NPC20、交互30、杂物40、装饰50，扩展按优先级及StreamKey稳定排序。这里的交互30是通用交互候选，不等于入口/出口必要流程点。实际放入实体杂物后重新校验通行与既有锚点可达，失败则撤销并在修复预算内换候选。

NPC与交互本轮仅有占位物/物理Trigger；杂物已有实体物理碰撞。完整对话、任务、杂物玩法或交互业务没有在本轮实现。战斗倍率继续按场景stage对应MapBiome读取，**不按角色当前所在Outdoor/Underground/Building区域动态换倍率**。

## 5. 预算、分帧与失败处理

| 参数 | 默认 | 处理要求 |
| --- | --- | --- |
| retryMax | 6 | 有界生成尝试；重试派生稳定种子，记录尝试次数与失败原因 |
| repairMax | 8 | 单次可达修复有界；不得不断挖掘直到看起来连通 |
| maxTileCells | 262144 | 分配前检查宽高乘积与溢出；超限直接报告配置错误 |
| maxContentObjects | 256 | 内容总预算，必要交互/流程点优先；记录被削减内容 |
| workColumnsPerFrame | 16 | 协程每帧推进列数上限；当前请求取消后停止后续装配 |
| frameBudgetMs | 5 | 只控制让出执行权，不由机器速度决定最终地图或降级分支；不是本机必定≤5ms的已验结论 |

失败必须报告配置/种子/阶段/尝试/修复/降级与原因。保底也要满足有限边界、入口到出口可达、角色净空和必要流程点；不能把旧“连通链式房间”无校验接入新连续图并当作同等结果。尺寸、外键、池不存在等配置错误与随机布局失败分别记录。

装配中切场景/重新生成必须取消旧请求并清理该请求的地图/内容根；后返回的协程不得覆盖新CurrentLayout或留下第二个玩家/敌人根。清理只作用于该次运行生成物，不动用户存档槽1。

## 6. 与现有玩法/MVP的接入

- 保留派遣、LoadingScene→WorldScene、3场景推进、胜败结算、事件、营地、HUD与当前会话槽位；TestScene仅作为独立调试入口。
- 新地图产出入口、区域真实边界与稳定内容锚点。PlayerSpawner、敌人生成、Ally房间判定、RunBounds/掉落死亡线、相机边界及清房推进必须消费这些数据，不能继续各自假定房间40×24/世界Y≥0。
- 自然图的数据生成/验证属于Model或RunMap数据层；Presenter负责流程意图与展示状态，View不承担地形业务计算。输入与设置继续走本轮MVP路径。
- 地形/阵营属性仍由既有MapBiome与FactionService决定；本轮不新增敌人倍率、不调整物品价格、事件奖励或Repeatable。
- 主地图生成期间不创建游戏存档事务；验证只用槽3，避免地图重试改掉runs/clears或重复发奖。
