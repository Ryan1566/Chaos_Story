## 1. 当前读写和续跑依据

| 环节 | 现有实现 | 本案后续补齐 |
| --- | --- | --- |
| 槽位读写 | `SaveSlotService` 从 `persistentDataPath/Saves/` 读 3 个 JSON 槽，先解析 `meta` 与 `payload`。缺 `payload` 时读档补默认对象。写入用同目录临时文件，再替换或移动为槽位文件。 | 统一识别格式版本及读档状态，显式校验与备份。现有 `TryLoad` 读取版本用于日志，尚无逐版本迁移分支。 |
| 配置读取 | 配置源表经现有导出器产出 C#、运行时 JSON 与 `ConfigTableIndex.json`。`ConfigLoader` 按 `ConfigTableAssets` 解析资源，缺失或解析错误会进入失败分支。 | 发布包记录配置版本与指纹。读取旧档后用目标配置校验持久业务 ID，配置不可用时保留原档。 |
| 局内检查点 | `ActiveRunSave` 的有效检查点记录格式、种子、出征序号、阶段、生成器版本、地图配置指纹、布局签名和局内状态。`RunCheckpoint.Validate` 校验检查点结构。`RunEncounter.ApplyCheckpoint` 比较生成器版本、地图配置指纹和布局签名，再恢复局内状态。 | 将旧档结构可读、局外状态可用、当前出征可续跑分别判断。地图不相容时提供明确恢复说明。 |

## 2. 迁移判定

| 类型 | 处理原则 |
| --- | --- |
| 旧档缺少追加字段 | 先用代表旧包实际写法的样例确认默认值。时代、深度和空列表按现有初始化和领域规则验证。村庄时钟需区分未存过与合法 `00:00`，编队需区分旧档缺字段与用户主动清空。用明确标记判断缺省语义。 |
| 字段重命名、类型或业务含义变化 | 只有实际发生不兼容变化时递增存档结构版本。按源版本到目标版本逐级迁移，版本标记与数据一起提交。缺 `payload` 的历史空壳单独识别。对已知版本不一致、未知旧版和高于当前支持版本分别提示，并保留原档。 |
| 业务 ID 变化 | 配置中的持久 ID 保持稳定。若确需换号，由策划与程序按对象类型及版本批准显式映射，覆盖道具、门客实例及模板、家族树节点、建筑、任务/选项、事件和世界地点。逐项验证数量、解锁、完成记录与归属，检查映射冲突及一对多等无法自动决断的情况。未有经批准规则的缺失 ID 暂停迁移。 |
| 局内状态兼容 | 同时核对检查点格式、出征标识和阶段、生成器版本、地图配置指纹、布局签名及恢复所需 ID。已进入结算但尚未提交的检查点同样验证。配置总指纹改变后可重新评估该档的局外与局内兼容性。 |

种子只能作为重建输入。若新生成器或新配置得出不同布局，保留原检查点和局外进度，提示使用与该档匹配的旧包恢复。以后如提供主动结束该次出征，需要另行确定扣除物品、返还、结算与奖励口径，经用户确认后才写入。直接更改指纹或清除 `activeRun` 会绕过已登记的扣除与领奖状态，不作为迁移路径。

## 3. 写入与恢复

1. 读取用户选中的槽位副本，区分空槽、可读、需迁移、格式不支持、损坏及暂时不可访问。列表预览仅查询状态。
2. 在内存副本完成版本转换、业务引用验证和检查点兼容判断。源档与迁移目标各自校验。需要重建场景时，先用禁止落盘的准备阶段完成恢复检查，准备失败返回可重试入口。
3. 核对所选槽位、目录和源档仍一致，先保留原始字节备份，再写同目录临时文件，回读校验后原子替换。场景准备与存档提交均成功后，再开放正式会话的操作和保存。重试从最近一次成功提交的文件开始，避免重复发奖、扣款或加出征次数。
4. 配置错误、迁移异常、文件锁、磁盘写入失败或场景准备失败时保留原始字节及失败诊断，清理本次准备状态。失败槽仍展示可识别状态，后续继续、导出或新建由用户明确选择。回退时使用匹配旧包和备份档，保持升级后的档案另存。

公司名或产品名改变目录时，路径迁移与存档结构迁移分开验证。按已登记的旧目录查找，向目标目录复制并校验，保留旧目录。目标槽已经存在时交由用户处理冲突。设置是否随旧目录导入由发布前确认，测试用独立目录。

## 4. 用例与发布检查

以下为待实施验收。使用合成档或已获授权的脱敏副本，逐项记录源版本、候选包、操作和结果。

| 用例 | 通过条件 |
| --- | --- |
| 新档、当前 v1 及早期 v1 缺字段 | 三个槽位能分别建档、读档、继续存档。旧有资源、建筑、成员和进度保留，追加字段默认值正确，午夜及空编队保持原意。 |
| 旧字段变换、ID 换号与缺失 | 有规则的转换保留数量和归属，已领奖及完成记录保持。关键 ID 缺失或映射冲突时给出可辨识原因，源档字节保持一致。 |
| 结构损坏、超前版本、配置缺失 | 档案可被识别为问题槽，提示原因。源槽及其他两个槽哈希保持不变。 |
| 锁盘、目标被改写、临时写入失败及再次加载 | 原槽和备份可用，失败可重试。成功后再读同一档无二次迁移，奖励、消耗、出征次数与结算均只计一次。 |
| 进行中出征和待结算恢复 | 同版本和指纹正确时恢复地图、背包、已击败敌人、已领取内容、任务与迷雾。待结算可继续原流程。修改生成器版本、地图配置指纹、布局签名分别触发续跑拒绝并保留检查点。 |
| 改名目录、槽位冲突与回退 | 新旧路径可在候选 Player 核对。来源、目标及冲突状态可识别，旧包能用原始备份恢复。 |

发布检查按候选包执行：

1. 核对应用与配置精确同号、三仓提交、运行时配置清单与指纹。核对源表经原管线导出的实际随包内容，以及这次支持的存档和检查点版本。发现来源、编号或指纹不匹配时停在候选阶段。
2. 用隔离档执行建档、读档、实体村庄、派遣、三图及结算返回，按兼容承诺覆盖旧档和出征恢复。保存用例、构建日志及回退证据。迁移尚未实施时，在内部记录列出已验证的兼容范围，其余旧档保留副本。正式发布需要相应的迁移验收或经确认的兼容范围。
3. 分别检查开发构建与正式构建。开发包用 `Ctrl+Shift+G` 打开 GM。正式包检查场景中无 GM 画布和测试入口，实机验证快捷键无效且正常玩家流程可用。若以后要求完全去掉 GM 专用程序集或资源，再单独增加包体清单检查。依据包内容和实机结果登记发布。
