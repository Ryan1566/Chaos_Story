## 1. 计划原则（来自用户原话）

| # | 原则 | 落地方式 |
| --- | --- | --- |
| P1 | **按概念案的重要性 + 易实现性划优先级** | §2 优先级表：重要 1~5、易实现 1~5，**双高先做**；单项极难（易=1）的提前"spike"拆小 |
| P2 | **每个功能都可以先在 `TestScene` 上做原型** | §5 TestScene 原型约定：**不切场景、表驱动、占位美术** |
| P3 | **不必按真实游玩流程顺序** | 波次按"依赖 + 可演示"排，而不是按"玩家从主菜单开始"排；例如局内地图（M8 的一部分）可以早于局外经营 |
| P4 | **数据与表现分离** | 一切数值/文案/配置**来自 `Excel/Chaos_excel/` 的表**；硬编码视为缺陷（§6 D3） |

**读法**：先做 **右上角**（重要高 + 易实现高）→ W0 全是 5/5、5/4；

## 3. 波次详情

> 每波统一给出：**目标 / 功能清单 / 依赖 / GM 演示路径 / 可测试验收 / 完成定义**。
> **GM 演示路径**的写法 = 从 GM 面板**点哪个分类 → 哪个版块 → 哪个按钮 → 看到什么**。
> 现有 GM 目录（2026-10-17 实测）：分类「界面」→ 主菜单面板 / 设置面板 / 存档面板 / 返回局外；「系统」→ 语言切换 / 日志与性能；「局内生成」→ 生成地图；「道具」→ 发放道具（预留）/ 背包·仓库（预留）。**W0 起在其上新增**。

### W0 地基（存档 / 进度 / 时代深度 / 原型场地与 GM）

**目标**：把"后面所有玩法都要挂上去的底座"先立起来 —— 能存进度、能推时代与深度、能在 TestScene 里用 GM 点出来。

| 项 | 内容 |
| --- | --- |
| 功能清单 | ① **M15**：`SavePayload` 扩字段（`era` / `depth` / 资源 / 库存 / 家族树节点 / 族人状态 / 计时器时间戳…）**只加字段不改语义**；② **M13/M13b**：时代推进（双门槛 + 单向）、深度 +1（**上限 = 当前时代序号**截断）；③ **`Era` / `Depth` 两张表**（规格见 `07_Era与Depth_字段规格.md`，`Depth` 共 25 行 = 5×5）；④ **TestScene 原型场地**（GM 入口 + 就地起面板/生成地图的骨架）；⑤ **GM 新增分类** |
| 依赖 | 无（这是所有波次的前置）；表结构依赖 `07_` 的字段规格 |
| GM 演示路径 | ① **存档与进度**：GM →「界面」→「存档面板」→ 点「打开存档面板」→ 选槽位「新建/读取」→ 观察 `era`/`depth` 显示；② **推进时代**：GM → 新增分类「**W0 进度**」→ 版块「**时代与深度**」→ 按钮「**写入测试进度**」（设 `era`/`depth`）→ 按钮「**推进时代（双门槛判定）**」→ 日志/面板显示"能否推进、差什么"；③ **深度截断**：同一版块 → 按钮「**深度 +1**」→ 在 `era=1` 时连点：**第 2 次起深度不再增加**（截断生效） |
| 可测试验收 | A1 存档里新增字段能落盘并读回（关掉 Play 再开，值还在）；A2 **老存档（无新字段）能读且新字段取初值**（零迁移，不报错）；A3 `era` 只能 1→5 单向推进，达到双门槛前推进被拒并给出原因；A4 `era=1` 时 `depth` 最大 **1**、`era=3` 时最大 **3**（截断）；A5 GM 新增入口**不需要改场景**（只改 `BuildCatalog()`） |
| 完成定义 | 见 §6 D1~D5（GM 能点出来 → 可观察 → 表驱动 → 落盘 → 无 Console error） |

## 5. TestScene 原型约定（**所有波次通用，硬约定**）

| # | 约定 | 说明 / 依据 |
| --- | --- | --- |
| T1 | **不切场景** | 原型阶段所有演示都在 `TestScene` 内完成；`EnterScene`（正式开局）/`WorldScene`（局内地图）/`LoadingScene`（读条）都不参与原型流程 |
| T2 | **就地用 RunMap 生图** | `RunMapBootstrap.BuildScene(uint runSeed, int sceneIndex, Transform parent, bool frameCamera = true)` 是 **public static**，GM 里直接调、把生成物挂到指定父节点即可；**TestScene 里目前没有 `RunMapBootstrap`**（实测 0 处引用），所以由 GM 按钮**运行时创建**（`AddComponent` + 传参）而不是改场景 |
| T3 | **面板走既有范式** | `UIManager` + `PanelType` + `Resources/UIPanels/<同名>.prefab`（例：`PanelType.WorldMapPanel` ↔ `Resources/UIPanels/WorldMapPanel.prefab`）。新面板 = 加一个 `PanelType` + 放一个同名 prefab，**不改 UIManager 逻辑** |
| T4 | **占位美术** | 使用现成切图：`Assets/Art/UI/**`（11 个分类目录：00_Panels…10_System）、`Assets/TileMap/{Kenney,Placeholder,RuleTile,Tile}`、`Resources/Prefabs/RunMap/` 的 **36 个** `Chunk_*.prefab`、TestScene 已有的 citizen 资源。**不因美术未就绪而等** |

| T6 | **同一 Unity 实例串行改码** | 只有一个 Unity 编辑器在线（2022.3.57f1c2，MCP 7890）；改脚本的人串行来，改完等编译回落（0 error）再验 |
| T7 | **新 `.cs` 用 UTF-8；改既有 GBK 按原编码写回** | `Scripts/` 是混合编码（GBK / UTF-8 BOM / 无 BOM）；乱码会让中文注释报废 |
| T8 | **GM 入口零成本** | 新功能一律挂在 `GMPanel.BuildCatalog()` 的 `GmSection` 下（标题 + 页面构建委托），**不需要动场景** |

## 6. 每波"完成定义"（统一口径 D1~D5）

一波只有**同时**满足下面 5 条才算完成：

| # | 完成定义 | 判定方式 |
| --- | --- | --- |
| **D1** | **GM 能点出来** | 从 GM 面板按 §3 的演示路径点得到，不依赖 Unity 编辑器里的手工操作 |
| **D2** | **可观察效果** | 屏幕上/日志里有明确可见的变化（数值、列表、对象出现/消失），而不是"代码跑过了" |
| **D3** | **数值与文案来自表 / 本地化** | 改表（或改本地化 key）→ 重跑导出 → 表现随之变化；代码里无硬编码数值/中文文案 |
| **D4** | **数据能存读** | 落盘字段进 `SavePayload`；退出 Play（或重进存档）后数据不丢；**老存档仍可读**（零迁移） |
| **D5** | **无 Console error** | Play 全程 `Console` 无 error；Unity 编译 0 error |

> **附**：每波结束需在 GM 里保留**可复现的演示入口**（不要"验完就删"），便于用户随时回看。
