## 1. 决策 A（核心）：加载形式 → **采纳 A：独立 `LoadingScene`**

### 1.1 C 不可行（确认 Lead 判断）
`LoadSceneAsync` + `allowSceneActivation=false` 的语义是「**资源加载完但场景不激活**」：新场景对象不跑 `Awake`/`OnEnable`、旧场景仍在。面板必须挂在目标场景的 Canvas 下 → 加载期间它**不可能可见**；等激活时加载早已结束，读条没有存在时机。**C 排除。**（按引擎语义判定；本轮无 Unity，未实测。）

### 1.2 A vs B 的具体代价

| 维度 | A. 独立 `LoadingScene`（**推荐**） | B. 常驻 Canvas（`DontDestroyOnLoad`） |
| --- | --- | --- |
| 新增资产 | 1 个场景 + Build Settings 2 条 | 0 个场景（但要在 TestScene 加一套 Canvas+EventSystem） |
| **常驻守卫** | 不需要 | **必写**；且 `TestScene` 是"回主菜单"场景、会被反复重载 → 漏守卫就**每次多一份**常驻 Canvas。工程里**没有现成范式可抄**：`SingletonMono` 不做 `DontDestroyOnLoad`，`SingletonAutoMono` 才是另一套 |
| **EventSystem** | 读条场景自带，随场景销毁 → 无残留 | 常驻 Canvas 要能点就必须常驻 `EventSystem`，**与目标场景自带的并存** → Unity 报 "Multiple EventSystems"/输入错乱；必须额外规定"目标场景不得自带 EventSystem"（**跨场景隐式契约**，脆弱） |
| **与 `UIManager` 纠缠** | 读条场景**不挂 `Entry`** → `UIManager.OnInit` 不跑，零纠缠 | `FindCanvas()` 是 `GameObject.Find("Canvas")`、`_canvas` 缓存在静态单例里；常驻 Canvas 叫 `Canvas` 会被抢，改名则要文档化"这是第二个 Canvas"；`PanelDic` 跨场景存活，读条 UI 若走 `UIManager` 会被缓存复用出过期状态 |
| 复用性 | **最好**：任何"菜单→世界/世界→菜单"都能复用同一场景 | 只在"已经身处 TestScene"时可用；从别处回菜单要依赖常驻对象仍在，链路更绕 |
| 交接尖峰 | 读条界面随场景销毁 → **盖不住激活尖峰**（见 §3 残余风险） | 可读条界面多留一帧盖住尖峰（唯一实质优势），代价是上面四条 |

### 1.3 A 的代价（含 Lead 未列的一条）
1. **`LoadingScene` 必须自带** `Canvas`（**名字不能叫 `Canvas`**）、`EventSystem`、一台相机；**不能挂 `Entry`**。证据：`UIManager.OnInit()` 会 `_canvas.Find("Base_BG").gameObject` → 读条场景没有 `Base_BG` 就 **NRE**；且 `Entry.Start` 会重复 `InputManager.Init()`/`SettingsManager.Init()`（`SettingsManager` 有 `_inited` 守卫，`InputManager` 没有）。
2. ⚠️ **读条界面没有本地化**（本轮新发现，见 §0 表）：`LocalizationManager` 随场景销毁。**取舍——推荐 (a)**：
   - **(a) 读条界面不放本地化文字**（用户要的就是"轮播图 + 进度条"，最多显示百分比数字）→ 零成本，**推荐**；
   - (b) 在 `LoadingScene` 自带一个 `LocalizationManager` 并挂同一份 `localizationData`（`Data/Localization/ChaosLocalizationConfig.asset`）→ 可行，需复制引用；
   - (c) 把 `LocalizationManager` 改成常驻 → 要动 `SingletonMono` 基类（影响 `DialogueManager` 等所有子类），**属独立改造，不在本任务**。
3. 读条界面在激活瞬间随场景销毁 → 无法用"多留一帧"盖住尖峰（若日后必须盖住，再补「DontDestroyOnLoad 读条 Canvas + 目标场景首帧后销毁」这个增量，**不要现在就做**）。

## 2. 决策 B：进度语义（精确公式）

```
未激活期：sceneReady = Mathf.Clamp01(async.progress / 0.9f)   // 激活前 progress ∈ [0, 0.9]
已设激活后：sceneReady = 1
assetsReady = 已完成 LoadAsync 的轮播 Sprite 数 / 请求总数   // 请求失败也算"完成"；无配表时 = 1
shown = Mathf.Max(shown, Mathf.Min(sceneReady, assetsReady))  // 单调不减，绝不回退
跳转条件 = shown >= 1 && sceneReady >= 1 && assetsReady >= 1 && 已渲染读条界面 >= 1 帧
          → async.allowSceneActivation = true
```

三个必须写死的细节：
1. **0.9 封顶**：激活前 `progress` 最大 0.9，所以要 `÷0.9`；但**设了 `allowSceneActivation=true` 后 `progress` 直接变 1.0**，此时再 ÷0.9 = 1.11 → 必须 `Clamp01`（或按"是否已设激活"分支），否则进度条会溢出。
2. **轮播图自己的 Sprite 也要计入 `assetsReady`**，否则会出现"条满了、背景还是空白"。
3. **请求失败的 Sprite 必须算"已完成"**（计入分子与分母）—— 否则 `assetsReady` 永远 <1 → **进度条停在 100% 之前、永不跳转**（最隐蔽的死锁）。

进度条实现建议用 `Image.fillAmount`（比 `Slider` 少一个组件与事件开销）。不做假进度、不做"最短展示时长"（用户要"立马进入"）。

## 4. 决策 D：场景加载入口归属 → **扩展 `ScenesLoadManager`，不复用事件**

- **同意 Lead**：在 `ScenesLoadManager` 新增 `public AsyncOperation BeginLoadSceneAsync(string name, bool activateOnComplete = false)`，内部 `SceneManager.LoadSceneAsync(name)` 并按需设 `allowSceneActivation = false`。**保持 `SceneManager` 调用集中在这一个类**；`LoadingController` 只消费返回的 `AsyncOperation`。
- 现有两个入口**保留不动**：`LoadScene`（1 处调用）、`LoadSceneAsync`（**0 调用**，实测；虽无消费者，删除属独立清理，不在本任务）。
- **不复用 `EventConstName.LoadProgress`**，三条理由：① `EventManager.Clear()` 会清空全部监听（`EventManager.cs:55-58`）→ 任何场景清理都会**静默**让进度条停死；② 单消费者直接持有 `AsyncOperation` 轮询即可，事件只增加一层间接；③ `LoadProgress` 与两个 `EventArgs` 现在就是 0 订阅/0 引用的死代码，复活它等于引入两条真相通路。→ **保留现状不动**（不删，也不接）。
- `GameSession` 需新增 **`TargetSceneName`**（实测现无此字段）：`SLPanel.EnterGame` 改为写 `TargetSceneName = "WorldScene"` 后 `LoadScene("LoadingScene")`；`LoadingController` 读它决定目标场景 → 这样 `LoadingScene` 对任意目标场景**可复用**。

## 7. 边界与失败模式

- **目标场景不在 Build Settings**：先用 `Application.CanStreamedLevelBeLoaded(name)` 预检；不通过 → `ChaosLog.Error` + 界面给出可见提示 + **不激活、不回退成黑屏**（保留读条界面或回主菜单）。**不要**直接调 `LoadSceneAsync` 等它抛。
- `GameSession.TargetSceneName` 为空 → Error + 回主菜单，不进入读条。
- 配表为空 / 全部 `srcImg` 无效 → **纯色兜底** + Warn，`assetsReady = 1`，照常跳转（不得卡死）。
- 单张 Sprite 加载失败 → 跳过该张 + Warn，并**计入已完成**（§2 细节 3）。
- 进度推进异常（`async` 为 null）→ Error + 不激活 + 恢复优先级。
- `backgroundLoadingPriority` 的恢复必须在**成功与异常两条路径**都执行。
- 复用：`LoadingScene` 不做"单例守卫"（每次加载都是新场景→新对象），但**不得**在其中放 `DontDestroyOnLoad` 对象。

## 8. 验收方式

1. Unity **0 编译错误**；改过 `.cs` 必须先 `AssetDatabase.Refresh(ForceUpdate)` 并等 `isCompiling` 回落再看（否则读到旧程序集）。
2. `EditorBuildSettings.m_Scenes` 含 **`TestScene` / `LoadingScene` / `WorldScene`** 共 3 条。
3. 主菜单 →「开始」→ 选档位 → **读条界面出现**（轮播背景 + 进度条）；进度**单调不减**、到 100% 后跳转。
4. 跳转后进入 `WorldScene` 并**不黑屏**（该场景有 Main Camera + Directional Light）。
5. 改一行配表 `srcImg` → 背景图随之变化（证明走的是配表路径，不是硬编码）。
6. 把 `LoadingTable` 配成空表 → 仍能正常跳转（纯色兜底）。
7. 临时把 `WorldScene` 移出 Build Settings → 给出明确 Error 且**不黑屏卡死**；**验证完立即恢复**。
8. 进入读条到跳转全程 `Profiler` 无单帧 > 16ms 尖峰（`WorldScene` 为空时应无）。
9. 手动把 `Time.timeScale` 置 0 → 读条仍推进（验证 §3 第 9 条）。
10. `Assets/Data/Records/` 内容不变（本次不应产生新的 `.record`）。
