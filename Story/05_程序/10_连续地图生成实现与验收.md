## 实现范围

正式入口继续为EnterScene→LoadingScene→WorldScene，三张图共用局种子，每张图由局种子、关卡、生成器版本派生随机流。默认硬边界320×144格，布局、地形、结构、内容均在界内规划。野外采用连续地表，地下采用洞道、洞室与入口，手工建筑继续复用当前结构资源。区域可以混合空间；遭遇区域独立于旧40×24房间块。战斗数值沿用当前关卡的MapBiome规则。

本轮不提交或推送Project_Chaos、Chaos_excel。旧地图文档中的冲突规则由本轮用户确认方案及22文档替代，未修改冻结的04_架构设计。

## 代码入口与生成顺序

| 文件（相对Assets） | 职责 |
| --- | --- |
| Scripts/Runtime/GameBase/RunMap/NaturalMapData.cs | 参数快照、区域、连接、语义网格、可达路径、放置请求及共享占用 |
| 同目录NaturalMapGenerator.cs | 有界规划、地表/地下/结构、角色通行检查与修复、内容计划、镜像、重试和保底 |
| 同目录NaturalMapRuntime.cs | 读取配置/结构资源、捕获玩家与门客运动能力、就绪状态和GM参数覆盖 |
| 同目录NaturalMapAssembler.cs | 计划落地、统一瓦片碰撞、地下背景、建筑实例及占位内容 |
| 同目录RunMapBootstrap.cs | 分阶段生成、读条消息、待激活地图移交、激活后物理复验和失败清理 |
| Scripts/Runtime/GameBase/ScenesLoader/LoadingController.cs | 生成期间逐帧刷新正式读条，失败进入正式恢复路径 |
| Scripts/Runtime/GameBase/Meta/RunSceneFlow.cs | 三图正式场景推进与生成失败回退 |
| Scripts/Runtime/Player/RunEncounter*.cs、PlayerSpawner.cs | 消费区域及放置计划；未就绪时不创建角色、不判清场 |
| Scripts/Runtime/GM/GMPanelNaturalMapPage.cs | 种子/尺寸配置及预览；不替代正式派遣入口 |

1. 校验参数、分配预算，读取实际角色能力和结构碰撞模板。
2. 规划有界地表、洞道、洞口及手工结构，分割语义遭遇区域，建立连接。
3. 扫描站立面，以角色体积、跳跃跨度、高度和下落约束构建通行图；修复通路并保护必要路线。
4. 按出生点/出口→NPC与敌人→交互物→实体杂物→装饰规划内容。每个实体杂物候选加入后重新检查通行，阻路则回滚换位。
5. 完成最终可达、支撑、净空、重叠、边界和数量检查；左右入口方向镜像整张计划，并复验主路长度。
6. 分批创建瓦片、结构、统一碰撞及静态内容。激活地图后同步物理、检查实际支撑，再消费角色锚点、启用相机及战斗统计。
7. 任意阶段失败记录明确原因并清理临时根节点；正式流程返回局外。保底生成也必须通过同样边界和通行检查。

配置指纹包括参数、角色能力、结构资源路径、权重和实际碰撞格。报告包含局种子、关卡、版本、指纹、尝试/修复次数、降级原因和实际主路长度。0是合法固定种子；未指定种子时单独创建局种子。第二、三图不再重新取当前时间。

## 放置接口与碰撞约定

扩展内容实现IMapPopulationPass，声明稳定StreamKey和Priority，通过MapPlacementContext.Candidates筛选支持面、净空、区域及语义标签，再调用TryReserve申请占地。从计划读取StableId、RegionId、Position（脚底锚点）、Facing、Footprint、ClearanceHeight等信息实例化。不要绕过占用记录另找随机坐标。

地形、布局、结构及不同内容类别使用独立随机流；稳定区域/锚点ID不依赖Unity实例ID。改变装饰数量不会移动地形及NPC。未知区域、越界请求、重复ID和重叠占地会被拒绝；实体占地写入最终实体网格并参与最终可达检查。

统一地形CompositeCollider使用整格碰撞，结构只保留美术并关闭重复瓦片碰撞及旧CameraBounds辅助体；玩家生成阶段不再批量关闭非瓦片碰撞体。NPC/交互占位物保留触发器，杂物使用已规划实体格；内容跟随本图根节点清理。地图范围、角色、触发器、地形职责分开。

算法留在地图领域层。MVP的Presenter/View继续负责正式界面的参数操作、事件和进度显示，不承担地形生成。

## 配置链路

MapGeneration_地图生成参数.xlsx包含3行、50列；MapLoading_地图生成读条表.xlsx追加9～21阶段文案。均通过原ConfigManager.ExportConfigs生成ConfigData和Runtime JSON，未手改生成文件。源表到JSON核对：MapGeneration共150项、MapLoading共168项（新增65条五语言文案）0差异，既有8行读条保持。

参数范围、默认值和限制见17字段规格。主路长度按实际通行边累计；方向0/100分别固定左/右出生；workColumnsPerFrame、frameBudgetMs只影响调度，不参与生成随机决策。

## 当前边界

- NPC、交互与杂物提供可验证占位物和生命周期接口，尚未加入完整NPC行为、任务或采集系统。
- 可达图使用保守体积/跳跃轨迹模型，配合真实玩家移动与碰撞验证；它不等于未来NPC的完整寻路执行器。
- 当前方向变化通过完整地图镜像实现；洞室、分支、回环和地形可随种子变化，尚非任意方向的世界级路线编辑器。
- Legacy MapLayout仅供兼容主题及诊断。新系统读取NaturalMapPlan及EncounterRegion，不再用CellX×40推导真实区域；旧编辑器房间工具仍用于旧结构资源维护。
- 未新增局中存档迁移、难度倍率或完整内容玩法。自然地形密度和美术仍可通过现有参数与结构池继续扩充。
