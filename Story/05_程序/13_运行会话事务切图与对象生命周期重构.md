## 2. 已核会话接口

主仓库路径：`Assets/Scripts/Runtime/GameBase/SaveManager/GameSession.cs`、`PrototypeSessionBootstrap.cs`及`GameBase/Meta/MetaProgressService.cs`。

| 接口/状态 | 已核实现 |
| --- | --- |
| SessionKind.None | 没有活动会话，SelectedSlot=0；CanCommit拒绝，没有默认真实槽3提交。 |
| SessionKind.Persistent | Begin(slot,payload,target)要求有效槽1～3及已读payload，捕获当时SaveSlotService.SavesDirectory；IsPersistent=true。 |
| SessionKind.Sandbox | BeginSandbox(initial)对传入payload做Json深克隆，未传则新建；SelectedSlot=0、无目录绑定，IsSandbox=true。这是内存会话，不是临时文件槽。 |
| ContextId/ContextChanged | Begin、BeginSandbox、有效Clear及Play重置时更新上下文代号；上下文改变清事件运行态、进度缓存/Boss标记及派遣选择等。 |
| CanCommit(out reason) | 无会话/无payload拒绝；正式会话槽非法或当前保存根与Begin时不符则拒绝，要求重新读档。 |
| SaveCurrent(out reason) | 先CanCommit；Sandbox成功为内存提交，不写槽文件；Persistent交SaveSlotService保存当前绑定槽，失败给原因。 |
| MetaProgressService.SaveSlot/SaveProgress | 只有Persistent返回选槽，其它为0；SaveProgress直接委托SaveCurrent，不再无会话落到槽3。 |

`PrototypeSessionBootstrap`在进入TestScene时显式开始Sandbox，避免继承正式玩家档的可写会话。BeginSandbox的克隆应保证原正式payload不被测试改动影响，需独立断言验证。命令执行期间Begin/BeginSandbox/Clear拒绝改变会话。

MetaProgressService仍保留无会话时用于读取/原型的内存payload；这不等于已经获得提交权限。读取默认值、内存变更、Sandbox提交与真实落盘须分开记录，不能只用HasSession或“保存成功”日志推断磁盘已写。

## 3. 已核统一命令接口

主仓库`Assets/Scripts/Runtime/GameBase/Meta/MetaCommandRunner.cs`：

```csharp
MetaCommandRunner.Execute(
    string command, Mutation mutation, out string reason,
    Action onCommitted = null, Action onRolledBack = null);
// Mutation: bool (out string reason)
```

同步路径先拒绝重入/空Mutation/不可提交会话，记录ContextId与payload身份，再捕获Json payload快照、BossClearedThisRun和UnityEngine.Random.state。Mutation返回true后校验上下文及载体未改变，再调用SaveCurrent；返回false、抛异常或保存失败则恢复payload、Boss标记与随机状态，使效果缓存失效，并执行回滚回调。最终通知在提交/回滚及局部回调完成后、仍持有IsExecuting保护时发布，最后才释放保护。每个Changed监听者独立捕获异常，递归通知受抑制；参数拒绝不通知。

回调用于处理payload外的运行态，不能把所有运行对象都假设能由Json快照恢复。事件队列/已解决结果、结算选择与Completed/PendingSave等必须逐项检查其提交/回滚时机。正式存储失败仍保留可见失败原因与原地重试，不能先关闭结果页再宣布未保存。

已核接入点如下，表示源码已接入，尚非运行通过或全仓覆盖结论：

| 消费者 | 当前接入与需要保持的语义 |
| --- | --- |
| VillageService | Execute统一Village命令；StartBuild/StartUpgrade/CancelBuild/Harvest公共API转入统一入口，避免只有UI按钮保存而其它调用绕过。 |
| MarketModel/MarketService | Model买卖委托服务；买卖事务需同时处理钱财与物品，保存失败不能留扣款或新增库存。 |
| RetainerRecruitmentModel | Retainer.Recruit命令；保留忙碌/同帧防重，失败返回id0，随机状态应回滚。 |
| EventService | Event.Choose/Complete命令；奖励与一次性标记同提交，成功后才登记结果/推进队列，失败保留当前事件。 |
| RunSettlementModel | Run.Settle命令；同时校验payload与ContextId，成功回调才设置应用/Completed，失败PendingSave待重试。同一payload重绑新会话也拒绝旧结算。 |
| DispatchService | Dispatch.Depart/Return统一保存；切图不能开始时CancelDeparture补偿提交，补偿失败明确报告，不假装已回退。Return失败恢复重伤幂等标记，不清理地图/玩家；IsInRun只读协调器。 |
| FamilyTreeService | FamilyTree.Unlock统一扣款、节点写入与保存；回滚同时使效果缓存失效，避免保存失败后属性加成残留。 |

提交边界已确定并实测：SaveCurrent成功后onCommitted抛异常只记错误，返回成功且不回滚已保存数据；onRolledBack抛异常不改变原失败原因。一个通知监听者抛异常不阻断后续监听。MetaRuntimeDriver按ContextId和payload共同隔离计时。连续计时和GM配置底层数据仍属于实时域状态，不能将命令事务描述为对所有内存字段或Unity对象的自动回滚。

## 4. 切图协调

验收要求为同一时刻只有一个有效切图请求；场景已加载不等于可玩Ready，必须由目标场景初始化/校验完成后发布。失败与取消要清理其临时对象和忙碌/目标状态，回可重试入口并保留仍有效的选择会话。旧请求迟到回调不得覆盖新请求、发布Ready或清掉新scope。

实现位于`GameBase/ScenesLoader/SceneTransitionCoordinator.cs`。TryBegin取得唯一Request（Id、ContextId、Target、Kind、SceneHandle）；Owns/IsCurrent/ReportReady/Fail/CancelActive校验请求身份。Phase覆盖Outside、Village、EnteringVillage、LoadingRun、Run、ReturningVillage、PrototypeRun和Cancelling。RunSceneFlow不再拥有第二份切图状态。

LoadingController登记AsyncOperation与PendingRoot，生成期间检查请求身份；激活回调只接管当前请求的地图。Unity不能中途取消已排队的LoadSceneAsync，因此取消后保持忙碌、放行激活以排空旧操作，再恢复入口，不允许新操作抢占。MainScene由VillageSceneBootstrap校验地形并初始化实体后报告Ready；WorldScene由RunSceneReadiness在Start之后检查已准备地图，再交RunEncounter接管。下一图不重复隐藏局外面板，避免覆盖原恢复列表。

同一正式会话的局内加载失败经返回村庄恢复；会话已退出则回EnterScene；村庄校验失败回存档界面，保留有效会话供重试。TestScene仍为编辑器原型入口，不加入正式构建列表。

## 5. 运行对象scope

清理按所有权而不是全局组件类型执行：A/B两个scope内即使挂相同角色/敌人/掉落组件，清理A也只能销毁A所属对象；持久相机/UI和B对象必须保留。Dispose需幂等，失败/取消后的迟到注册必须有明确归属处理；清理本身不应当作正常击杀产掉落、推进清场或触发结算保存。

`Player/RunObjectScope.cs`与RunObjectScopeMember提供Register、Owns、GetOrCreateRoot、DestroyOwned、Dispose。RunEncounter.Ownership持有阶段scope；地图容器、出生点、玩家、队友、敌人、掉落、边界和ticker按归属管理。父子关系内显式存在其它scope时，旧scope清理会先保留其它scope；重复Dispose为空操作，已释放scope拒绝注册。

清理立即停用对象/物理/回调，Play下帧末销毁。旧或外部敌人的回调不进入击杀与掉落。PrototypeMapSpawner只有清理自己当前容器时才可能清CurrentMapRoot，不清读条已发布的新地图。PlayerSpawner不再全局清AllyController或按名字隐藏citizen，相机仅在仍跟随本scope玩家时解除。RunEncounter.Clear本身不结算重伤；撤离重伤由Dispatch.Return保存事务负责。
