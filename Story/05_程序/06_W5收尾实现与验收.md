## 1. 范围与入口

本轮执行用户授权的1～7。正式入口保留 `EnterScene → LoadingScene → WorldScene`；TestScene 保留就地原型。只修改两张源表的四格文字，再执行 `ExcelTool/ExportExcelConfigs`；不改奖励、价格、时代门槛、地形倍率和Repeatable规则。M6独立局外战斗继续推迟。

正式流程：开始 → 槽位 → 局外地图 → 门客招募 → 派遣选1～4人 → 读条 → 三场战斗 → 结算 → 局外事件 → 局外地图。局外地图增加门客、库存、市场入口；招募调用现有规则，无新增费用或数值。

## 2. 模块与调用关系

| 模块 | 责任与接口 |
| --- | --- |
| `DispatchService` | 编队校验、runs与runTeam、当前槽位保存；TestScene调用原型，正式场景调用RunSceneFlow；拒绝重复出发 |
| `RunSceneFlow` | Loading/Active/Returning状态；传队伍与种子，订阅sceneLoaded并让出一帧，接管加载器已准备地图；返回原场景并恢复局外根面板 |
| `PrototypeMapSpawner.AdoptPreparedMap` | 接管RunMap_Pending容器；不重新生成第一场地图；后续场景与清理共用现有Spawn/Clear |
| `RunEncounter.cs`（360行） | 保留公开入口；负责生成时序与资源清理，try/finally释放重入保护 |
| `RunEncounter.Team.cs`（190行） | 队伍生命、倒地、观战、失败与伤病 |
| `RunEncounter.Rooms.cs`（126行） | 房间活体重算与场景推进 |
| `RunEncounter.Enemies.cs`（180行） | 地形、敌人生成、掉落；属性按场景汇总日志 |
| `RunEncounterTicker.cs`（25行）／`RunDropItem.cs` | 帧驱动／地面拾取对象，独立文件 |
| `MetaProgressService.SaveProgress` | 当前会话槽位保存；无会话测试使用槽3 |
| `EventService` | 奖励和一次性ID同次落盘；保存失败回滚完整payload；结果页覆盖恢复仍幂等；关闭成功才移队 |
| `MarketService`／`RunSettlementPanel` | 交易失败还原；胜败均保存，结算重试不重复入库或推进；弹事件前弹出旧结算页 |
| `GameplayText`／`GameplayLocalizationConfig` | 复用现有本地化，物品NameKey、市场、库存、事件与部分编队文案；73条简中/英语条目 |

库存、已用扎营次数、掉落种子属于整局，跨场景2/3保留，只在新局重置。地下地图合法房间可低至y=-72：旧固定死亡线-20会令敌人及AI误坠死。现敌人按房底减20，玩家及AI按整图最低房底减20；未修改`GameBase/RunMap/**`。

返回EnterScene时，重复LocalizationManager在父根被销毁前曾覆盖单例引用；Awake现优先保留常驻实例，避免回局外丢失词条。该历史GBK文件保持原编码。

Normify连接器本轮未提供工具。模块源记录补入`Assets/AI/normify-project-chaos/modules/project-chaos/bootstrap/w5-gameplay.md`；本记录是源码人工核对结果，未冒称执行normify编译/验证，也未伪造其生成物时间和收据。

## 4. 验证边界与后续

合成EventSystem/InputSystem事件不等于真人操作。三场清房使用既有GM击杀接口，接触伤害使用实际物理碰撞；因此链路结果不代表真人完整通关、战斗手感或发布质量验收。事件/交易结果等部分服务字符串及结算页仍是中文，其他语言本轮没有完整翻译验收。

数值审查见21报告：Era/Depth显示难度尚未进入敌人公式，阵营倍率全1.00，可重复1004存在循环获取奖励风险；依用户决定均保持，重复节奏以后再定。三个仓库均未提交或推送；Project_Chaos与Chaos_excel保留用户自行提交权限。
