## 1. 命名空间与程序集（**开工前必须先看，决定了你 using 什么、能不能引用 UnityEditor**）

| `DialogueSystem` | `DialogueRuntimeData`（`MVP/Model/`） |
| `TangLaoShi` | **废弃**：`GameBase/UIManager/OtherUIManager/` 下的 `UIManager`、`BasePanel` |

> ⚠ **同一个类名在不同命名空间下各有一份**：`UIManager` 与 `BasePanel` 都有「真的（全局命名空间）」与
> 「废弃的（`TangLaoShi`）」两份。`OtherUIManager/BasePanel.cs` 上有 `[Obsolete("该基类被废置", false)]`
> —— 注意 `error` 是 `false`，所以**误用不会编译报错，只出警告**，会静默失效。
> **规矩：永远用全局命名空间的 `UIManager` / `BasePanel`，永远不要 `using TangLaoShi;`。**

日志与本地化必须写全名或 using：

```csharp
using ChaosDebug;          // ChaosLog / LogChannel
using LocalizationSystem;  // LocalizationManager / LocalizedText / LanguageType
```

### 1.2 程序集（`.asmdef`）：**`Scripts/` 下没有任何 asmdef**

实测：`Scripts/` 下 0 个 `.asmdef`（只有 `Plugins/Spine*` 有自己的）。因此：

- `Scripts/Runtime/**` → 编译进预定义程序集 **`Assembly-CSharp`**（运行时程序集）
- `Scripts/Editor/**`（目录名恰好是 Unity 特殊目录 `Editor`）→ 编译进 **`Assembly-CSharp-Editor`**

**后果（这是真正的构建风险，不是风格问题）**：`Assembly-CSharp` 在**打包 Player 时不会引用 `UnityEditor`**。
所以 `Scripts/Runtime/` 里任何**不在 `#if UNITY_EDITOR` 里**的 `UnityEditor` 用法都会让 Player 构建失败。

实测全量扫描 `Scripts/Runtime/` 对 `UnityEditor` 的引用，只有 **1 处真实代码引用**：

| 文件 | 行 | 内容 | 是否受 `#if UNITY_EDITOR` 保护 |
| --- | --- | --- | --- |
| `Scripts/Runtime/GameBase/ConfigManager/Config/ConfigManager.cs` | **9** | `using UnityEditor;` | ❌ **没有**（该文件的 `#if UNITY_EDITOR` 从第 60 行才开始） |
| `Scripts/Runtime/GameBase/LogManager/LogBootstrap.cs` | 34 | `[UnityEditor.InitializeOnLoadMethod]` | ✅ 有（第 28 行 `#if`，第 39 行 `#endif`） |
| 其余 2 处 | — | 均为注释/字符串（`AudioManager.cs:34`、`ChaosLog.cs:166/194`） | 不构成引用 |

> **结论：`ConfigManager.cs:9` 的 `using UnityEditor;` 是当前唯一会打断 Player 构建的运行时污染点。**
> 本次任务**不修**（属清点与验证阶段），修复方案交架构师在 T5 排期。

## 2. EventCenter 家族（事件中心）

四个文件的分工：

| 文件 | 职责 |
| --- | --- |
| `EventCenter.cs` | 旧版事件中心 `EventCenter` + `IEventInfo` / `EventInfo<T>` / `EventInfo`。**已整体废弃** |
| `EventManager.cs` | **现行**事件中心 `EventManager` + 触发扩展类 `EventTriggerExt` |
| `EventConstName.cs` | 事件名常量（避免硬编码字符串） |
| `CustomEventArgs.cs` | 各事件的参数类型（`EventArgs` 子类） |

### 2.1 `EventCenter` —— **不可用**

```csharp

// EventCenter.cs:42
[Obsolete("该类未进行使用，请使用EventManager", true)]   // ← error: true

```

**实测证据**（反射读取特性）：

```
[EventCenter] found=True IsError=True
```

`IsError=true` 意味着**任何**对 `EventCenter` 的引用（哪怕 `EventCenter.Instance.AddEventListener(...)`）
都会产生 **CS0619 编译错误**，不是警告。→ **不要用它，用 `EventManager`。**

`IEventInfo` / `EventInfo<T>` / `EventInfo` 是 `EventCenter` 的配套类型，同样没有使用方。

**最小使用范式（可直接复制）**

```csharp
using System;
using ChaosDebug;

public class MyThing : MonoBehaviour
{
    private void Start()
    {
        // 1) 监听：handler 签名必须是 (object sender, EventArgs e)
        EventManager.Instance.AddListener(EventConstName.GetKeyDown, OnKeyDown);
    }

    private void OnKeyDown(object sender, EventArgs e)
    {
        if (!(e is InputArgs args)) return;      // 用 is 而不是 as，类型不对就提前返回
        ChaosLog.Info(LogChannel.Input, "按下 " + args.keyCodeValue);
    }

    private void OnDestroy()
    {
        EventManager.Instance.RemoveListener(EventConstName.GetKeyDown, OnKeyDown);
    }
}

// 2) 触发（两种写法等价）
this.TriggerEvent(EventConstName.SaveSetting, new SavingSettingEventArgs { a_settings = data });
// 等价于
EventManager.Instance.TriggerEvent(EventConstName.SaveSetting, this, new SavingSettingEventArgs { a_settings = data });
```

**实测结果**

```
[EventManager] OK AddListener+TriggerEvent hits=1(expect 1) removed2ndNoThrow=true
```

**注意事项**

1. **参数类型必须精确匹配**：`EventHandler` 是 `(object, EventArgs)`，所以事件参数类必须继承 `EventArgs`。
   `InputTest.cs:24` 的 `if (!(e is InputArgs args)) return;` 是标准写法。
2. **未注册的事件名触发不会抛异常**，静默什么都不发生 —— 排查"事件没响应"时先确认拼写与注册时机。
3. **`RemoveListener` 前必须确认事件名已存在**；传不同的委托实例（如 `x => {}` 两次）无法移除。
4. `Clear()` 会清掉**所有**事件，设计意图是切场景防泄漏 —— 但会连"常驻系统"的订阅一起清掉，
   别在场景切换时无脑调。
5. 触发扩展方法 `this.TriggerEvent(...)` 要求调用方在**实例方法的 `this`** 上下文里（`MonoBehaviour` 里可以直接用）。
6. **没有"事件是否存在"的查询接口**，也没有异常隔离 —— 某个监听者抛异常会中断后续监听者。

## 3. Singleton 三件套（**选错就是 NRE**）

| 基类 | 文件 | 约束 | 实例从哪来 |
| --- | --- | --- | --- |
| `SingletonBase<T>` | `SingletonBase.cs:6` | `where T : new()` | 首次访问 `Instance` 时 `new T()` |
| `SingletonMono<T>` | `SingletonMono.cs:6` | `where T : MonoBehaviour` | **不会自动创建**，靠 `Awake` 里 `instance = this as T`（即**场景里必须手动挂**） |
| `SingletonAutoMono<T>` | `SingletonAutoMono.cs:7` | `where T : MonoBehaviour` | 首次访问 `GetInstance()` 时 `new GameObject()` + `AddComponent<T>()` + `DontDestroyOnLoad` |

```csharp
public class SingletonBase<T> where T : new()
{
    private static T instance;
    public static T Instance { get { if (instance == null) instance = new T(); return instance; } }  // :9
}

public class SingletonMono<T> : MonoBehaviour where T : MonoBehaviour
{
    public static T GetInstance() { return instance; }        // :9  ← 没有懒创建
    protected virtual void Awake() { instance = this as T; }  // :17
}

public class SingletonAutoMono<T> : MonoBehaviour where T : MonoBehaviour
{
    public static T GetInstance()                              // :10
    {
        if (instance == null)
        {
            GameObject obj = new GameObject();
            obj.name = typeof(T).ToString();
            GameObject.DontDestroyOnLoad(obj);
            instance = obj.AddComponent<T>();
        }
        return instance;
    }
}
```

**实测**

```
[SingletonBase] ResManager.Instance stable=True
[SingletonMono] DialogueManager.GetInstance()=null(场景无实例) LocalizationManager.GetInstance()=null(场景无实例)
```

> ⚠ 这里的 `LocalizationManager` 为 null 是 **Edit Mode 不执行 `Awake`** 造成的，
> 不代表场景里没有它 —— 实测 TestScene 中该组件**存在**（`位于 hierarchy root，名为 LocalizationManager`）。
> `DialogueManager` 则是**真的不在场景里**（`total=0`）。

**注意事项**

1. **`SingletonMono` 的 `GetInstance()` 没有"找不到就创建"的兜底**，拿不到就返回 `null`。
   调用方**必须判空**（`SettingsManager.ApplyLocalization` 就是这么做的，拿不到只报 WARN）。
2. `SingletonMono.Awake` 是 `protected virtual`，**子类覆写时务必 `base.Awake()`**，
   否则 `instance` 不会被赋值 → `GetInstance()` 永远 null。
   `LocalizationManager.Awake`（`LocalizationManager.cs:29-33`）正确地调了 `base.Awake()`。
3. `SingletonBase<T>` **没有线程安全、没有 null 重置口**。静态字段跨场景存活，
   如果它内部缓存了 UnityEngine 对象（见 `MonoManager`），对象被销毁后就成了"僵尸引用"。
4. `SingletonAutoMono` 与 `SingletonBase` 都**不检查"是否已有实例挂在场景里"**，
   手工挂一个 + 代码再创建 = 两份实例。
5. `SingletonBase<T>` 的 `Instance` 属性**在非主线程调用也会创建实例**，接 Unity API 会抛异常。

## 4. MonoManager / MonoController（给非 Mono 类提供生命周期与协程）

```csharp
public class MonoManager : SingletonBase<MonoManager>          // MonoManager.cs:9
{
    public MonoManager();                                      // :13  ← 构造里就 new GameObject("MonoController")
    public void AddUpdateListener(UnityAction func);           // :24
    public void RemoveUpdateListener(UnityAction func);        // :33
    public Coroutine StartCoroutine(IEnumerator routine);      // :38
    public Coroutine StartCoroutine(string methodName, object value);  // :43
    public Coroutine StartCoroutine(string methodName);        // :48
}

public class MonoController : MonoBehaviour                   // MonoController.cs:8
{
    public event UnityAction updateEvent;                      // :10
    public void AddUpdateListener(UnityAction func);           // :27
    public void RemoveUpdateListener(UnityAction func);        // :36
    public void Clear();                                       // :41
    void Start() { DontDestroyOnLoad(gameObject); }             // :12  ← 只有 Play Mode 会执行
}
```

**最小使用范式（可直接复制）**

```csharp
// 非 MonoBehaviour 的普通类里，想每帧跑一段逻辑 / 起协程：
private void OnEnable()
{
    MonoManager.Instance.AddUpdateListener(Tick);
}
private void OnDisable()
{
    MonoManager.Instance.RemoveUpdateListener(Tick);   // ⚠ 必须成对，否则委托泄漏
}
private void Tick() { /* 每帧 */ }

// 起协程
MonoManager.Instance.StartCoroutine(MyRoutine());
```

**实测结果**

```
第一次调用: [ConfigLoader.LoadDataAsync] THROWS MissingReferenceException :
            The object of type 'MonoController' has been destroyed but you are still trying to access it.
后续调用:   [MonoManager] Instance obtained, type=MonoManager
            [MonoManager] AddUpdateListener OK
            [MonoManager] private controller field null=False (Unity-null aware)
```

**⚠ 这是一个真实的坑，务必读懂**

`MonoManager` 是 `SingletonBase`（普通 C# 对象，静态字段），但它在构造函数里
`new GameObject("MonoController")` 并把 `MonoController` 组件缓存进私有字段 `controller`。

- 这个 GameObject 落在**当前场景**里，只有 `MonoController.Start()` 被调用后才 `DontDestroyOnLoad`。
- **`Start()` 只在 Play Mode 执行**。所以在 Edit Mode（编辑器工具、批处理、非 Play 的自动化）里，
  该对象随时可能被销毁，而 `MonoManager` 的静态实例与 `controller` 字段**都不会被重置**。
- 之后每次 `MonoManager.Instance.xxx`（含 `ResManager.LoadAsync`、`AudioManager`、`InputManager`、
  `ScenesLoadManager.LoadSceneAsync`）都会抛 `MissingReferenceException`。

**本次任务实测复现过 1 次**（上表第一行），下一次调用（域重载后静态被清）恢复正常。

**对 task-6 的含义**

1. 业务代码里正常用（Play Mode）是安全的，因为 `Start()` 会 `DontDestroyOnLoad`。
2. **编辑器工具 / 非 Play 的自动化脚本里不要走 `ResManager.LoadAsync` / `MonoManager`**，
   会随机炸。这类场景改用 `Resources.Load` 同步读。
3. 若架构师要顺手加固：`MonoManager` 的 `controller` 应做 Unity-null 检查并在必要时重建。

**其他注意事项**

- `AddUpdateListener` **不去重**，同一个委托加两次会跑两次。
- 没有 `StopCoroutine` 转发方法，也拿不到 `MonoBehaviour` 引用 —— 需要停协程时
  得自己保留 `Coroutine` 句柄，但**没有 API 能停**（只能 `MonoController.Clear()` 清 update 事件，
  它管不了协程）。需要停协程的场合请用 `MonoBehaviour` 本体。

## 5. ResManager（资源加载）

```csharp
public class ResManager : SingletonBase<ResManager>                                  // ResManager.cs:8
{
    public T Load<T>(string name) where T : Object;                                  // :17
    public void LoadAsync<T>(string name, UnityAction<T> callback) where T : Object;  // :39
}
```

**行为要点（读源码 + 实测）**

- `name` 是 **`Resources` 相对路径，不带扩展名**，例如 `"UIPanels/MainMenuPanel"`。
- `Load<T>` 内部 `Resources.Load<T>(name)`：
  - **如果结果是 `GameObject`，会自动 `GameObject.Instantiate(res)` 并返回实例**（`ResManager.cs:20-24`）；
  - 其他类型（`TextAsset` / `AudioClip` / `Sprite` / `ScriptableObject`）**原样返回资产本身，不复制**。
- 找不到资源时 `Resources.Load` 返回 `null`，`Load` **不抛异常，直接返回 null**（实测）。
- `LoadAsync<T>` 走 `MonoManager.Instance.StartCoroutine`，因此**继承 §4 的 Edit Mode 坑**。
  它在 `yield` 之前先打印 `Warn("未寻找到该资源:" + name)`，但**之后仍会调用 callback**。

**最小使用范式（可直接复制）**

```csharp
using UnityEngine;

// 同步读配置文本（不会产生副本）
TextAsset ta = ResManager.Instance.Load<TextAsset>("Data/Json/Runtime/TestTableConfig");
if (ta == null) { /* 一定要判空！ */ }
var data = JsonUtility.FromJson<DataList<TestTableConfig>>(ta.text);

// 同步加载并实例化预制体（返回的是 Clone，已在场景里）
GameObject panel = ResManager.Instance.Load<GameObject>(GlobalPath.res_PanelPath + "MainMenuPanel");
if (panel == null) { /* 缺预制体 */ }
panel.transform.SetParent(canvas, false);

// 异步（回调可能拿到 null）
ResManager.Instance.LoadAsync<AudioClip>(GlobalPath.res_SoundPath + "牛叫", clip =>
{
    if (clip == null) return;
    source.clip = clip; source.Play();
});
```

**实测结果**

```
[ResManager.Load] correct path len=563 datas=4 first=张三
[ResManager.Load] missing asset -> null (no throw)
```

**注意事项**

1. **`Load<GameObject>` 一定会 Instantiate** —— 想拿"资产本身"（比如读预制体上的组件配置）不要用 `Load`。
   `UIManager` 早期就踩过这个坑（用实例名拼路径，实例名带 `(Clone)` 后缀必然失败），
   现在改成用枚举名拼路径（见 `UIManager.cs:170-175`）。
2. **没有卸载 / 引用计数 / 缓存管理**，完全依赖 `Resources.UnloadUnusedAssets()`。
3. `Load<T>` 的泛型约束是 `Object`，传基础类型编译不过。
4. **callback 可能收到 null**（`LoadAsyncFunc` 里 `res.asset` 为 null 时仍调 callback），
   所有异步回调第一行都该判空。
5. `LoadAsync` 每次都新起协程，**没有并发合并**；同一资源连点会重复加载。

6. `Clear()` **只是 `poolDic.Clear()`**，**不会销毁任何 GameObject**。池里的物体会留在场景里，
   但失去了管理 —— 切场景时若未 `Destroy` 会泄漏。用之前请确认架构师对池的生命周期有约定。
