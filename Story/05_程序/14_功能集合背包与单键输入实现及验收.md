## 1. 实现范围

本轮在既有局内菜单入口接入三页功能集合，实现四类物理背包、重要道具永久收藏、幂等扩格接口，以及单格键鼠绑定。队伍、局内地图、重要/工程/疗伤三类快捷选用均为占位；杂物不提供快捷选用。

本轮源表追加 `RunCategory`、`IsUnique`，保留旧 `Category`。现有 ID 1、5、6 配为疗伤加成，其余现有道具配为杂物；没有新增正式重要道具、工程道具或扩格奖励事件。验证脚本注入的临时道具只用于测试，不能当成正式内容。

## 3. 数据与接口约定

### 3.1 容量与运行时隔离

`RunBagSection` 顺序为 Important、Engineering、Recovery、Misc。初始容量分别为 0、1、2、5，硬上限为 5、7、7、30。容量读数按区间裁剪。物理背包属于当前 `GameSession.ContextId`；会话改变时清空运行时槽，避免跨存档泄漏。

永久字段为 `runImportantSlots`、`runEngineeringSlots`、`runRecoverySlots`、`runMiscSlots`、`runSlotGrants`、`ownedImportantItems`。它们独立于局外 `items` 和 `EffectType=2` 仓库扩格。

### 3.2 获得与永久收藏

`RunInventory.AddItem(uint itemId, uint count, out string reason)` 要求有效会话和已初始化背包，拒绝无效/禁用定义及零数量。普通堆叠超限时整次拒绝，不部分入包。重要道具先完成永久所有权保存，再尝试物理放置；满包时返回获得成功并给出收藏提示。

`InventoryService.AddItem` 对 `RunCategory=1` 不写普通仓库 `items`，而是登记永久收藏；在外层命令的变更阶段通过 `RegisterImportantInCommand` 加入当前事务。重要类型按 `Index` 唯一，即使调用时数量大于 1，也只保存一个 ID。

`TryCarryImportant` 将已拥有但未携带的收藏放入可用槽。`BeginRun` 尝试恢复所有重要收藏；未能放入的保留在 `GetUncarriedImportant` 返回列表。重要物品的移除入口拒绝消耗或出售。

### 3.3 整堆移动

`TryMove(from, fromIndex, to, toIndex, out reason)` 在写槽前校验地址开放状态、源物品和双方类型。杂物接受所有类型，专用行只接受对应 `RunCategory`。通过后同时交换两个引用，再发出变更通知；拒绝时两槽及数量均不改变。读取 `GetSlot` 和 `Stacks` 返回副本，调用方不能通过读取结果修改槽。

### 3.4 扩格与事务边界

`RunInventory.GrantSlots(section, amount, sourceId, out reason)` 是事件、剧情、养成可调用入口。区域必须有效、数量必须为正、来源必须非空。回执为 `区域编号:sourceId`，同一区域同一来源重复调用幂等；新容量不超过区域上限。

独立调用由 `MetaCommandRunner` 保存；外层玩法命令变更阶段合并到外层保存。`IsExecuting` 在提交和通知期间仍为 true，`IsMutating` 只在 mutation 执行时为 true。扩格和永久收藏不能在提交/通知回调中加入已经保存的命令。失败保存必须同时回滚容量、回执或永久所有权。

## 4. 输入与界面约定

输入资产的 Jump 键鼠路径仅有 `<Keyboard>/space`，不存在 Mouse 组第二触发器或 KeyboardFixed 固定空格触发器。Functions 默认为 Tab，Map 默认为 M。手柄动作保留独立绑定；Functions 的手柄默认路径为空，可单独设置。

键鼠页面保留一个可替换绑定格。该格重绑定允许键盘和鼠标按钮、排除手柄；移动的复合绑定按左移/右移拆成独立行。鼠标位置、移动、滚轮及 `anyKey` 不作为按钮候选。手柄重绑排除键盘和鼠标。页面关闭、切换和取消编辑须停止采集并恢复控件状态。

局内 Tab 打开/关闭功能集合，M 打开/切至集合地图页；局外村庄 M 打开/关闭世界观地图。UI、GM、重绑定等输入阻塞仍由原所有者控制。已移除固定备用键处理，清理输入管理器及单格绑定入口说明；旧预制体的备用空格提示隐藏，设置页无第二绑定按钮。历史设计记录不代表当前行为。

## 6. 审查问题与待补结果

### 6.1 首次市场购买重要道具

审查时 `MarketService.TryBuyCore` 用 `!added || countAfter <= countBefore` 判断入库失败；`GetCount` 只查普通仓库 `items`。重要道具获得只增加 `ownedImportantItems`，因此首次购买会被误判失败，外层命令退款并回滚收藏。

主代理已修复：`MarketService.GetCount` 对重要类型改读 `RunBagProgression.Owns` 并返回 0/1，原前后持有数增长判定因此适用于永久收藏；已拥有时拒绝重复收费的规则保留。文档审查已只读核对该实际代码变化。

同时已加入首次购买扣 3 钱财并永久拥有、再次购买及出售被拒且不扣款两条定向契约，当前 `contracts.txt` 已核对这两条 PASS。重要获得与扩格的磁盘失败回滚也有当前 PASS 记录；未单独注入市场保存失败，不能把这些记录扩写为该渠道全部故障分支均已执行。
