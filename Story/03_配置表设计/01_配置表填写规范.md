## 0. 三十秒速查（只记这 6 句）

1. 文件名 = `英文表名_中文说明.xlsx`，英文表名**全局唯一**、开头字母、无空格。放在 `Assets/Excel/Chaos_excel/`（**不要放子目录**）。
2. 只用一个页签（导出器只看第 1 个）。第 1 行写表名，第 2 行留 `是否读取 | IsConfig`（无人读，纯装饰）。
3. 第 3 行中文备注 → 变成 C# 字段注释；第 4 行英文属性名 → 变成字段名与 Json key，**每列必填、不可重复**；第 6 行类型只能从白名单里选。
4. **第 5 行每列都必须填**，只能填 `client` / `both` / `server`（小写）。填 `server` 的列会被**整列丢掉**（类里没有、Json 里也没有）。
5. **第 7 行就是第一条正式数据**（它不是"示例行"，会被真的导出）。数字列不能留空。
6. 表头 6 行 + 数据行，**中间不能有空列、表尾不能有空行**；字符串里**不能有英文逗号 `,` 和英文双引号 `"`**。

## 2. 表头 7 行（行号写死在导出器里，不可自行增删行）

```
         A          B           C          D          E
第1行   类名       TestTable                                    ← 装饰，导出器不读
第2行   是否读取   IsConfig                                      ← 装饰，导出器不读
第3行   序号       角色名称     职业       头像       速度        ← 中文备注 → C# 字段注释
第4行   Index      CharName    Occupation head_icon  speed      ← 英文属性名 → 字段名/Json key（必填）
第5行   client     client      client     both       server     ← 端标记（已生效，见 §4）
第6行   uint       string      uint       uint       float      ← 类型（白名单，见 §3）
第7行   1          张三        0          20001      1          ← 会被导出！见 §5
第8行起 …正式数据…
```

| 行 | 约定名 | 导出器是否读取 | 实证 |
| --- | --- | --- | --- |
| 第 1 行 | 类名 | ❌ **不读**。类名只由文件名推导 | `GetFileName()` 只对文件名 `Split('_')` |
| 第 2 行 | 是否读取 | ❌ **不读**。全代码无任何引用 | 只声明了 `remarkIndex/propertyIndex/endIndex/typeIndex/valueIndex` 五个行常量 |
| 第 3 行 | 中文备注 | ✅ 读 → 生成 C# 字段行尾注释 `//序号` | `GetRemark()` |
| 第 4 行 | 英文属性名 | ✅ 读 → 字段名 + Json key。**空则抛异常** | `GetProperties()`：空即 `throw` |
| 第 5 行 | 端标记 | ✅ **已生效**（与旧文档说法不同，见 §4） | `GetEnd()` 的结果在 `ExportClass` / `ExportJson` 中被用作过滤 |
| 第 6 行 | 类型 | ✅ 读 → C# 字段类型 + Json 转换分支 | `GetType()` + `Convert()` |
| 第 7 行 | 示例行 | ⚠️ **会被当作正式数据导出** | `GetValues()` 循环自第 7 行开始 |
| 第 8 行起 | 数据 | ✅ 读 | 同上 |

**列方向**：读取范围是 `第1列 ~ 最后一列`。**中间不能出现空列**——第 4 行为空会抛
「第4行第N列为空」，并且**中断整轮导出**（后面的表全部不导出）。

**行方向**：范围到 `Dimension.End.Row`。**表尾不能留空行**，空行会变成一条空数据对象。

## 3. 类型白名单（第 6 行）

### 3.1 只能用这 7 个

| 第 6 行填写 | 生成的 C# 字段类型 | 用途建议 | 示例值 |
| --- | --- | --- | --- |
| `int` | `int` | 普通整数（最常用） | `100` |
| `uint` | `uint` | 非负整数（ID、数量） | `20001` |
| `long` | `long` | 大整数 | `10000000000` |
| `ulong` | `ulong` | 大非负整数 | `100` |
| `float` | `float` | 小数（速度、倍率） | `1.5` |
| `double` | `double` | 高精度小数 | `1.5` |
| `string` | `string` | 文本、名称 | `张三` |

### 3.2 禁止填写（会失败）

| 禁止填 | 后果 |
| --- | --- |
| `bool` / `enum` / `DateTime` / `boolean` / `byte` / `short` 等白名单外写法 | 抛异常「不支持此类型: xxx」，**整张表导出失败** |
| `int32` / `int64` / `long long` | 转换器**接受**（不报错），但会把这几个字**原样**写成 C# 字段类型 → **生成的 C# 编译不过**，整个工程报错 |

> ⚠️ `int32` / `int64` / `long long` 是最阴险的一类：Excel 里一切正常，导出日志也显示成功，
> 直到 Unity 编译时才炸。**数字列统一用 `int` / `uint` / `long` / `ulong` / `float` / `double`。**

### 3.3 没有 bool 怎么办

用 `uint`（或 `int`）填 `0` / `1`，并在字段规格文档里写清 `0=否，1=是`。
**不要**填 `true` / `false` / `是` / `否`——白名单里没有 bool，会直接抛异常。

### 3.4 没有 enum 怎么办

主流做法：用 `uint` 存枚举数字 ID，并在**字段规格文档里手写一张「数字 ↔ 含义」对照表**
（样板见 `03_TestTable_字段规格.md` 的 `Occupation` 列）。不要指望表里能存枚举名。

| 第 5 行填写 | C# 类里的字段 | Json 里的键 | 策划感受 |
| --- | --- | --- | --- |

## 6. 单元格内容规则

### 6.1 字符串列（`string`）

| 规则 | 原因 |
| --- | --- |
| **禁止英文逗号 `,`** | 导出器用 `Json.Split(',')` 切分列值来组装对象，英文逗号会让行与列**错位**，破坏整张表的 Json |
| 需要停顿/并列时用**中文逗号 `，`** | 中文逗号是普通字符，安全 |
| **禁止英文双引号 `"`** | 导出器给字符串加引号时**不做转义**，值里的 `"` 会提前闭合字符串，破坏 Json |
| **禁止换行**（单元格内 Alt+Enter） | 同上，会写坏 Json |
| 允许：中文、英文、数字、空格、中文标点、`-` `_` `/` `%` `（）` | —— |
| 数字型文本（如"001"）请改用 `string` 并注意 Excel 不要吃前导零 | —— |

### 6.2 数字列（`int` / `uint` / `long` / `ulong` / `float` / `double`）

- **导出器对数字列不做任何合法性校验**：填 `待定`、`暂无`、`-`、`TBD`、`=公式` 都不会报错，
  而是**直接拼进 Json**，产生运行时解析失败的脏数据（或读到离谱的值）。
- 数字列**必须填纯数字**。还没定数就先留 `0`，并在字段规格文档的「待确认问题」里登记。
- `float` / `double` 可用小数点（用半角 `.`，不要用全角 `．`）。
- `uint` / `ulong` 是**无符号**类型，**不要填负数**（填了不会被拦，但语义上是错的）。
- **数字列不要留空**：空值会产出 `"Index":,` 这种非法 Json。
- Excel 的单元格若被设为「文本」格式，`1.0` 可能被读成字符串 `"1.0"`，`float` 列请用常规/数值格式。

### 6.3 表级自检

- 不要用**合并单元格**（跨列合并会让第 4 行属性名读到空值）。
- 不要在表头上方/下方写标题、说明、空行（第 1～6 行就是表头区，第 7 行起全部是数据）。
- 不要在同一张表里放两个逻辑表（拆成两个文件，注意 §1 的表名唯一性）。

### 7.1 空表/半空表的三段式（Lead 2026-10-05 实测裁定）

| 源表情形 | EPPlus `Dimension` | 导出器实际行为 | 对后续表的影响 |
| --- | --- | --- | --- |
| 页签**完全空白** | `null` | `:88`/`:124` → `NullReferenceException` → `:99` catch + `ChaosLog.Error` | **中断整批导出，其后所有表都不导出** |
| **只有表头**（1~6 行） | `End.Row = 6` | 通过 `:88`；`GetValues` 返回空 → `:205-209` 打日志「该表无任何导出项」后 `return` | **无影响，只跳过本表** |

## 10. 常见症状 → 原因速查

| 症状 | 最可能的原因 |
| --- | --- |
| Console 报「第4行第N列为空」 | 第 4 行有空格，或列中间有空列（L8） |
| Console 报「不支持此类型: xxx」 | 第 6 行写了白名单外类型（§3.2） |
| Console 报「路径不存在」 | 导出目录没预建（L7，找程序） |
| 导出成功但 Unity 报编译错误 | 表名非法 C# 标识符，或第 6 行写了 `int32`/`long long`（§3.2） |
| **部分表没有被导出** | 目录里有**页签完全空白**的表 → `Dimension` 为 `null` → **NRE 中断整批导出**（L1/§7.1，Console 有 `ChaosLog.Error`）；或文件名不是 `.xlsx`；或表在子目录里（L13） |
| Console 出现 `NullReferenceException`（导出时） | 源表目录里有一张**页签完全空白**的表（L1/§7.1）。**注意：只有表头没有数据的表不会报这个错**，它只在日志里留一条「该表无任何导出项」 |
| 某列数据在游戏里读不到 | 第 5 行填了 `server` 或**留空**（§4） |
| 某列的值永远是 0 / 空串 | 第 5 行留空（§4） |
| Json 解析失败 / 数据串行错位 | `string` 里有英文逗号（L3）、双引号或换行（L4） |
| 表里明明有数据，Json 里多/少一条 | 第 7 行被当成数据（§5）；或表尾有空行（L9） |
| 改了 Excel，游戏里数据没变 | 没重新执行导出菜单（运行时读的是产物，不是 Excel） |
| 表 B 覆盖了表 A | 两张表文件名前缀相同（§1） |
| 表填得没问题，但游戏里**一张表都读不到** | 已知 P0：运行时读取路径错位（Q4，程序侧缺陷）。**不是策划的填表问题**，交程序 |
