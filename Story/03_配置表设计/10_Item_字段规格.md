# `Item` 字段规格说明（道具表）

> 状态：评审中
> Owner：策划
> 最后更新：2026-10-29
> 关联：`Story/02_系统策划/06_资源与库存.md`（库存/格位/叠加规则）、`Story/03_配置表设计/08_Effect_字段规格.md`（效果表与叠加规则）、`Story/03_配置表设计/01_配置表填写规范.md`、`Story/03_配置表设计/02_配置表字段规格模板.md`、`Assets/Excel/Chaos_excel/Item_道具表.xlsx`

> **本表是道具"模板"**：库存里存的是 `{ itemId, count }`（`ItemStackSave`），`itemId` → 本表 `Index`。
> **当前增量（2026-10-29）**：现为12列（A～L），新增局内分类和唯一标记，权威补充见§11；以下W5的10列表头保留为历史基础，K/L按§11连续追加。重要收藏使用独立的`ownedImportantItems`，不占局外`items`格位。
> 一个道具要挂**多个**效果时**不要在本表加列**，走 `ItemEffect` 关联表（§4）。

> **两条硬约束（写给策划自己看）**
> 1. **顶层目录 `Assets/Excel/Chaos_excel/` 里任何一张表都必须 ≥ 1 行数据**（只有表头 = 空表）。只有表头 → 无导出项；**页签完全空白 → 抛异常并中断整批导出**，其后所有表都不导出。
> 2. **顶层同英文前缀只能有一张表**（`Item_A.xlsx` 与 `Item_B.xlsx` 会导出同一个 `ItemConfig` 并**静默互相覆盖**）。
> 3. 表头固定 **7 行**，**第 7 行就是第一条数据**；表尾不得留空行；第 5 行每列填 `client`；第 6 行类型只能取 **12 类型白名单**且小写。

### 3.1 开关型字段

| 字段 | `true` | `false` |
| --- | --- | --- |
| `IsCampItem` | 扎营类（只扎营时可用；库存显示角标） | 普通道具 |
| `Enable` | 允许入库/展示 | 跳过（保留行，便于临时下线） |

> `bool` 可填 `true`/`false`、`1`/`0`、`是`/`否`（不区分大小写，**不能留空**）；导出为**裸值** `true`/`false`。

### 3.2 `Category` 类别对照表（`uint` + 对照表，**不能用 enum**）

> ⚠️ **2026-10-22 订正**：实际 `Item_道具表.xlsx`（W5.3 落地）用的是 **`1` 药品 / `2` 材料 / `3` 装备 / `4` 图纸 / `5` 消耗 / `6` 其他**；本文原表（2 甲修 / 3 材料 / 4 图纸 / 5 装备）与实表**不一致**，已按实表改写。

| 值 | 类别 | 说明 | 典型用途 |
| --- | --- | --- | --- |
| `1` | 药品 | 恢复类消耗品 | 局内使用（W3） |
| `2` | 甲修 | 修复护甲/装备耐久 | 局内/扎营 |
| `3` | 材料 | 建造与制造原料（也可直接进资源） | 建造（W1b） |
| `4` | 图纸 | 解锁高级建造/产业 | 建造（W1b） |
| `5` | 装备 | 可升级/可带出的装备 | W3/W4 |
| `6` | 其他 | 剧情/事件道具 | W5 |
| `7+` | **预留** | — | ⚠️ 新增类别先登记再使用 |

> `Category` 只用于**分类展示与筛选**，**不驱动使用逻辑**（使用逻辑按 `EffectId`/局内规则）。新增类别属于接口变更，需同步本文档与 UI 图标映射。

## 4. 一个道具挂多个效果：`ItemEffect` 关联表（**W1 不建，先把列定死**）

> **为什么不能在本表加列**：导出器**不支持嵌套结构**（一格里塞不了数组），且"一个道具多个效果"数量不定 → 必须拆成"主体表 + 关联表"（与 `FamilyTreeEffect` 同一模式，见 `08_Effect_字段规格.md` §0/§4.1）。

| 行 | A | B | C | D | E |
| --- | --- | --- | --- | --- | --- |
| 第 1 行（装饰） | `类名` | `ItemEffect` | | | |
| 第 2 行（装饰） | `是否读取` | `IsConfig` | | | |
| 第 3 行 中文备注 | 序号 | 道具ID | 效果ID | 权重 | 是否启用 |
| 第 4 行 英文属性名 | `Index` | `ItemId` | `EffectId` | `Weight` | `Enable` |
| 第 5 行 端标记 | `client` | `client` | `client` | `client` | `client` |
| 第 6 行 类型 | `uint` | `uint` | `uint` | `float` | `bool` |
| 第 7 行起 | — | — | — | — | **正式数据** |

| 列 | 第 4 行 属性名 | 类型 | 含义 |
| --- | --- | --- | --- |
| A | `Index` | `uint` | 关联行唯一 ID |
| B | `ItemId` | `uint` | 外键 → `Item.Index` |

| D | `Weight` | `float` | 默认 `1`（与 `FamilyTreeEffect.Weight` 同义） |

> 等真的出现"一个道具多个被动效果"时再建 `ItemEffect`（结构与 `FamilyTreeEffect` 一致，可复用同一聚合器）。

## 5. 与存档 / 库存的关系

| 数据 | 在表里 | 在存档里 | 说明 |

## 6. **W1a 需程序新增的 `Effect` 行清单**（别自己编）

> 现状（实测）：`Effect_效果表.xlsx` **已建好 5 行**：
> `1 = 类型2/目标0/值2（格位+2）`、`2 = 类型3/0/1（带出上限+1）`、`3 = 类型5/0/1（解锁补员）`、`4 = 类型6/2001/-5（农田建造-5s）`、`5 = 类型4/目标1/值10（门客生命+10）`。

### 6.1 结论：**W1a 必需新增 = 0 行**

理由：本波用到的效果类型都已有行 —— ① 验收"格位可提升"用**现有 `Index 1`（类型2，格位+2）**；② 门客属性/信心上限用**类型 4**（现有 `Index 5` 是 `目标=1 生命`，信心上限是 `目标=5`，**W1a 不需要**）；③ `Item.EffectId` 本波**全部填 `0`**（道具没有被动效果）。

### 6.2 建议预留 3 行（`Index 6~8`，供 W1a 验收 / W1b 家族树直接用）

> 若程序建 `Effect` 表时需要补行，**按这张表填，不要自由发挥**（类型码语义见 `08_Effect_字段规格.md` §3.2）：

| `Index` | `EffectType` | `Target` | `Value` | `Note`（说明） | 用途 |
| --- | --- | --- | --- | --- | --- |
| `6` | `2`（格位） | `0` | `1` | `W1a 验收：格位 +1（验证格位可被提升）` | 库存验收 A8 |
| `7` | `4`（门客属性） | `5`（信心上限） | `10` | `W1a 验收：门客信心上限 +10` | 家族树（W1b）预留 |
| `8` | `3`（带出上限） | `0` | `2` | `W1a 验收：带出上限 +2（W3 用）` | 带出（W3）预留 |

> ⚠️ **`Note` 列禁英文逗号/引号/换行**；`Index` 必须从 **6** 起接现有 5 行（不要复用 1~5）。

## 8. 数据约束与校验规则

| # | 约束 | 违反后果 | 谁来把关 |
| --- | --- | --- | --- |
| C1 | `Index` 表内唯一、非空 | 库存取错道具 | 程序/策划 |
| C2 | `NameKey` / `IconKey` 非空；**禁英文逗号 / 英文双引号 / 换行** | 英文逗号会**破坏整表 Json** | 策划 |
| C3 | `Category` ∈ `1~6`（或已登记新值） | 未知类别 → 图标/筛选异常 | 策划 |
| C4 | `StackLimit ≥ 1`（默认 99） | 0 → 无法入库 | 策划 |
| C5 | `EffectId` 为 `0` 或**已存在**的 `Effect.Index` | 悬空外键 → 效果静默缺失（**导出器不校验外键**） | 策划 |
| C6 | `IsCampItem` / `Enable` **逐行填满** | 空值 → 导出期抛异常并**中断整批导出** | 程序/策划 |
| C7 | 同一 `EffectId` 若在 `ItemEffect` 与 `Item.EffectId` 同时表达同一效果 → **重复计算** | 属性/数量翻倍 | 策划（`策划建议`：二选一，别双写） |
| C8 | 表格行数 ≥1（顶层硬约束） | 空表 → 无导出项/中断整批 | 程序/策划 |
| C9 | `BuyPrice` / `SellPrice` 为 `uint`（**不能填负数/小数**）；`0` = 不可买/不可卖，两者都 0 = 该物品**不进市场列表** | 负数会变成超大数（危险） | 策划 |
| C10 | **卖价由表直接填**，约定默认 `SellPrice = floor(BuyPrice × 50%)`；**代码不计算卖价**（个别物品可例外） | 若代码自己算，表里改价就失效 | 策划/程序 |
