## 2. 列含义说明

| 列 | 填写规则 |
| --- | --- |
| 表名（英文前缀） | 文件名第一个 `_` 之前的英文段，即导出的 C# 类名前缀（`TestTable` → `TestTableConfig` / `TestTableData`）。**全局唯一**。 |
| 中文说明 | 文件名 `_` 之后的中文部分，只用于人工识别。 |
| 源文件 | **主仓库（Unity 工程）**相对路径，从 `Assets/` 起（配置表源表在 `Assets/Excel/Chaos_excel/`，**不在 `Chaos_Story` 仓库内**）。 |
| 用途 | 一句话说清"谁在什么时候读它、决定什么"。不要写"存放数据"这种废话。 |
| 导出模式 | `Config`（只读配置，进 `Resources/Data/Json/Runtime/`）/ `Data`（可写存档，进 `Data/Records/`）。见下方注意。 |
| 状态 | `草稿`（表结构还在改）/ `评审中` / `已定稿`（字段不再变，程序可依赖）/ `已实现`（程序已接入）。 |
| 字段规格文档 | 指向 `Story/03_配置表设计/` 下对应的字段规格文档；没有就写"待补"。 |

> **注意「导出模式」这一列的含义**：导出器提供的是**菜单级的两个批处理**——
> `ExcelTool → ExportExcelConfigs` 处理目录里**所有**表，`ExcelTool → ExportExcelModels` 同样处理**所有**表；
> `ExcelTool → ExportExcel` 则**两套都跑**。
> 也就是说**表本身没有 Config/Data 开关**，这一列表达的是这张表**意图给谁用**（只读配置，还是需要落盘的可写数据），
> 用于向程序说明用途，不要把"模式"理解成每张表可以各选一个。

## 3. 登记一张新表的步骤

1. 在 `Story/03_配置表设计/` 下按 `NN_表名_字段规格.md` 命名新建字段规格文档
   （`NN` 顺延：已有 `03_TestTable_字段规格.md` → 下一张用 `04_`）。模板见 `02_配置表字段规格模板.md`。

   （`Item_武器` 与 `ItemArmor_防具` 可以共存，`Item_武器` 与 `Item_防具` 不行）。
3. 按 `01_配置表填写规范.md` 在 `Assets/Excel/Chaos_excel/` 新建 `英文表名_中文说明.xlsx`。
4. 走完 `01_配置表填写规范.md` §9 的 **14 项**自检清单。
5. 字段规格文档与清单都更新为 `评审中`，交架构师/程序评审；定稿后置 `已定稿`。

> 原因是两种情形的实测行为（详见 `01_配置表填写规范.md` §7.1）：
> **页签完全空白** → `Dimension == null` → `ConfigManager.cs:88`/`:124` 抛 `NullReferenceException`，被 `:99` catch 后**中断整批导出**（会打 `ChaosLog.Error`，不是静默），该表及其后所有表都不导出；
> **只有表头无数据** → 不抛异常，仅在 `:205` 打一条「该表无任何导出项」日志后跳过本表。
> 即 `if (Dimension.End.Row == 0) return;` 这个守卫本身失效（空页签时 `Dimension` 为 `null`，永不为 0，`return` 分支不可达），应改为 `continue`。缺陷待架构师排期（`Story/00_索引.md` Q5 / B9 = 架构师 C11 / P1-4b）。
