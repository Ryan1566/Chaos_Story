# `WorldFaction` 字段规格说明（势力范围配置表）

> 状态：评审中
> Owner：策划
> 最后更新：2026-10-14
> 关联：`Story/02_系统策划/02_局外世界观地图系统.md`（§7 数据流、§9 势力清单与配色）、`Story/03_配置表设计/05_WorldMap_字段规格.md`、`Story/03_配置表设计/01_配置表填写规范.md`、`Story/03_配置表设计/02_配置表字段规格模板.md`、`Assets/Excel/Chaos_excel/WorldFaction_势力范围配置表.xlsx`

> ⚠️ **本表由「地图绘制工具」产出，不是策划手填**：工具按**5 个时期分别绘制**势力范围，导出 5 张**时期分表**；
> 使用者再**手工合并**成顶层这**一张** `WorldFaction_势力范围配置表.xlsx`。产出链路见 `Story/02_系统策划/02_局外世界观地图系统.md` §7。

> **三条硬约束（踩过的坑，必须先读）**
> 1. **顶层目录 `Assets/Excel/Chaos_excel/` 里任何一张表都必须 ≥ 1 行数据**（只有表头 = 空表）。只有表头 → 该表无导出项；**页签完全空白 → 抛异常并中断整批导出**，其后所有表都不导出。→ **顶层合并表必须至少有 1 行数据**。
> 2. **顶层同英文前缀只能有一张表**：`WorldFaction_A.xlsx` 与 `WorldFaction_B.xlsx` 会导出**同一个** `WorldFactionConfig` 并**静默互相覆盖**（不报错）。→ **5 张时期分表必须放在子目录**，顶层只留一张合并表。
> 3. 子目录 `Assets/Excel/Chaos_excel/_worldmap_tool/` **不参与导出**（导出器只扫顶层、不递归），所以分表可以放心用同名前缀。

## 3. 字段清单（逐列：本表的权威字段定义）

| 列 | 第 3 行 中文备注 | 第 4 行 属性名 | 第 5 行 端标记 | 第 6 行 类型 | 含义与取值 | 取值范围 | 示例 |
| --- | --- | --- | --- | --- | --- | --- | --- |

## 4. 键值 / 枚举字段对照表

### 4.1 开关型字段（`bool`）

> 导出后 Json 里是**裸值** `true` / `false`（**不加引号**）。
> **可填**：`true`/`false`、`1`/`0`、`是`/`否`（**不区分大小写**，前后空格自动忽略）；**不能留空**；其它文本**抛异常并中断整批导出**。

| 字段 | `true` 的含义 | `false` 的含义 |
| --- | --- | --- |
| `Enable` | 该**顶点**参与多边形绘制 | 该顶点**不参与**（保留行，便于临时剔除一个点调试） |

> ⚠️ `Enable` 是**顶点级**开关，不是"整块区域开关"。要整块区域下线，请按 `(Stage,FactionId,RegionId)` **整组**把 `Enable` 置 `false`（**策划建议**，避免只关一半导致多边形畸变）。

### 4.2 枚举型字段（`uint` + 对照表；**导出器不支持 `enum`**）

**`Stage`（时期，与概念案 §5.3 轴一一致）**

| 2 | 秦朝 |
| 3 | 秦末起义初期 |
| 4 | 楚汉争霸 |
| 5 | 汉刘邦时期 |

## 5. 多边形规则（本表的核心）

| # | 规则 |
| --- | --- |
| M1 | **一个多边形** = 同一条 `(Stage, FactionId, RegionId)` 下的所有 `Enable = true` 行，按 **`PointOrder` 升序**把 `(X, Y)` 依次连成**闭合**多边形 |
| M2 | 同一区域**顶点数 ≥ 3**；少于 3 个顶点的区域**不构成多边形** → 跳过并记 warning（不得崩溃） |
| M3 | `PointOrder` 从 **1 起连续**（1,2,3…）。跳号/重复 → 顶点顺序不确定（多边形自交/变形），**工具应在导出前拦截** |
| M4 | **飞地规则**：同一 `(Stage, FactionId)` 可有**多块不相连领地** → 用不同 `RegionId` 区分（本土建议 `1`，飞地 `2,3…`）；**每个 `(Stage, FactionId, RegionId)` 各自独立成多边形，顶点数各自 ≥ 3** |
| M5 | **不要求重复首点**：按 `PointOrder` 顺序连完**自动闭合**（工具产出约定需与此一致，见 §9 Q2） |
| M6 | 同一区域的 `Color` 应**每行一致**（逐行携带是数据结构使然）；不一致时**以该区域第一行为准**并记 warning（**策划建议**） |
| M7 | 多边形**不做自交/凹多边形校验**（凹多边形合法；自交会造成填充异常）——**策划建议**：工具给出自交提示但不阻断 |
| M8 | **同势力同色 + 按势力聚合**：同一 `(Stage, FactionId)` 的所有区域（含飞地）**`Color` 必须一致**（不一致由工具判 **Error 并阻止导出**，见 §6 C10）；运行时按 `(Stage, FactionId)` **聚合**判定归属 —— `RegionId` 只用于"分块绘制"，**点落在该势力任一区域内即属于该势力**；**两片之间的空隙不属于任何势力** |

**运行时归属判定口径（点查询 `TryGetFactionAt`）**

```
输入：点 p（归一化或世界坐标）+ 当前 Stage
  ├─ 遍历该 Stage 下所有 (FactionId, RegionId) 多边形
  ├─ p 落在任意一块内 → 返回该块的 FactionId（**不管落在第几块**）
  └─ 都不命中（含两片之间的缝隙）→ 返回「无势力」
```

| # | 口径 |
| --- | --- |
| R1 | `RegionId` **不参与**归属判定 —— 只用于"分块绘制"与"顶点分组" |
| R2 | 同势力的多块区域**等价**：点在 A 片内或 B 片内，结果都是**同一个 `FactionId`** |
| R3 | **两片之间的空隙不属于任何势力**（不是"按包围盒 / 最小凸包判定"） |
| R4 | 点**恰好落在边界上**的归属待确认（§9 Q8；**策划建议**按"含边界"处理，避免出现 1 像素宽的缝） |

**飞地（同势力多块）自检条目（3 条，可复现）**

| # | 自检项 | 判定方式 |
| --- | --- | --- |
| F1 | **同势力两块不相连区域导出正确**：给同一 `(Stage, FactionId)` 画两片不相连的领地，导出后两块的 `RegionId` 分别为 **(N, N+1)**，且两块的 `Color` **完全相同** | 复读顶层合并表：按 `(Stage, FactionId)` 分组，断言 `RegionId` 集合 = {N, N+1}、`Color` 去重后集合大小 = **1** |
| F2 | **运行时按势力聚合**：「时期 1 / 势力 1」查询返回 **2 块**区域，两块 `factionId` 相同、颜色相同 | 运行时按 `(Stage, FactionId)` 聚合后断言：块数 = **2**、`factionId` 全等、`color` 全等（接口名由程序定；口径见上方 R1~R4） |
| F3 | **三种取点分别得到正确归属**：点在 **A 片内** → 势力 1；点在 **B 片内** → 势力 1；点在 **两片之间的缝隙** → **无势力**（**不是**"就近归属"或"包围盒归属"） | 取三点分别调点查询：期望 `1 / 1 / 无势力`（`null` 或 `0`） |

## 6. 数据约束与校验规则

> 导出器**不做任何校验**。以下由**工具在导出前校验** + 策划人工把关。

| # | 约束 | 违反后果 | 谁来把关 |
| --- | --- | --- | --- |
| C1 | `Index` **全局唯一**；⚠️ **5 张分表合并后必须重新编号**（各分表都从 1 起会造成重复） | 重复本身不中断导出，但会让排查与后续按 Index 操作出错 | 工具（或合并时重编号）+ 策划 |
| C2 | `Stage` ∈ `1~5` | 未知时期数据永远不会被显示 | 工具 |
| C3 | `X`、`Y` ∈ `[0, 1]` | 顶点跑到图外 → 多边形被裁切/变形 | 工具 |
| C4 | **Y 向上**：`X = px / 图宽`、`Y = 1 - py / 图高`（`px`/`py` 以图片**左上角**为原点） | **算错 = 上下镜像**，整张势力图反了（最危险的一处） | 工具 + 程序（§9 Q1） |
| C5 | `Color` 必须是 `#RRGGBB`（7 字符）；**禁英文逗号 / 英文双引号 / 换行** | 英文逗号会**破坏整表 Json**；格式错 → 填充色异常 | 工具 + 策划 |
| C6 | 同一 `(Stage,FactionId,RegionId)` 顶点数 ≥3 且 `PointOrder` 连续 | 多边形缺失/变形 | 工具 |
| C7 | `Enable` **逐行填满**，不得留空 | 空值 → 导出期抛异常并**中断整批导出** | 工具 + 策划 |
| C8 | 顶层合并表**必须 ≥1 行数据** | 只有表头 → 无导出项；空白页签 → **中断整批导出** | 策划 + 程序 |
| **C10** | **同一 `(Stage, FactionId)` 下所有区域（含飞地）的 `Color` 必须一致**：工具**新建同势力区域时自动继承**该势力已有颜色；一旦出现不一致，**工具判 Error 并阻止导出** | 图上同一势力被画成**两种颜色** → 玩家会误认为**两个势力**（比"没画"更糟：信息错误） | **工具（Error 阻断）** + 策划 |

## 7. 维护流程（分表 → 合并 → 导出）

```
① 工具：按时期分别绘制势力范围
     Assets/Excel/Chaos_excel/_worldmap_tool/            ← 子目录：不参与导出，可同名前缀
        ├── WorldFaction_Stage1.xlsx   ← 时期 1（战国末期）★ 本次要产出
        ├── WorldFaction_Stage2.xlsx   ← 时期 2（秦朝）     内容待确认
        ├── WorldFaction_Stage3.xlsx   ← 时期 3（秦末起义初期）
        ├── WorldFaction_Stage4.xlsx   ← 时期 4（楚汉争霸）
        └── WorldFaction_Stage5.xlsx   ← 时期 5（汉刘邦时期）
② 手工合并（用户已确认手工合并）
     → Assets/Excel/Chaos_excel/WorldFaction_势力范围配置表.xlsx   ← 顶层：参与导出
        ※ 合并后把 Index 重新编号（C1）；表尾不得留空行；≥1 行数据（C8）
③ 程序执行 ExcelTool/ExportExcelConfigs
     → Resources/Data/Json/Runtime/WorldFactionConfig.json
     → Scripts/Runtime/MVP/Model/ConfigData/WorldFactionConfig.cs
④ 运行时：按存档当前 Stage 过滤 → 按 (FactionId, RegionId) 分组 → 按 PointOrder 连线成多边形
```

> **为什么分表放子目录**：导出器只扫**顶层**、**不递归子目录**（`01_配置表填写规范.md` §1 / L13），所以子目录里的分表不会参与导出、也不会与顶层合并表撞前缀（H2）。
> **为什么顶层只留一张**：`WorldFaction_A.xlsx` 与 `WorldFaction_B.xlsx` 会导出同一个 `WorldFactionConfig`，**后导出者覆盖前者且不报错**（H2）。
