# `FamilyTree` 字段规格说明（家族树节点表）

> 状态：评审中
> Owner：策划
> 最后更新：2026-10-17
> 关联：`Story/02_系统策划/08_家族树系统.md`（规则与 15 节点效果表）、`Story/03_配置表设计/13_FamilyTreeEffect_字段规格.md`（节点↔效果）、`Story/03_配置表设计/08_Effect_字段规格.md`（效果本体）、`Story/03_配置表设计/01_配置表填写规范.md`、`Assets/Excel/Chaos_excel/FamilyTree_家族树表.xlsx`

> **本表只管"节点是什么、前置是谁、点亮要花什么"**；**节点给什么效果**由 `FamilyTreeEffect` 关联表表达（**本表不带 `EffectId`**，见 §4 说明）。

> **两条硬约束（写给策划自己看）**
> 1. **顶层目录 `Assets/Excel/Chaos_excel/` 里任何一张表都必须 ≥ 1 行数据**（只有表头 = 空表）。只有表头 → 无导出项；**页签完全空白 → 抛异常并中断整批导出**，其后所有表都不导出。
> 2. **顶层同英文前缀只能有一张表**（`FamilyTree_A.xlsx` 与 `FamilyTree_B.xlsx` 会导出同一个 `FamilyTreeConfig` 并**静默互相覆盖**）。
> 3. 表头固定 **7 行**，**第 7 行就是第一条数据**；表尾不得留空行；第 5 行每列填 `client`；第 6 行类型只能取 **12 类型白名单**且小写。

### 3.1 `Board` 板块对照表（`uint` + 对照表，**不能用 enum**）

| 值 | 板块 | 本期给的效果方向 |
| --- | --- | --- |
| `1` | 影响力 | **带出上限**（1→10 的主来源） |
| `2` | 家族产业 | 建造时长 / **格位** / 收获产量 |
| `3` | 族人培养 | 族人生命 / 信心上限 / **解锁扎营补充减员** |

| `5` | 局内战斗 | 族人速度 / 格位 / 带出上限 |

## 4. 为什么本表**没有** `EffectId` 列（与任务清单的差异，**必须说明**）

任务清单建议的列含 `EffectId`（单效果）。本文**去掉**它，理由：

| # | 理由 |
| --- | --- |
| 1 | **08 文档已定"效果走关联表"**：`FamilyTreeEffect(Index/NodeId/EffectId/Weight/Enable)` 才是一对多的正确表达；两处同时写 `EffectId` 会**双写**，`08_Effect_` §C7 明确警告"同一效果被表达两次 → 数值翻倍" |
| 2 | 将来一个节点给**多个**效果时，本表加列塞不下（导出器**不支持嵌套**） |
| 3 | MVP 每节点恰好 1 个效果 → `FamilyTreeEffect` 就是 **15 行**，不增加维护成本 |
| 4 | 聚合只需读一张关联表，**只有一个入口** |

## 6. 数据约束与校验规则

| # | 约束 | 违反后果 | 谁来把关 |
| --- | --- | --- | --- |
| C1 | `Index` 表内唯一、非空 | 存档节点 ID 冲突 | 程序/策划 |
| C2 | 恰好 **15 行**、`Board` 1~5 各 3 行 | 板块页签数量不对 | 策划 |
| C3 | 同一 `Board` 内 `OrderInBoard` 为 1/2/3 且不重复 | UI 顺序错乱 | 策划 |
| C4 | `PrereqNodeId` 为 `0` 或**存在的 `Index`**；同板块内成链 | 悬空前置 → 该节点永不满足（E3） | 程序/策划 |
| C5 | **不能出现环**（A→B→A） | 两个节点都永远点不亮 | 程序（建议启动期检测） |
| C6 | 每个板块 `OrderInBoard=1` 的节点 `PrereqNodeId` **必须为 0** | 板块入口被锁 → 整板块不可达 | 策划 |
| C7 | `CostType` ∈ `1~4` | 消耗类型的资源找不到 | 策划 |
| C8 | `NameKey` **禁英文逗号 / 英文双引号 / 换行** | 英文逗号会**破坏整表 Json** | 策划 |
| C9 | 所有 `Enable` 逐行填满 | 空值 → 导出期抛异常并**中断整批导出** | 程序/策划 |
