# `Effect` 与 `FamilyTreeEffect` 字段规格说明（效果表 / 节点效果关联表）

> 状态：评审中
> Owner：策划
> 最后更新：2026-10-17
> 关联：`Story/01_企划/01_游戏概念案.md`（§6 M1/M3/M9/M10、§7 数值框架）、`Story/02_系统策划/04_功能开发计划与优先级.md`（W1 家族树 / 效果模型）、`Story/03_配置表设计/01_配置表填写规范.md`、`Story/03_配置表设计/02_配置表字段规格模板.md`、`Assets/Excel/Chaos_excel/Effect_效果表.xlsx`、`Assets/Excel/Chaos_excel/FamilyTreeEffect_节点效果表.xlsx`

> **这是跨系统基石**：家族树节点、建筑、道具将来都靠"**一个主体挂多个效果**"表达。
> 先定这张表，再动 M3（家族树）——否则每个系统各造一套效果表达，后期无法统一聚合。

## 0. 为什么必须"拆表"（背景，先读）

| 约束（工程事实） | 后果 | 结论 |
| --- | --- | --- |
| 导出器**不支持嵌套结构**（一格里塞不了数组/对象） | "一个节点挂 3 个效果"无法写在一行里 | **必须拆成"主体表 + 关联表"**（一对多）|
| 导出器**不支持 `enum`** | 效果类型不能用枚举名 | 用 `uint` **类型码 + 对照表**（§3.2）|
| 字符串单元格**禁英文逗号 / 双引号 / 换行** | 若把效果写成 `+2格位,+1带出上限` 这类文本，**英文逗号会破坏整表 Json** | **禁止**用文本拼效果；一律拆行 |

> **反面例子（不要这样做）**：`FamilyTree` 表里写一列 `Effects = +2格位,+1带出上限` ——
> ① 英文逗号会**破坏整表 Json**；② 运行时还要自己解析字符串（脆弱、无类型校验）；③ 无法做"效果叠加"的统一聚合。
> **正确做法**：`Effect` 存效果本体，`FamilyTreeEffect` 存"节点 → 效果"的多对多关联。

### 3.2 `EffectType` 类型码对照表（`uint`，**不能用 enum**）

| 值 | 效果类型 | `Target` 含义 | `Value` 单位 | **叠加规则**（见 §5） | 来源 |
| --- | --- | --- | --- | --- | --- |
| **1** | 资源产出 | 资源条目 ID（将来资源表主键） | 数量（整数；负值 = 消耗） | **相加** | 用户/批准计划 |
| **2** | 格位 | `0`（无目标） | 格位数（整数） | **相加** | 用户/批准计划 |
| **3** | 带出上限 | `0`（无目标） | 件数（整数） | **相加**（最后 clamp 到 1~10） | 用户/批准计划 |
| **4** | 族人属性 | 属性 ID（1 生命 / 2 攻击 / 3 防御 / 4 速度 / 5 信心上限） | 属性点（整数，可负） | **相加** | 用户/批准计划 |
| **5** | 解锁补充减员 | `0`（无目标） | `0`=未解锁 / `1`=解锁 | **取最高**（0/1 语义：任一为 1 即解锁） | 用户/批准计划 |
| **6** | 建造时长 | 建筑 ID（将来建筑表主键） | **秒**（**负值 = 缩短**） | **相加**（最后 clamp 到 ≥1 秒） | 用户/批准计划 |
| **7** | 收获产量 | 产业/建筑 ID | 产量（整数） | **相加** | **策划增补（已登记）** |
| **8** | 概率 / 成功率 | 场景类型 ID（如护送/事件） | **整数百分比 0~100**（正负均可，如 +10 = +10%） | **相加**（最后 clamp 到 0~100） | **策划增补（已登记）** |
| **9+** | **预留** | — | — | — | ⚠️ **新增类型必须先在本表登记 + 同步程序**，然后在表里才能用 |

> ⚠️ **新增 `EffectType` 是接口变更**：必须同时改三处 —— ① 本文档 §3.2；② 程序聚合实现（`switch` 分支）；③ 若涉及新目标表，还要登记对应外键表。**不要在表里先填 `9` 试**（会静默失效或抛异常）。

### 3.3 `Target` 的语义（按 `EffectType` 分派）

| `EffectType` | `Target` 填什么 | 当前是否已有目标表 |
| --- | --- | --- |
| 1 资源产出 | 资源条目 ID | ❌ 资源表未建（先用占位 ID，`策划建议` 1001 起） |
| 2 格位 / 3 带出上限 / 5 解锁补充减员 | `0` | 无目标，固定填 0 |
| 4 族人属性 | 属性 ID（1~5，见上表） | 属性为**固定枚举语义**（≤5，随代码），不需要表 |
| 6 建造时长 / 7 收获产量 | 建筑 / 产业 ID | ❌ 建筑表未建（先用占位 ID，`策划建议` 2001 起） |
| 8 概率 / 成功率 | 场景类型 ID（待定） | ❌ 待定 |

> **`Target` 是外键但不是强校验项**：导出器**不校验外键**，运行时通常只做查表；填错 → 效果静默无效（不报错）。**由策划人工把关**（见 §6 C7）。

| 将来新增 | 表名 | 列（与本文同构） |
| --- | --- | --- |
| 建筑效果 | `BuildingEffect` | `Index` / `BuildingId`(外键) / `EffectId`(外键) / `Weight` / `Enable` |

## 5. 效果叠加规则（**运行时聚合照此实现**）

### 5.1 三类叠加语义

| 类别 | 规则 | 适用 `EffectType` | 理由 |
| --- | --- | --- | --- |
| **增量型（Additive）** | **相加**：`Σ(Value × Weight)` | 1 资源产出、2 格位、3 带出上限、4 族人属性、6 建造时长、7 收获产量、8 概率 | 多个来源应该累积；加法可预期、好调参 |
| **上限/解锁型（Cap/Unlock）** | **取最高**：`max(Value)` | 5 解锁补充减员（0/1） | 布尔语义：任一来源解锁即解锁，重复给不会叠成 2 |
| **覆盖型（Override）** | **取最后**：按 `Effect.Index` **升序**，**后者覆盖前者** | 目前**无使用**（预留） | 用于"某来源替换基础值"；必须按 Index 定序才有确定性 |

### 5.2 聚合公式（程序按此实现）

```
给定主体（节点/建筑/道具）集合 S，以及基础值 Base：
  for 每个 EffectType：
     增量型： result = Base + Σ( e.Value * e.Weight )        （e ∈ S 且类型匹配且 Enable）
     解锁型： result = max( 0/1 of each e.Value )            （任一为 1 → 1）
     覆盖型： result = 按 Effect.Index 升序取最后一个非空值
  clamp 到该属性的硬范围（见 5.3）
```

### 5.3 硬范围 clamp（**必须做，否则会出现离谱数值**）

| 属性 | 硬范围 | 依据 |
| --- | --- | --- |
| 带出上限 | **1 ~ 10** | 概念案：初始 1 → 满级 10 |
| 格位 | **0 ~ 255** | `byte` 可表达范围（规范 §3.1 类型上限） |
| 资源数量 | **0 ~ 42 亿** | `uint` 上限 |
| 建造时长 | **≥ 1 秒** | 0 或负数会导致无法完成 |
| 概率 / 成功率 | **0 ~ 100** | 整数百分比 |
| 信心 | **0 ~ 100** | 概念案 §7 |

> clamp 发生时要**记 warning**（不是静默截断），便于发现"叠加过头"的配置错误。

### 5.4 生效范围（与概念案一致）

| 效果来源 | 何时生效 | 何时失效 |
| --- | --- | --- |
| 家族树 / 建筑 / 道具（局外常驻） | 局外**永久** | 不失效（除非节点被重置） |
| 局内非消耗加成（信心/数值/buff） | **局内生效** | **回局外失效**（概念案原话） |
| 反哺带出物 | 带出后进入局外库存 → 按物品类型生效 | 消耗型用掉即失效 |

## 7. 数据约束与校验规则

| # | 约束 | 违反后果 | 谁来把关 |
| --- | --- | --- | --- |
| C1 | `Effect.Index` 表内唯一、非空 | 关联取错效果 | 程序/策划 |
| C2 | `EffectType` ∈ 已登记类型码（1~8，或经登记的新值） | 未知类型 → 运行时跳过并记 warning | 程序 + 策划 |
| C3 | `Value` 不得留空；整型语义的效果请填整数 | 空值 → 导出期抛异常并**中断整批导出** | 程序/策划 |
| C4 | `Note` 禁英文逗号 / 英文双引号 / 换行 | **英文逗号会破坏整表 Json** | 策划 |
| C5 | `FamilyTreeEffect.EffectId` 必须存在于 `Effect.Index` | 外键悬空 → 效果静默缺失（导出器不校验） | 策划（§8 Q5） |
| C6 | 同一 `(NodeId, EffectId)` 不重复 | 同一效果被算两次 → 数值翻倍 | 程序（可校验）+ 策划 |
| C7 | `Target` 若指向未建的表（资源/建筑），先按占位 ID 段 `1001+` / `2001+` | 将来建表时要重编号，成本高 | 策划（**策划建议**：先定 ID 段约定） |
| C8 | 所有 `Enable` 逐行填满 | 空值 → 导出失败 | 程序/策划 |
| C9 | `Weight` 默认 1；非 1 值时必须在 `Note` 写清用途 | 聚合口径不明确 | 策划 |
