## 1. 一句话概述

玩家扮演一名**秦国的官吏**，拖家带口来到秦赵边境的一座小村庄；在村外山洞中的**传送阵**上，派出最多 4 名族人进入**边缘空间**进行肉鸽式探索与战斗，
带回图纸、材料与经验**反哺家族**；家族又用这些收获提升建造、产业、族人与战力，从而挑战更高的**时代与难度**——
从**战国末期**一路走到**汉刘邦时期**，在**局外经营建造**与**局内肉鸽战斗**的双轮驱动下，把一个小家族经营成贯穿乱世的势力。

> **一句话分工**：**局外是经营建造游戏，局内是肉鸽战斗游戏，两者相辅相成**（用户原话）。

## 2. 设计目标

### 2.1 要达成的体验目标

| # | 体验目标 | 如何验证（可观察的行为或指标） |
| --- | --- | --- |
| G1 | 玩家能感到「**局外与局内互相喂养**」：局外的经营成果让局内更轻松，局内的收获又让局外变强 | 打完一局回到局外，玩家能明确说出"这局的收获让我下一步能做什么"（家族树可点的节点 / 可建的建筑 / 可买的物资至少增加 1 项） |
| G2 | 玩家能感到「**历史推进的沉重感**」：时代只能向前、难度层层加码 | 5 个时代按 战国末期 → 秦朝 → 秦末起义初期 → 楚汉争霸 → 汉刘邦时期 **单向**推进（不可回退），每次推进伴随时代事件；⚠️ **与时代正交的还有第二条轴：层数**（跨局累积、每通关 +1、可反复刷，见 §5.3） |
| G3 | 玩家能感到「**家族是自己的作品**」：经营对象是可识别的族人与家族树，而不是抽象数值 | 家族树 5 个板块（影响力 / 家族产业 / 族人培养 / 局外战斗 / 局内战斗）均有可点节点；族人可命名与培养 |
| G4 | 玩家能感到「**失败不是清零**」，愿意再来一局 | 一局失败后仍能带回部分收获（通关则全额带出），且重伤/信心不足会迫使玩家做**换人决策**而非无脑重开 |
| G5 | 一局节奏可预期：**30~40 分钟**打完 3 个场景、局内**完全不限时** | 实测一局时长落在 30~40 分钟区间；**局内任何环节都不出现限时失败——含 boss 战**（用户 Q2 明确） |

## 5. 核心循环（Core Loop）

### 5.1 分钟级循环（局内一次交互）

> 战斗形态（用户 A1 答案）：**玩家直接操作 1 名角色，其余 3 名由 AI 控制**。

```
推进场景 → 遭遇敌人（操作 1 名 + 3 名 AI）→ 战斗 → 打怪掉落 / 事件 → 扎营（修甲、完全治疗、补充减员）
→ 场景末尾 boss → 进入下一场景 …第 3 个场景 boss → 通关 → 选择带出
```

| 步骤 | 玩家在做什么 | 系统给什么反馈 | 情绪目标 |
| --- | --- | --- | --- |
| 1 | 操作 1 名角色在横板场景中前进、战斗；另外 3 名 AI 自动行动 | 队伍状态（生命 / 甲 / 状态）、掉落、事件提示 | 掌控感 + 队伍协同感 |
| 2 | 战斗中做取舍：用不用消耗品、何时扎营 | 消耗品格位变化、扎营结果（修甲 / 完全治疗 / 补员） | 资源紧张感 |
| 3 | 打场景末尾 boss | boss 血条、阶段变化、掉落 | 阶段性的爽感与压力 |
| 4 | 场景间推进（共 3 个场景），随时查看带出候选 | 场景进度（1/3、2/3、3/3） | 前进感 |
| 5 | 通关后**列表勾选**要带回局外的物品 | 带出上限（初始 1 → 满级 10 件） | 收获感与抉择感 |

### 5.2 小时级循环（一个 session）

```
局外：建造 / 收获（倒计时）→ 查看市场与运送 → 家族树加点 → 处理重伤 / 信心
   → 派遣最多 4 人进边缘空间
   → 局内 3 个场景（30~40 分钟，无倒计时）
   → 通关：全额带出（受上限） / 失败：带回部分收获
   → 反哺局外：图纸、材料、装备、药品入账 → 家族树与建造推进 → 再派遣
```

- 一局 = **3 个不同的场景**，每个场景末尾都有 boss；**打过第 3 个场景的 boss 证明该难度通关**。
- **反哺材料、装备、药品等算在一起，统一受带出数量上限影响**（**不是只有反哺材料受上限**，用户 A4 明确）。
- 局内获得的**非消耗加成**（信心、数值、技能 buff）**局内生效，回到局外失效**。

### 5.3 长线循环（跨 session 的留存驱动）

> ⚠️ **长线有两条正交的推进轴**（用户 Q1 答案）：**时代 / 难度**（基础难度档，单向）与**层数 / 深度**（**全局唯一一条**，跨局累积、**不重置**、**上限受时代约束**）。
> **层数 ≠ 时代**，两者不可混为一谈。

```
【轴一 · 时代 / 难度】单向、不可回退（基础难度档）
  局外里程碑达成（规定"局外养成下限"）＋ 打过本局第 3 场景 boss
     → 时代推进 → 战国末期 → 秦朝 → 秦末起义初期 → 楚汉争霸 → 汉刘邦时期

【轴二 · 层数 / 深度】全局一条、不重置、上限 = 当前时代序号
  每通关一次（打过本局第 3 场景 boss）→ 深度 +1，但不超过当前时代序号
  可刷范围：时代 N ⇒ 深度 1 ~ N      （时代 1 只有深度 1）
```

**轴一：时代 / 难度（基础难度档）**

- **所有时代的肉鸽副本都是同一个「边缘空间」**（不是每个时代换一个新空间）；**时代只影响难度**。
- **时代随难度变更，无法回退**（用户 A3 答案）——不存在"回去打旧时代"的设定。
- 进下一时代的门槛是**双条件**：① 打过该难度第 3 场景 boss；② 一个**局外里程碑**（规定**局外养成的下限**，防止只练局内就推时代）。

**轴二：层数 / 深度（全局唯一一条、上限受时代约束的深度轴）**

- **深度是全局唯一的一条轴**（**不是每个时代各一套**），**跨局累积**，**不重置**。
- **每通关一次，深度 +1**。用户原话「去到边缘空间的尽头击败 boss 获得**通往更高一层的通行权**」= **打完本局第 3 场景 boss → 深度 +1**。
- ⚠️ **深度上限 = 当前时代序号**（用户 Q2' 答案）：**时代 1 最深只能到深度 1，时代 2 最深到深度 2 …… 时代 5 最深到深度 5**；**达到上限后就不再增加**。
- 因此**可反复刷的深度范围 = 1 ~ 当前时代序号**：**时代 1 期间只有深度 1，几乎没有深度练度空间**——这一点直接影响"退路"的判断，见 §5.4 与 §10 R10'。
- 时代仍只决定**基础难度档**；**深度是在其之上叠加的增量**。
- **每局**边缘空间都会**生成 3 个场景**，**依次打过才算通关**。
- `策划建议`：深度的起始值与首次解锁方式属实现细节，由 `Story/02_系统策划/` 确定。

**共同部分**

- 每局都是「局外准备 → 派遣最多 4 人 → 局内 3 个场景 → 通关/失败 → 选择带出 → 反哺局外」。
- 局外技能树的具体载体是**家族树**（5 个板块，见 M3 与 §7）。

### 5.4 循环的驱动力与断点

| 问题 | 回答 |
| --- | --- |
| 玩家为什么愿意再来一次？ | ① 失败也不是清零（部分带回）；② 反哺直接点亮家族树节点与建造目标；③ 通关后时代推进带来新内容；④ 带出上限随家族树提升（1 → 10），"下次能带更多"本身就是动机 |
| 循环在哪里可能断掉？ | ① **重伤未愈或信心不足 → 无法出战**，可出战角色不足时会卡住派遣；② 局外资源产出跟不上建造 / 市场消耗；③ 难度墙（时代不可回退 ⇒ **不能回旧时代刷**；退路只有 **深度 1 ~ 当前时代序号** 这个**有限**的刷取空间，见下方补偿手段）；④ **两条难度轴并存导致玩家困惑**（分不清"我卡的是时代还是深度"，见 §10 R11）；⑤ **时代 1 期间深度上限只有 1 ⇒ 几乎没有深度练度空间**（见 §10 R10'）；⑥ 等待倒计时期间无事可做 |
| 补偿手段 | ① **深度轴是"有限度的退路 / 练度空间"**：时代 N 期间可反复刷 **深度 1 ~ N** 累积实力与收获；⚠️ **但上限随时代增长 —— 时代 1 期间只有深度 1，几乎没有深度练度空间**，此时卡关必须靠 ②③④⑤ 与**局外补强**（见 §5.3、§10 R10'）；② 重伤按倒计时恢复，可用扎营类 / 治疗类道具与家族树加速（`策划建议`）；③ 信心可通过局外事件、局内表现、家族树恢复（`策划建议`）；④ 市场可买到村庄**无法产出**的物资（用户 A5 答案）作为资源兜底；⑤ **失败也能带回部分收获**，保证每局都有正收益；⑥ 卡关时先回局外补家族树——这正是"两者相辅相成"的设计意图 |

> ⚠️ **计时口径必须分清（本项目关键口径）**：
> - **局外有计时器**：建造、定期收获物资、市场刷新、重伤倒计时，全部走**运行时计时器**逻辑（用户 A2 / A4 / A5）。
> - **局内无倒计时**：肉鸽战斗**不设倒计时、不限时失败**，玩家可以慢慢打完 3 个场景（用户 B8）。
> 两句不矛盾，但**绝不可混为一谈**。**用户 Q2 已确认：局内任何环节都不限时，含 boss 战。**

## 7. 数值框架

> 只写"口径与曲线"。**本节结论要能直接指导配置表设计。**

| 项目 | 内容 |
| --- | --- |
| 数值类型 | ① **角色属性**（生命、攻击、防御、速度等；**人形态共用同一套角色逻辑**）；② **资源**（物资、材料、图纸、钱财）；③ **进度 / 状态**（家族树节点、时代 / 难度、**层数 / 深度**、族人品质、**信心**、**重伤倒计时**、格位、带出上限） |
| 成长曲线 | 局内 = 单局内滚雪球式成长（肉鸽）；局外 = **家族树按板块阶梯式成长**。`策划建议`：家族树节点收益用**分段递增**（前段平缓、后段陡峭）而非指数，避免后期数值爆炸；局内成长速度需保证"半小时内能感到明显变强" |
| 单位约定 | **时间统一用「秒」**（建造倒计时、收获周期、市场刷新、**重伤倒计时**）；资源与数量用整数；**概率用 0~100 的整数百分比**；信心用 **0~100** 整数；格位用「个」；带出用「件」；传送人数用「人」 |
| 数值上限 | 单属性建议 **≤ 999999**（`uint` 足够）；资源 **≤ 42 亿**（`uint`）；**层数（深度）用 `byte`**（**上限 = 当前时代序号，最大 5**；此前按"无上限"写过 `uint`，限定上限后改用 `byte` 更贴合取值范围）；重伤倒计时 ≤ 数天秒数（`uint`）；信心 `0~100`（`byte`）；格位 `0~255`（`byte`）；带出件数 **1~10**（`byte`）；传送人数 **≤ 4**（`byte`） |
| 小数处理 | 属性 / 资源 / 进度**一律整数**（`int` / `uint` / `byte` / `short`）；仅"速度、倍率、距离"这类天然连续量用 `float`；`策划建议`：**概率与百分比不要用 `float`**，用整数百分比（0~100）或万分数（0~10000），避免显示与舍入歧义 |
| 平衡依据 | 以「**一局 30~40 分钟、3 个场景、失败也能带回部分收获**」为基准反推：`策划建议` 单场景 8~12 分钟、boss 战 2~3 分钟、场景间事件 1~2 分钟；家族树单节点收益量级以"**一局收获能点亮 1~3 个节点**"为准 |
| 调数值流程 | 改 `Assets/Excel/Chaos_excel/` 下的源表 → **必须由程序执行导出菜单重新导出** → 产物（`Resources/Data/Json/Runtime/**`、`ConfigData/`、`ModelData/`、`Data/Records/`）**一律不可手改**；`策划建议`：数值优先表驱动，避免硬编码 |

### 7.1 关键数据必须能被表结构表达（**遵守导出器 12 类型白名单**）

> **权威 = `ConfigManager.Convert` 的 `case` 列表**（共 12 个）：`int` `uint` `long` `ulong` `byte` `sbyte` `short` `ushort` `float` `double` `bool` `string`。
> **`enum` 不可用** —— 一切枚举一律写成 `uint`（或 `byte` / `short`）+ **数字 ↔ 含义对照表**，写进对应的字段规格文档。
> 禁用：`decimal`（`JsonUtility` 静默丢弃）、`char`（JSON 存成数字）、`DateTime`，以及已删除的 `int32` / `int64` / `long long`。
> 详见 `Story/03_配置表设计/01_配置表填写规范.md` §3。

| 数据 | 表达方式 | 第 6 行类型 | 说明 |
| --- | --- | --- | --- |
| **传送人数上限（≤4）** | 单值参数 | `byte` | 硬上限 4；"一个人也能传"表示**实际派遣人数是运行时变量**，不是表里的多列 |
| **带出上限（初始 1 → 满级 10）** | 家族树节点效果 + 单值 | `byte` | 由家族树节点逐级提升；运行时取当前值 |
| **格位数量（背包 / 消耗品格）** | 单值参数 + 家族树加成 | `byte` | 初始值待定（`策划建议`：6~8 格），可由局外升级 |
| **同名道具叠加上限** | 每行一个值 | `ushort` / `uint` | 按道具行分别配置；与格位共同构成限制（用户 B9：**格位 + 同名叠加上限**） |
| **重伤倒计时** | 秒 | `uint` | 单位秒；**计时基准（真实时间 / 游戏内时间）待定**，见 §12 Q4 |
| **是否「扎营类道具」** | 开关 | **`bool`** | 消耗品需**区分是否为扎营类道具**（用户 B9）。可填 `true` / `false`、`1` / `0`、`是` / `否`，**不能留空** |
| **时代 / 难度（1~5）** | 枚举 ID | `uint` | **无 enum**：`1 战国末期 / 2 秦朝 / 3 秦末起义初期 / 4 楚汉争霸 / 5 汉刘邦时期`，对照表写进字段规格文档 |
| **家族树板块（1~5）** | 枚举 ID | `uint` | `1 影响力 / 2 家族产业 / 3 族人培养 / 4 局外战斗 / 5 局内战斗` |
| **角色形态** | 枚举 ID（**当前恒为 1**） | `uint` | 用户明确**只考虑人形态、所有角色走同一套角色逻辑**；保留字段是为将来扩展留位，**MVP 不实现其他形态** |
| **族人品质 / 稀有度** | 枚举 ID | `uint` | 局外养成含"角色品质、稀有角色"（用户原话） |
| **信心（0~100）** | 单值 | `byte` | 低于阈值**无法出战**（阈值待定，见 §12 Q4） |
| **场景序号（1~3）** | 枚举 ID | `uint` | 一局 3 个场景，每场景末尾一个 boss |
| **层数 / 深度** | 单值（跨局累积、**不重置**） | `byte` | **每通关一次 +1**；**上限 = 当前时代序号**（最大 5，达到上限后不再增加） |
| **深度 → 难度叠加（二维表）** | **拆表**（时代序号 × 深度 → 难度增量） | `uint` 主键 + `uint`/`float` 系数 | `策划建议`：**不需要无限曲线**——深度上限 5、时代上限 5，用 **5×5 的二维表驱动**（行 = 时代 1~5，列 = 深度 1~5）即可。最终难度 = **时代基础难度档 ⊕ 该表查出的增量**；表驱动便于调参，**不要硬编码公式** |
| **时代难度档（1~5）** | 每时代一行 | `uint` | 与深度**正交**：时代给"基础难度档"，深度在其上叠加增量 |
| **"技能 → 多个效果" / "场景 → 多个事件"** | **必须拆表 + 外键** | `uint` 外键 | 导出器**不支持嵌套结构**（见 §10 R4），不允许在一格里塞 Json |
| **概率 / 百分比** | 整数 | `byte`（0~100）或 `ushort`（0~10000） | `策划建议`：不要用 `float` 存概率 |

## 10. 依赖与风险

| # | 依赖 / 风险 | 说明 | 应对 |
| --- | --- | --- | --- |
| R1 | **工程无联网层** | 用户明确不联网 ⇒ **市场、价格波动、运送时长、护送成功率全部本地模拟**；"各种文明派遣的队伍"是**单机 NPC 阵营** | 设计上不引入任何需要服务端校验的逻辑；MVP 不排 M5 / M6 |
| R2 | **存档链路当前有 P0 缺陷** | 运行时配置读取通路（`ConfigLoader` 路径错位）实测失效，已由架构师 / 程序记录并排期。而本作**局外计时器 + 重伤倒计时 + 家族树 + 时代进度**都强依赖存档 | 概念案不阻塞；但**架构评估时必须先解决存档 / 读配置通路**，否则 M15 无法落地 |
| R3 | **局外计时器与"回合驱动剧情事件"两套推进机制并存** | 用户 A2 同时要求"建造 / 收获走倒计时（运行时计时器）"与"剧情事件走回合驱动" | `策划建议`：以**倒计时为时间轴**、事件**挂载在回合 / 阶段边界**上；两套机制的时序归属需架构师与策划共同确认（属设计风险，非工程缺陷） |
| R4 | **导出器不支持嵌套结构** | 如"一个技能挂多个效果""一个场景挂多个事件"无法在一格内表达 | **拆表 + 外键**（主表 + 明细表） |
| R5 | **导出器不支持 `enum`** | 时代、难度、家族树板块、品质、阵营、场景序号等全是枚举 | 一律 `uint` + 数字对照表，对照表写进对应字段规格文档 |
| R6 | **导出器其它硬约束** | 一张表只读第 1 个页签；字符串不能含英文逗号 / 双引号 / 换行；数字列不校验；**源表目录只允许放成品表**（空页签会中断整批导出） | 写入各表填写规范，由 `Story/03_配置表设计/` 统一复核 |
| R7 | **内容量风险：5 个时代 × 3 场景 × boss + 剧情事件** | 内容量随时代线性堆叠，MVP 不可能全做 | **MVP 只做第 1 时代**，但数据结构预留 5 个（见 §8） |
| R8 | **"局外战斗纯 AI、不走局内战斗逻辑" = 需要第二套战斗结算** | 存在重复实现与长期维护分叉的风险 | 需架构师评估：抽公共伤害 / 结算层，还是接受两套轻量实现（属第二阶段 M6，MVP 不阻塞） |
| R9 | **重伤卡派遣 + 时代不可回退 = 卡关可能无退路** | 玩家可能同时"没人能出战"且"不能回旧时代刷" | ① **层数轴可反复刷，是这个断点的主要退路**；② 辅以市场（可买村庄不产物资）、扎营类道具、家族树加速、**失败也能带回部分收获**（§5.4 补偿手段） |
| R10 | **时代不可回退 ＋ 深度难度叠加 ⇒ 难度失控** —— ⚠️ **风险已显著下降** | 原先担心"深度只增不减、无限叠加会把难度推爆"；**现在深度有硬上限 = 当前时代序号（最大 5）**，且每次上探还要先过时代门槛 | **上限直接消除了"无限叠加"的风险**，不再需要软上限设计。仍建议：① 保证 **5×5 的每个格子都可通关且收益合理**；② 难度增量用二维表**逐格调参**（§7.1），不要用单一公式 |
| R10' | **时代 1 期间深度上限只有 1 ⇒ 开局几乎没有深度练度空间** | 玩家在时代 1 卡住时**不能靠刷深度堆练度**（可刷范围只有深度 1），与"深度是退路"的直觉相反，容易产生"卡死感" | **必须靠局外补强**：① 村庄 / 家族树 / 族人培养（主要手段）；② **失败也能带回部分收获**，保证每局都有正收益；③ 若实测该阶段挫败感过强，`策划建议` 再考虑放宽（如时代 1 允许深度 2 或提高局外产出）——**需实测数据后再定，本概念案不发明数值** |
| R11 | **两条难度轴并存的可读性风险** | 玩家可能分不清"我卡的是**时代**还是**深度**"，也不清楚**深度上限=时代序号**这件事（会误以为能无限刷） | `策划建议`：局外**明确分开展示两条进度**（时代 = 主线进度；深度 = 计数器 + **明确显示上限**，如 `深度 2 / 2`）；进局前用一句文案说清"本局难度 = 时代基础档 + 深度叠加"。**需 UI 主动区分两者**（见 §9） |
