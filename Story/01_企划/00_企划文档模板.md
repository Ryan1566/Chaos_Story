## 1. 一句话概述

⬜ 用**一句话**说清：玩家扮演谁、在什么世界里、做什么、得到什么乐趣。

> 示例写法：「玩家扮演一名被卷入混沌裂隙的幸存者，在不断崩塌的据点间收集资源、招募同伴，
> 通过一次次抉择推进剧情，体验『资源永远不够』的紧张与成长。」

**反面示例**（不要这样写）：「本项目是一款多人在线开放世界 RPG，具有丰富的玩法和精美的画面。」
—— 没有信息量，无法据此做设计。

## 7. 数值框架

> 只写"口径与曲线"，具体数值落在配置表里。**本节结论要能直接指导配置表设计。**

| 项目 | 内容 |
| --- | --- |
| 数值类型 | ⬜ 属性（生命/攻击/速度…）/ 资源（金币/材料…）/ 进度（等级/经验…） |
| 成长曲线 | ⬜ 线性 / 指数 / 分段；示例公式 |
| 单位约定 | ⬜ 例：时间用毫秒、速度用米/秒、概率用 0~100 的整数 |
| 数值上限 | ⬜ 例：单属性 ≤ 9999（影响配置表类型选择：`uint` 还是 `ulong`） |
| 小数处理 | ⬜ 哪些列允许小数（`float`），哪些必须整数（`int`/`uint`） |
| 平衡依据 | ⬜ 例：以「3 刀击杀同级怪」为基准反推 |
| 调数值流程 | ⬜ 改哪张表、是否需要重新导出、是否需要重启游戏 |

> ⚠️ 类型选择受导出器白名单限制（只有 `int`/`uint`/`long`/`ulong`/`float`/`double`/`string`），
> 且**不支持 bool 与 enum**。所以"布尔开关"要设计成 `uint` 的 0/1，"枚举"要设计成 `uint` + 对照表。
> 详见 `Story/03_配置表设计/01_配置表填写规范.md` §3。
